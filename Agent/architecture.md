# 프로젝트 구조

## 하나의 패키지를 배포해요

`packages/ui`만 `@eli/ui`로 배포해요. 공통 토큰도 이 패키지에 포함해요. `apps/storybook`은 비공개 개발 앱이에요.

공개 컴포넌트는 `packages/ui/src/{그룹}/{컴포넌트}/`에서 관리하고 그룹의 `index.ts`로 내보내요. 사용자는 `@eli/ui/{그룹}`에서 가져와요. 실제 공개 경로는 `packages/ui/package.json`의 `exports`를 기준으로 확인해요.

하나의 그룹에 역할이 가까운 컴포넌트를 함께 둘 수 있어요. 각 컴포넌트의 타입·구조·스타일·Hook은 PascalCase 컴포넌트 폴더 안에서 관리하고, 그룹 진입점에서는 외부에 필요한 심벌만 공개해요.

`Agent/` 문서에는 현재 컴포넌트 명단이나 개별 props를 반복해서 기록하지 않아요. 여러 컴포넌트에 적용되는 구조 규칙과 별도 공개 여부처럼 예외적인 결정만 기록해요. 구현 현황은 루트 README와 Storybook에서 확인해요.

`packages/ui/src/dim`은 Modal 같은 오버레이 컴포넌트가 내부에서 공유해요. 공개 사용 사례가 확정되기 전까지 별도의 패키지 진입점을 만들지 않아요.

`packages/ui/src/icon`은 컴포넌트 내부에서 재사용하는 아이콘을 관리해요. 아이콘 자체를 공개하기 전까지 별도의 패키지 진입점을 만들지 않아요.

컴포넌트 Storybook 예제는 `apps/storybook/stories`에서 관리하고 개발용 `@/` 경로로 UI 소스를 연결해요. 이를 통해 `packages/ui`에 Storybook 의존성을 추가하지 않아요.

## 코드와 스타일을 함께 연결해요

TypeScript는 ESM과 타입 선언을 만들고 `scripts/build-ui.mjs`는 CSS를 같은 상대 경로로 복사해요. 컴포넌트는 자신의 CSS를 import하고, 그 CSS는 필요한 공통 토큰을 연결해요. `sideEffects`에는 CSS를 등록해요.

그룹 진입점에서 여러 CSS 의존성이 연결되면 사용하지 않는 형제 컴포넌트의 CSS도 포함될 수 있어요. JS 트리 셰이킹과 CSS 제거를 같은 것으로 설명하지 않아요. 실제 소비 번들로 확인해요.

## 폰트 로딩을 분리해요

`@eli/ui`는 `--eli-font-family-sans`와 fallback만 제공해요. 폰트 파일을 패키지에 넣거나 CDN에서 자동으로 불러오지 않아요. 이를 통해 컴포넌트 패키지 용량과 소비 앱의 폰트 로딩 정책을 분리해요.

추후 초기 설정 도구가 소비 프로젝트의 프레임워크를 확인하고 Pretendard를 설치한 뒤 전역 진입점에 한 번 연결해요. 이미 같은 폰트가 설정되어 있으면 다시 추가하지 않아요. MCP는 이 과정을 안내할 수 있지만 재현 가능한 설치와 파일 변경은 초기 설정 도구가 담당해요.

## 실행 의존성을 검토해요

현재 배포 패키지에는 `dependencies`가 없어요. React 19.3 계열을 개발·검증 기준으로 삼고 peer 범위는 `^19.3.0`이에요. React DOM은 SSR 검증용 개발 의존성으로만 사용하며 배포 패키지에는 포함하지 않아요. 포털 같은 런타임 기능을 구현할 때 peer dependency 필요성을 별도로 검토해요. 지원 범위를 넓힐 때 해당 버전의 소비 테스트를 추가해요.

새 실행 의존성을 추가하면 목적·직접 구현 비용·용량·라이선스를 검토하고 패키징 검사의 기준을 함께 갱신해요. 개발 도구와 실행 의존성을 구분해요.

## 현재 상태와 예정된 기능

색상·타이포그래피·레이아웃 토큰을 패키지에 포함하고 실제 tarball의 Vite 소비와 서버 렌더링을 검증해요. 구현된 컴포넌트와 확정되지 않은 디자인은 루트 README에서 구분해요. Storybook은 Cloudflare Worker에 정적 파일로 배포하며 사용자 지정 도메인에서 확인해요. 폰트 초기 설정 도구, Next.js 소비 검증, 문서 사이트, MCP, npm 배포 자동화는 아직 없어요. 필요할 때 `apps/docs`, `packages/docs-mcp`를 추가해요. 공통 SSR 검증만으로 Next.js 고유의 RSC·라우팅·hydration 호환성을 보장하지 않아요.
