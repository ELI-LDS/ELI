# 한국어 문서 작성 규칙

토스의 [라이팅 원칙](https://toss.tech/article/21022)과 [토스플레이스 UX 라이팅](https://docs.tossplace.com/guide/front-integration/plugin/design/ux-writing.html)을 참고해요. ELI의 기술 문서에 맞게 적용하는 규칙이며 토스의 공식 지침을 그대로 복제한 문서는 아니에요.

- 설명은 해요체로 써요. 제목·표·짧은 체크리스트는 명사형도 괜찮아요.
- 해야 할 일을 먼저 말하고, 필요한 이유를 이어서 설명해요.
- 한 문장에는 하나의 내용을 담아요. 같은 설명을 반복하지 않아요.
- 어려운 표현은 쉽게 풀되 API·타입·명령어 이름은 정확하게 써요.
- 필수는 “반드시 확인해요”, 금지는 “포함하지 않아요”처럼 명확하게 써요.
- 실제 결과와 예상 결과를 구분해요. 미구현 기능은 “예정이에요”라고 표시해요.
- 사용자를 탓하거나 불필요한 불안감을 주지 않아요.

“패키지 용량 검증 수행 필수”보다는 “배포 전에 `pnpm size`로 다운로드 용량을 확인해요”라고 써요.

커밋 제목은 `branch.md`의 한국어 요약 규칙을 유지해요. 명령어와 기존 식별자는 말투를 맞추려고 바꾸지 않아요.
