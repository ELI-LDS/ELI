# 버전 규칙

`@eli/ui` 안의 모든 컴포넌트와 토큰은 하나의 버전을 사용해요. [SemVer](https://semver.org/lang/ko/)의 `MAJOR.MINOR.PATCH` 형식을 따라요.

| 변경 | 버전 | 예시 |
| --- | --- | --- |
| 기존 사용법과 호환되지 않아요 | MAJOR | 공개 props·경로·CSS 변수 삭제 또는 이름 변경 |
| 기존 사용법을 유지하며 기능을 추가해요 | MINOR | 새 컴포넌트·선택적 prop·variant |
| 기존 계약을 유지하며 오류를 고쳐요 | PATCH | 명세와 다른 스타일·동작·접근성 오류 수정 |

## 초기 버전을 관리해요

초기 버전은 `0.1.0`이에요. 아직 게시하지 않았어요. `0.x`에서는 호환성 변경과 기능 추가에 MINOR, 호환되는 오류 수정에 PATCH를 올려요. 이는 ELI의 개발 단계 운영 규칙이에요.

안정된 공개 API와 사용 규칙을 지원하는 첫 정식 버전을 `1.0.0`으로 정해요. 사전 배포는 `1.0.0-beta.1`처럼 쓰고 npm `next` 태그를 사용해요. 정식 배포는 `latest`를 사용해요.

## 변경 영향을 기록해요

공개 props·import 경로·CSS 변수·기본 동작·문서로 약속한 디자인을 호환성 판단에 포함해요. 명세대로 고치는 스타일 수정과 새 디자인으로 바꾸는 변경을 구분해요.

지침·Storybook만 바뀌고 배포 결과가 달라지지 않으면 버전을 올리지 않아요. 여러 변경을 묶을 때는 가장 큰 변경 유형을 적용해요. PR에는 예상 유형을 기록하고 릴리스 준비 때 패키지 버전을 한 번 올려요.

릴리스 때 루트 `CHANGELOG.md`에 사용자에게 달라지는 점과 이전 방법을 기록해요. 패키지 버전·lockfile·태그(`v0.1.0` 형식)를 일치시켜요. 이미 배포한 버전은 재사용하지 않아요. npm 게시와 Git 태그 생성은 실제 릴리스 작업에서 진행해요.
