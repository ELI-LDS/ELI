# 컴포넌트 가이드를 실제 에이전트에서 확인해요

하네스 담당자가 Button·Select·Modal의 조회 → 선택 → 필요한 소스 설치 → 기능 연결을 확인할 때 사용하는 실행 체크리스트예요. 웹사이트 제작이나 하네스 구현 변경은 이번 범위에 포함하지 않아요. 아래 실행 시나리오는 준비된 상태이며 실제 Claude Code·Codex 세션 검증은 아직 하지 않았어요.

규칙의 기준은 [하네스 완료 기준](../Agent/harness.md#새-설치-도구와-연결하는-완료-기준), [MCP 도구 계약](../Agent/mcp-spec.md#도구), [소스 설치 계약](../Agent/registry.md#하네스가-소비-방식을-구분하게-해요)이에요. 이 문서에서 컴포넌트 규칙이나 설치 규격을 다시 정의하지 않아요.

## 시작할 환경을 기록해요

- 기존 지원 React 앱의 별도 검증 브랜치나 임시 프로젝트를 사용해요. 공개 웹사이트를 만들 필요는 없어요. 앱·폰트·토큰과 프로젝트 DESIGN.md의 준비 상태는 기존 셋업 절차에 따라 확인해요.
- 실행한 CLI 버전, UI 콘텐츠 버전, 하네스 버전, 에이전트·모델·세션을 각각 기록해요. 검증 후보와 실제 공개 버전을 구분하고 후보를 npm latest로 안내하지 않아요.
- eli.json·eli.lock.json·eli.harness.json과 실제 파일을 확인해요. UI 콘텐츠 버전과 get_versions의 ui.docs가 다르면 차이를 먼저 확인하고 이 시나리오를 그대로 통과 처리하지 않아요.
- 아래 요청을 각각 새 대화에서 먼저 실행해요. 에이전트에게 컴포넌트 이름·prop 정답을 미리 알려주지 않아야 사용 목적을 보고 고르는지 확인할 수 있어요.

| 환경 | 확인할 상황 | 초기 상태 |
| --- | --- | --- |
| A. 이미 연결한 프로젝트 | MCP 도구가 보이는 세션에서 가이드를 읽고 작업해요. | 담당자 실행 전 |
| B. 하네스를 설치한 현재 세션 | MCP 도구가 아직 보이지 않으면 설치된 eli-docs.mjs로 같은 문서를 읽고 작업을 이어가요. | 담당자 실행 전 |
| C. 기존 소스가 있는 프로젝트 | 사용자 지정 설치 위치와 수정된 파일을 유지하며 필요한 항목만 추가해요. | 담당자 실행 전 |

Claude Code와 Codex는 실제로 사용한 환경별로 결과를 따로 남겨요. 프로젝트 밖의 설정 변경이나 Codex 훅 신뢰가 필요하면 기존 설치 안내를 따라 사용자가 확인해요. 저장소에 있는 조회 스크립트 실행 성공만으로 B의 설치·신뢰·스킬 동작까지 통과했다고 기록하지 않아요.

## 공통 확인 항목

- [ ] 사용 목적에 맞는 컴포넌트를 목록·검색과 승인된 가이드로 선택했어요. 읽은 도구와 섹션을 기록했어요.
- [ ] 실제 사용할 props를 조회했어요. 문서에 없는 API나 별도 children 조립 방식을 만들지 않았어요.
- [ ] 설치가 필요한 항목의 id·실제 의존성을 확인했어요. 관련 컴포넌트 추천 목록을 모두 설치하거나 add --all을 실행하지 않았어요.
- [ ] 생성한 import가 설치 기록의 path·export와 실제 파일에 맞아요. 기존 @/ 별칭이나 전체 UI 패키지를 임의로 요구하지 않았어요.
- [ ] className·style·소스의 기존 사용자 수정을 보존했어요. modified를 규칙 위반으로 단정하거나 원본으로 복구하지 않았어요.
- [ ] 생성한 코드가 소비 앱의 타입 검사·빌드를 통과하고 실제 브라우저에서 요청한 기능이 동작해요.
- [ ] 조회 실패·미제공 가이드·버전 차이가 있다면 추측해 채우지 않고 확인하지 못한 부분을 보고했어요.

## 1. 주요 행동을 제공하는 버튼

에이전트에 다음 요청을 전달해요.

> 설정 화면에서 가장 중요한 행동인 ‘저장’ 버튼을 만들어줘. 아이콘은 필요 없어. 누르면 실제 서버 요청 대신 저장 함수를 호출하고 완료 문구를 보여줘. 저장 중에는 다시 누를 수 없게 해줘.

확인할 사용 기준은 [Button 승인 가이드](../apps/docs/content/components/button.json)에서 읽어요.

- [ ] 주요 행동과 아이콘 없는 텍스트 버튼에 맞는 선택을 했고 그 근거를 가이드에서 확인했어요.
- [ ] onClick으로 소비 앱의 저장 함수를 연결하고 처리 중 여부를 disabled에 연결했어요. 존재하지 않는 loading prop을 만들지 않았어요.
- [ ] 저장 전·처리 중·완료 뒤의 동작을 확인했어요. 처리 중 재실행을 막고 완료 뒤에는 다시 사용할 수 있어요.
- [ ] 처음 Button만 설치한 상태에는 IconButton·Modal·하네스 등 관계없는 항목이 따라오지 않았어요. 실제로 참조하는 토큰·아이콘 등 의존 파일은 허용해요.

## 2. 목록에서 하나 고르는 입력

> 분류를 하나 고르는 입력을 만들어줘. 라벨은 ‘분류’, 선택 전 안내는 ‘분류를 선택하세요’야. 디자인·개발·운영을 선택지로 주고 운영은 선택할 수 없게 해줘. 선택한 값은 화면에서 확인할 수 있게 해줘.

확인할 사용 기준은 [Select 승인 가이드](../apps/docs/content/components/select.json)에서 읽어요.

- [ ] 단일 선택 요구에 맞게 선택했고 label·placeholder·options를 연결했어요. 각 옵션의 value가 고유해요.
- [ ] value·onValueChange 또는 실제 지원하는 비제어 방식으로 선택 결과를 연결했어요. 읽기 전용 값만 고정해 선택이 되지 않는 상태를 만들지 않았어요.
- [ ] 운영 옵션을 건너뛰고 다른 옵션은 선택할 수 있어요. 선택 후 표시값이 바뀌고 목록이 닫혀요.
- [ ] 방향키·Home·End·Escape와 닫힘 뒤 포커스를 승인 가이드에 따라 확인했어요. 검색·다중 선택을 지원한다고 설명하지 않았어요.
- [ ] MenuItem은 Select의 실제 의존성으로 제공돼요. 옵션의 좌우 아이콘·단축키를 임의로 켜거나 별도 옵션 children을 중첩하지 않았어요.

## 3. 실행 전 확인받는 창

> ‘변경 확인’을 누르면 확인 창을 열어줘. 제목은 ‘변경할까요?’, 안내는 ‘변경할 내용을 확인해 주세요.’로 해줘. 취소와 배경 클릭·Esc는 닫히게 해줘. 확인 버튼은 저장 함수를 실행하고 성공했을 때만 닫아줘. 실패하면 창을 유지하고 오류 내용을 보여줘.

확인할 사용 기준은 [Modal 승인 가이드](../apps/docs/content/components/modal.json)에서 읽어요.

- [ ] open·onOpenChange로 외부 열기와 닫힘을 연결했어요. 내부 Positive·Secondary 액션을 공개 props로 연결하고 임의의 children·중복 액션 버튼을 넣지 않았어요.
- [ ] Dim·Secondary·Escape로 닫히고 콘텐츠 내부 클릭으로는 닫히지 않아요. 닫은 뒤 외부 버튼으로 다시 열려요.
- [ ] Positive는 소비 앱의 저장 함수를 실행해요. 성공 후 소비 앱이 닫고, 실패 시 창을 유지하며 지원하는 안내 슬롯으로 오류를 전달해요.
- [ ] Secondary의 자동 닫힘을 취소해야 하는 별도 조건도 event.preventDefault()로 확인했어요. 기본 취소 버튼을 항상 취소 불가능하게 바꾸지는 않았어요.
- [ ] 열릴 때 Secondary로 포커스가 이동하고 Tab·Shift+Tab이 내부를 순환해요. 닫히면 열었던 버튼으로 돌아오며 배경 조작·스크롤 잠금이 복원돼요.
- [ ] 기존 디자인·최대 너비를 임의로 바꾸지 않았어요. Modal의 Button·Dim 의존성과 예시의 외부 Button 설치를 구분했어요.

## 실패·기존 설치 상황도 확인해요

안전한 임시 프로젝트나 테스트용 설정에서 다음 상황을 따로 확인해요. 실제 소비 앱의 파일을 손상시키거나 운영 MCP를 수정하지 않아요.

| 상황 | 확인할 결과 | 초기 상태 |
| --- | --- | --- |
| 승인 가이드나 요청 섹션이 없어요 | 미제공임을 알리고 규칙을 지어내지 않아요. 코드에서 확인한 기술 사실과 구분해요. | 담당자 실행 전 |
| MCP·조회 스크립트가 모두 실패해요 | 필요한 문서 조회가 미완료임을 알리고 확인되지 않은 props·선택 기준을 적용하지 않아요. | 담당자 실행 전 |
| 로컬 UI 버전과 MCP 문서 버전이 달라요 | 버전 차이를 알리고 로컬 API를 대조해요. 소스를 강제로 업데이트하지 않아요. | 담당자 실행 전 |
| 사용자 지정 경로에 수정한 Button이 있어요 | 실제 경로를 사용하고 수정 내용을 보존해요. 다시 추가할 때 충돌을 숨기거나 덮어쓰지 않아요. | 담당자 실행 전 |

## 실행 결과를 남겨요

각 시나리오와 환경별로 다음 양식을 복사해요. 결과는 통과·실패·미실행으로 표시하고 실패 또는 미실행 이유를 적어요. 담당자에게 전달한 사실과 실제 실행 완료를 구분해요.

```text
확인 날짜 / 확인자:
시나리오 / 환경 A·B·C:
에이전트·모델 / 세션:
CLI 버전 / UI 콘텐츠 버전 / 하네스 버전:
MCP ui.docs / 검증한 저장소 커밋 또는 공개 태그:
요청한 도구·섹션 / 반환 결과:
선택 이유 / 추가한 항목과 의존 항목:
실제 설치 경로·import / 기존 수정 보존 여부:
타입·빌드 명령과 결과 / 브라우저에서 조작한 항목:
결과(통과·실패·미실행) / 근거 또는 남은 문제:
도구 호출 횟수·토큰(확인할 수 있을 때만):
```

토큰 수를 알 수 없으면 미측정으로 남겨요. 일부 도구 응답 길이나 조회 스크립트의 성공을 에이전트 전체 성능·토큰 절감률로 바꾸어 설명하지 않아요.

## 이번에 사전 확인한 범위

2026-11-24에 저장소의 packages/harness/hooks/eli-docs.mjs로 공개 MCP를 조회했어요. 조회 스크립트 원본은 main에 병합된 #113의 구현이며 이번 작업에서 수정하지 않았어요.

- get_versions 1회, 세 컴포넌트의 get_component·get_props 각 1회로 총 7회를 호출했어요.
- Button·Select·Modal이 stable이며 요청한 섹션·진입 파일·export·props가 로컬 승인 데이터와 일치했어요. 일반 상세 응답에 source·review가 없는지도 확인했어요.
- UI latest/docs는 0.3.0, 최소 하네스는 0.1.0으로 응답했어요. 이것이 설치된 CLI·하네스의 최신 공개 버전을 뜻하지는 않아요.
- 이 확인은 저장소의 읽기 전용 조회 스크립트와 공개 서버를 대상으로 했어요. 위 환경 A·B·C의 실제 에이전트 선택·설치·생성 코드 실행은 담당자 확인 전이에요.

이번 문서는 실행할 요청과 확인 기준을 전달하기 위한 준비예요. 하네스·MCP 구현 변경, npm 게시, 웹사이트 제작이나 담당자에게 별도 메시지를 보내는 작업은 하지 않았어요.
