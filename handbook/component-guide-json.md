# 컴포넌트 문서를 JSON으로 정리해요

디자이너의 Markdown을 전달받으면 AI가 코드와 대조해 JSON 초안을 만들고, 사용자가 검토해요. 검토한 JSON은 문서 웹사이트·MCP가 함께 읽을 자료예요. 하네스는 MCP를 통해 같은 기준을 읽으며 컴포넌트 규칙을 따로 복사하지 않아요.

현재 공개 컴포넌트 가이드 JSON은 34개예요. 기존 31개에 이어 추가 전달된 Modal·Divider·Tab 3개도 사용자 승인으로 stable이 되어 전체 34개가 승인본이에요. 조회 계층·데이터 생성·MCP 도구는 구현되어 있지만 새 초안의 내용은 승인 전 응답에 제공하지 않아요. 자동 Markdown 변환기는 없으며 하네스의 실제 사용 흐름 검증·토큰 측정과 웹페이지 구현은 별도로 구분해요.

## 자료를 받을 준비를 해요

- [빈 JSON 틀](../apps/docs/content/templates/component-guide.json)을 복사해 `content/components/{id}.json`에 작성해요. 빈 틀 자체는 조회 대상이 아니에요.
- [JSON Schema](../apps/docs/content/component-guide.schema.json)가 필드·자료형·필수 항목의 기준이에요. 선택지는 코드와 비교할 수 있게 `choices[].props`에 묶고, `when`에 선택 이유를 적어요.
- 실제 문서가 없는 컴포넌트의 빈 JSON 파일은 미리 만들지 않아요.
- 디자이너에게 frontmatter나 영어 제목을 요구하지 않아요. 이미 작성한 Markdown을 그대로 전달받아요. 제목을 정리하거나 Props 표를 삭제하도록 요구하지 않아요.

## 전달받은 문서를 변환해요

1. 원문을 `content/source/components/{id}.md`에 보존해요. 설명이 틀렸더라도 원문을 조용히 수정하지 않아요. 파일 바이트의 SHA-256과 저장소 기준 경로를 JSON의 `source`에 기록해요.
2. 사용 목적·추천 상황·선택 기준·콘텐츠·동작·조합·주의 사항을 분류해요. 문장을 짧게 정리할 수 있지만 조건·강도·숫자·의미를 바꾸지 않아요. 조합 기준은 각 속성의 독립된 규칙으로 분해하지 않아요.
3. `name`·`group`·`id`는 실제 공개 exports와 레지스트리 항목에 맞춰요. `choices`의 prop·선택값과 관련 컴포넌트 이름도 코드에 존재하는지 대조해요.
4. 원문의 Props·기본값·토큰·치수 표는 구현 확인에 사용해요. JSON에 전체 API·CSS 수치·설치 의존성 표를 다시 만들지 않아요. 현재 데이터 생성기는 레지스트리의 TypeScript·CSS에서 기술 정보를 추출해요. 실행·적용 범위는 [문서 앱 지침](../Agent/docs.md#원본은-가이드-json과-레지스트리-json이에요)을 따라요.
5. 전달되지 않은 정보는 `null`, 확인 결과 해당하지 않는 목록은 `[]`로 표현해요. 문구 길이·개수 제한·반응형 기준을 예시만 보고 만들지 않아요. 현재 DOM 구조는 이해를 위한 설명이며 내부 선택자의 장기 호환성을 약속하지 않아요.
6. 의도가 불분명하면 `review.questions`, 명세와 구현이 다르면 `review.implementationGaps`에 적어요. 코드에 맞춰 기술 설명을 보완한 내용과 사용자에게 확인받은 변경은 변환 결과 안내에 함께 남겨요.
7. 예시는 `{ "title": "설명", "code": "코드" }` 형식이에요. 원문에 없다면 우선 `null`로 둬요. 개발자가 보완할 때는 설치 기록에 맞는 import를 사용하고 실제 타입 검사를 통과한 예시만 제공해요. 지원하지 않는 중첩이나 존재하지 않는 prop은 만들지 않아요.
8. 스키마·코드 참조·원문 의미·출처 해시를 확인하고 JSON 초안을 사용자에게 보여줘요. 자동 생성된 파일로 취급해 덮어쓰거나 AI 변환만으로 승인하지 않아요.

이후 원문이 바뀌면 JSON을 같은 변경에서 다시 검토하고 해시를 갱신해요. 코드가 바뀌어 설명·예시·선택값이 어긋난 경우에도 원문과 차이를 확인해요. 같은 API를 지원하는지 문서 버전과 실제 설치된 UI 콘텐츠 버전을 후속 조회 계층에서 구분해야 해요.

## 검토와 공개를 구분해요

- `draft`: 작성·대조·사용자 검토 중이에요. 일반 MCP·웹사이트 조회에는 상태만 알리고 내용을 담지 않아요.
- `stable`: 사용자가 검토를 완료했어요. 목적·권장 상황·출처·타입 검사한 코드 예시가 있고 미해결 질문·구현 차이가 없어야 해요. 스키마 통과만으로 사용자 검토와 예시 검증을 대체하지 않아요.

`stable`도 실제 공개 배포 완료를 뜻하지 않아요. 아직 배포되지 않은 코드의 가이드를 기존 공개 UI 버전의 가이드처럼 제공하지 않아요. MCP 응답을 공개할 때 게시된 콘텐츠 버전·원본과 대조해요.

문서별 필드와 기존 MCP 섹션의 대응은 [원격 MCP 규격](../Agent/mcp-spec.md#컴포넌트-json과-응답을-연결해요)에서만 관리해요. 검토 항목·원본 경로·해시는 내부 검토 정보이며 기본 도구 응답에 통째로 넣지 않아요. 데이터가 없으면 내용을 만들어 채우지 않고 해당 정보의 부재를 알 수 있게 해요.

## Button 첫 변환을 확인해요

### Notion 원문을 가져온 현황

2026-11-24에 [Components Docs](https://app.notion.com/p/40e98345027980c89afac6829c7991a0?v=40e9834502798063ba26000c7dfefced)에서 하위 페이지를 포함한 Markdown 내보내기로 목록의 23개 원문을 모두 가져왔어요. 목록과 파일 수를 대조하고 저장한 각 파일이 내보낸 바이트와 같은지 확인했어요. CSV·ZIP은 문서 원본 폴더에 넣지 않았어요.

- [기본 템플릿](../apps/docs/content/source/templates/component-guide.md) 1개는 문서 작성 양식 원본이에요. 사용 가이드 JSON 템플릿과 구분해요.
- 컴포넌트 Markdown 22개는 `source/components/`에 보존했어요. FAB·Chip·Navigation처럼 묶인 문서는 실제 공개 심벌별 JSON으로 구분했어요.
- [Tab 원문](../apps/docs/content/source/components/tab.md)은 제목과 Notion 상태만 있고 본문은 비어 있어요. 내용을 만들어 채우지 않았어요.
- Button 본문은 앞서 전달받은 문서와 같아요. 내보내기에 포함된 제목·Notion 상태도 보존하고 기존 JSON의 출처 해시만 맞췄어요.
- 현재 Notion의 컴포넌트 문서 상태는 모두 `진행 중`이에요. Notion의 상태가 코드 대조 결과나 JSON의 사용자 승인 상태를 대신하지 않아요. Notion 상태와 JSON의 사용자 검토 상태를 자동으로 연결하지 않아요.

본문에서는 TextField의 X가 연결되지 않았다는 설명, Select·SegmentControl의 disabled 미지원 설명, 진행률이 여섯 값으로 제한된다는 설명 등을 확인했어요. 최신 API 보완 전의 설명일 수 있으므로 실제 코드와 대조해 JSON의 기술 설명을 맞추고 review.implementationGaps에 원문과의 차이를 기록했어요. 원문은 수정하지 않았어요.

### 추가 변환 전에 합의한 항목

2026-11-24에 사용자가 다음 안내를 확정했어요. 원문의 고정 개수 설명은 그대로 보존하고, 해당 JSON 초안에는 권장 범위와 실제 구현을 구분해 반영해요.

- SegmentControl은 2~4개 항목을 권장해요. 현재 배열 타입과 구현에서 이 개수를 강제로 제한하지 않아요.
- NavigationBar·NavigationBarGlass는 3~5개 항목을 권장해요. 현재 배열 타입과 구현에서 이 개수를 강제로 제한하지 않아요.

추가로 사용자가 NavigationBar·NavigationBarGlass의 항목별 disabled 제거와 SnackBar 자동 닫힘을 확정했어요. 단독 Bar Item의 disabled도 제외하며 Drawer의 네이티브 버튼 속성이나 FabMenu의 개별 disabled를 제거하는 변경은 아니에요.

SnackBar는 기본 5초, duration=0이면 유지하고 open·defaultOpen·onOpenChange로 제어·비제어 표시를 제공해요. 마우스·내부 포커스·창 비활성 중에는 남은 시간을 보존해요. 액션은 기존 onAction만 실행하며 즉시 닫힘은 부모가 open을 변경해요. 원문은 변경하지 않고 JSON에 사용자 합의 후의 실제 동작을 반영했어요.

### 추가 JSON 초안 현황

본문이 있는 원문 21개에서 공개 컴포넌트 JSON 31개를 작성했어요. Button을 포함하며 같은 원문을 공유하는 하위 컴포넌트도 각각 목적·실제 API·조합 책임을 구분했어요. Tab은 미작성이고 Modal·Divider는 이번 Notion 내보내기에 원문이 없어 별도 JSON을 만들지 않았어요. 기존 공개 컴포넌트가 삭제됐다는 뜻은 아니에요.

전체 Props·기본값·CSS 수치 표나 긴 원문을 그대로 복제하지 않았어요. Color·Variant의 묶인 기준은 유지하고, 공개 심벌이 아닌 Text·Card·BottomSheet 등은 일반 콘텐츠·소비 앱 화면으로 설명했어요. 최초 변환에서는 원문에 React 코드가 없어 examples를 null로 두었고, 이후 개발자가 공개 API를 사용한 예시를 컴포넌트마다 한 개씩 보완해 타입 검사했어요. 원문 작성자의 예시와 구분해요.

기술 설명이 오래된 부분은 처음에 review.implementationGaps에 기록했어요. 현재 코드와 사용자 합의로 정리한 내용은 [검토 기록](component-guide-review.md)에 옮기고 미해결 목록에서 제거했어요. 당시 사용 기준·예시의 기술 검토 이후 사용자 승인을 받아 기존 31개는 stable로 전환했어요. 이 승인은 이후 추가한 문서에 자동 적용하지 않아요.

### Button 초안의 보완 사항

[원본](../apps/docs/content/source/components/button.md)과 [JSON 초안](../apps/docs/content/components/button.json)을 함께 확인해요. Color·Variant 추천 6개와 크기 선택 기준 2개를 담았어요. 기본 Props 표와 CSS 치수는 복제하지 않았어요.

| 확인한 항목 | JSON에 반영한 내용 |
| --- | --- |
| 원문 3.2의 HTML 속성 | 현재 코드가 `dangerouslySetInnerHTML`도 제외한다는 사실을 보완했어요. |
| Focus 설명 | 전용 디자인 상태가 없다는 사실과 네이티브 키보드 포커스 지원을 구분했어요. |
| Modal 조합 | 내부 Button과 공개 액션 props를 사용해요. `<Modal><Button /></Modal>` 예시는 만들지 않았어요. |
| Ghost 배경 | 사용자 합의에 따라 Brand·Neutral의 Default만 투명하게 바꾸고 나머지 상태는 유지해요. 이 구현은 기존 공개 콘텐츠에 자동 반영되지 않아요. |
| 코드 예시·콘텐츠 제한 | 최초에는 null로 두었어요. 이후 개발자가 타입 검사를 거친 코드 예시를 보완했고, 미전달 콘텐츠 제한은 null로 유지해요. |

준비 당시 JSON은 `draft`였고, 2026-11-24에 사용자 승인으로 31개 모두 `stable`로 전환했어요. 질문·구현 차이가 비어 있는 것만으로 승인으로 보지 않아요. 이후 전달받는 문서도 `draft`로 시작해 같은 절차로 승인해요.

### 첫 준비의 검증 기록

2026-11-24에 기존 개발 도구의 JSON Schema 검사기로 스키마·템플릿·Button 초안과 잘못된 입력 5개를 확인했어요. 원문 해시·공개 이름/그룹·관련 컴포넌트를 대조하고 선택 기준 8개의 props가 실제 Button 타입을 만족하는지 TypeScript로 확인했어요. 검사기 의존성이나 CI 작업을 새로 추가하지 않았어요.

Chromium의 실제 Button에서 Ghost의 두 색상·두 크기·네 상태를 수정 전후 비교했어요. Default 배경만 투명해지고 Hover·Pressed·Disabled의 배경과 글자색·테두리·그림자·높이·padding은 유지됐어요. 실기기·다른 브라우저의 전체 행렬은 이번에 반복하지 않았어요.

`pnpm size` 결과는 내부 UI tarball 자체의 압축 125,965 B·압축 해제 480,411 B·321개 파일이에요. CLI·선택 JSON·추가 의존성을 합친 전체 다운로드량이 아니에요. 새 실행 의존성·버전 증가·기존 공개 파일 교체는 없으며 Ghost 변경은 다음 UI 콘텐츠 MINOR에 포함해요.

## 추가 변환과 동작 변경을 검증했어요

2026-11-24에 다음 범위를 확인했어요.

- JSON 31개·빈 템플릿의 스키마, 잘못된 입력 5개의 거부, 원문 21개와 출처 해시, 공개 이름·그룹·참조를 확인했어요. 선택 기준 31개는 조합 전체를 실제 Props의 Partial 타입과 대조했어요. 문서의 승인이나 예시 실행 검증을 대신하지 않아요.
- 보존한 Notion 원문 23개의 파일 바이트·해시와 변경 문서의 로컬 링크·앵커 119개를 확인했어요. git diff --check도 통과했어요.
- pnpm check의 타입·린트·Storybook 빌드·실제 UI tarball 소비·Chromium 상호작용과 axe·Next.js SSR/hydration·용량 검사를 실행했어요. Navigation의 모든 항목 이동, SnackBar의 기본 타이머·마우스/포커스/창 비활성 일시 정지·재표시·시간 변경·제거 시 정리를 확인했어요.
- pnpm test:registry로 생성 JSON의 파일·의존 관계와 선택 설치한 소스의 타입·Vite·Next.js SSR/hydration·같은 브라우저 동작을 확인했어요. 실제 npm 게시·공개 콘텐츠 교체는 하지 않았어요.
- 빌드한 Storybook의 직접 바꿔보기에서 duration·open args 반영, 자동 닫힘과 다시 표시하기를 확인했어요. 한눈에 보기는 duration=0으로 두 예시가 유지돼요.

일반 pnpm check의 첫 실행은 이 컴퓨터의 Node 24.21.0에서 선택적 소켓 QoS의 setTypeOfService EINVAL 오류로 중단됐어요. 로컬 검증 프로세스에서만 해당 QoS 메서드를 사용하지 않게 한 뒤 위 브라우저·Next.js·소스 소비 검사를 완료했어요. 임시 처리는 Git에서 제외한 .artifacts에만 두었으며 공유 프로젝트·개인 설정·배포 코드에는 추가하지 않았어요. 이 환경 조건을 생략해 일반 실행과 같은 검증으로 표현하지 않아요.

최종 내부 UI tarball은 압축 127,822 B·압축 해제 486,147 B·325개 파일이에요. 새 실행 의존성이나 실제 버전 증가는 없어요. UI 콘텐츠의 다음 MINOR 대상으로 CHANGELOG에 기록했으며 전체 브라우저·모바일 실기기·패키지 매니저 행렬을 이번에 반복하지 않았어요.

## 사용 예시와 사용자 검토를 준비했어요

2026-11-24에 공개 컴포넌트별 개발자 사용 예시 31개를 보완하고 실제 레지스트리 소스와 함께 타입 검사·Vite 빌드를 확인했어요. 해결한 원문 차이와 각 JSON의 검토 상태는 [검토 기록](component-guide-review.md)에 있어요. 원문·해시·사용 목적은 유지하고 확인되지 않은 디자인 규칙은 추가하지 않았어요.

## 추가 전달 문서 세 개를 정리했어요

2026-11-24에 Modal·Divider·Tab 원문을 ZIP으로 받아 원문·해시와 JSON 초안을 추가했어요. Tab의 빈 원문은 새 전달본으로 교체했어요. 현재 보존한 컴포넌트 Markdown은 24개, 작성 템플릿 원문은 1개이며 공개 심벌별 JSON은 34개예요. 원문 수와 컴포넌트 수가 다른 이유는 한 문서가 하위 컴포넌트를 함께 설명하기 때문이에요.

기존 승인본 31개와 UI 구현은 변경하지 않았어요. 새 문서 3개는 draft로 작성·검증한 뒤 사용자의 진행 요청에 따라 stable로 전환했어요. 이전 시점의 준비·검증 기록은 위에 보존하고 현재 결과와 구분해요.

추가 원문의 기술 설명 보완과 검토 목록은 [검토 기록](component-guide-review.md#추가-원문-세-개를-대조했어요)에서 확인해요. Modal은 이미 합의한 닫힘·포커스 동작을 유지하고, Tab의 그룹 동작은 소비 앱 예시로 구분했어요. 이전 미커밋 지침 보완 8개는 별도 stash에 보존했으며 이번 문서 추가에 섞지 않았어요.

- ZIP의 Markdown 3개가 저장한 원문 바이트·출처 해시와 일치해요. 스키마·공개 이름/그룹·조합 참조는 JSON 34개 전체에서 확인했고, 기존 선택 기준 31개도 실제 Props와 대조했어요.
- pnpm test:docs의 생성·조회 검사 8개를 통과했어요. 추가한 draft가 목록에 반영되고 미승인 섹션·예시는 응답에 나오지 않아요. 생성 TS 데이터는 Git에서 제외하며 직접 수정하지 않았어요.
- 새 예시 3개는 현재 UI 콘텐츠 0.3.0의 레지스트리에서 필요한 소스만 복원해 strict 타입·Vite/CSS 빌드를 통과했어요. 기본 로컬 import와 별도 CSS import가 필요 없는 연결을 확인했어요.
- Chromium에서 Modal의 열기·Positive 후 닫기·Dim/Secondary/Esc 닫기·포커스 복귀, Divider 표시, Tab 예시의 단일 선택·패널·방향키/Home/End를 확인했어요. Tab 그룹 처리는 예시의 소비 앱 코드예요. 브라우저 콘솔 오류는 없었어요.
- 최신 main의 의존성은 고정 lockfile 그대로 준비했으며 lockfile·UI·하네스·CLI 구현·버전은 변경하지 않았어요. 이번 변경은 문서·JSON·검토 상태 검사이므로 전체 UI 빌드·릴리스 행렬·용량 측정은 반복하지 않았어요. 실제 모바일 기기와 모든 브라우저에서 예시를 확인했다는 뜻은 아니에요.

2026-11-24에 사용자의 진행 요청으로 추가 3개를 승인하고 전체 34개를 stable로 전환했어요. 문서 조회 검사 8개를 통과했고 승인본의 예시·접근성 섹션이 요청대로 반환되는지 확인했어요. pnpm build:docs도 통과해 /mcp가 동적 서버 경로로 빌드되는 것을 확인했어요. 로컬 승인·검증과 실제 원격 MCP 배포 확인은 구분해요.

## 담당자가 이어서 연결해요

문서 웹사이트와 MCP는 공통 조회 계층에서 같은 JSON을 읽어요. 목록에는 짧은 설명만, 상세 조회에는 요청한 부분만 반환해요. 설치 파일은 UI 레지스트리, 실제 로컬 import는 소비 프로젝트의 설치 기록을 기준으로 해요.

읽기 전용 MCP는 파일 설치를 실행하지 않아요. 하네스의 스킬·훅과 사용 가이드의 담당 범위는 [하네스 지침](../Agent/harness.md)을 따라요. 이번 준비에서 `packages/harness`의 구현·배포물은 수정하지 않아요.

JSON 자체의 토큰 절감률은 아직 측정하지 않았어요. 부분 조회가 구현되면 동일한 내용·토크나이저로 문서 본문·전체 JSON·부분 JSON을 비교하고, 필요한 호출 횟수와 실제 작업 결과도 함께 확인해요.
