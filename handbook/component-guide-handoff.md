# MCP·하네스 컴포넌트 가이드 연동 인계

2026-11-24 기준으로 규칙 데이터와 예시를 준비한 인계 문서예요. 실제 MCP 도구·조회 계층·하네스 연결을 구현하거나 담당자에게 별도 메시지를 전송한 상태는 아니에요. PR에서 이 문서를 확인할 수 있게 연결해요.

## 연결한 뒤의 상태

이 문서를 작성한 뒤 조회 계층과 MCP 도구를 가이드 JSON에 연결했고, 2026-11-24에 사용자가 31개 문서를 승인해 `stable`로 전환했어요. 일반 응답은 `stable`의 내용만 담아요. `draft`인 컴포넌트는 목록에 상태만 나오고 섹션은 비어 있어요. 검토 전용 조회는 만들지 않았어요. 이후 Modal·Divider·Tab 원문과 가이드 초안을 추가해 처음에는 stable 31개·draft 3개로 검증한 뒤, 사용자의 진행 요청으로 추가 3개도 승인해 로컬 데이터 기준 전체 34개가 stable이에요. 실제 공개 응답 반영은 배포 후 별도로 확인해요. GET API·실제 하네스 흐름과 토큰 측정은 별도 작업이에요. 데이터 생성기의 기본 검사와 로컬 스키마·예시 검증, CI의 전체 스키마 검증 연결을 구분해요. 아래는 연결 전 시점의 인계 기록이며 현재 검토 상태는 [검토 기록](component-guide-review.md)을 기준으로 확인해요.

## 준비된 자료

| 자료 | 위치·용도 |
| --- | --- |
| 디자이너 원문 | apps/docs/content/source/components의 Markdown 22개, 템플릿 원문 1개를 그대로 보존했어요. |
| 검토용 데이터 | apps/docs/content/components의 공개 심벌별 JSON 31개예요. 사용자 승인 전 draft이며 각 문서에 타입 검사를 거친 개발자 예시가 있어요. |
| 형식 | [JSON Schema](../apps/docs/content/component-guide.schema.json)와 [빈 템플릿](../apps/docs/content/templates/component-guide.json)을 기준으로 읽어요. |
| 대조 결과 | [검토 기록](component-guide-review.md)에 원문과 구현의 차이·처리 결과·예시별 검토 상태가 있어요. |
| 규격의 기준 | 도구 이름·입출력·섹션 매핑은 [원격 MCP 규격](../Agent/mcp-spec.md#컴포넌트-json과-응답을-연결해요)에서 관리해요. 여기에 별도 규격을 만들지 않아요. |

현재 모든 문서는 사용자 검토 전이라 기본 공개 조회에 제공할 승인본은 0개예요. 초안이 있다는 이유로 공개 검색이나 일반 상세 조회에 포함하지 않아요. Tab은 본문 미작성, Modal·Divider는 원문 미전달 상태예요. 미제공 문서를 임의로 만들어 채우지 않아요.

## 설명 대상인 UI를 먼저 확인해요

이번 가이드는 현재 main에 이미 게시된 콘텐츠와 같다는 뜻이 아니에요. Navigation의 항목별 disabled 제거·SnackBar 자동 닫힘·Ghost 기본 배경 변경을 포함한 다음 UI 콘텐츠 MINOR 후보를 설명해요. [UI PR #103](https://github.com/ELI-team/ELI/pull/103)의 기준 커밋 1acaffa749c11a2316b28ce44499bf263d70b51c와 문서 PR의 검증 기록을 함께 확인해요. 문서의 일반 공개와 병합 순서는 이 UI 변경이 반영된 뒤 결정해요. workspace manifest에 남은 0.2.0 숫자만 보고 공개 v0.2.0과 같은 API로 안내하지 않아요.

사용자가 문서를 승인한 뒤에도 설명 대상 UI 콘텐츠가 실제 공개되었는지 담당자가 확인해야 해요. 원격 서버의 ui.docs·ui.latest와 설치 도구 버전을 바꾸는 작업은 [버전 기준](../Agent/versioning.md#설치-도구와-콘텐츠-버전을-구분해요)에 맞춰 별도로 진행해요. 이 인계로 기존 get_versions 필드의 의미나 하네스 호환 범위가 자동 변경되지는 않아요.

## 담당자가 이어서 구현할 순서

1. JSON을 스키마로 검증하고 source 해시·공개 id/name/group·선택값·참조를 대조하는 데이터 검사를 연결해요. 승인 상태와 공개 대상 UI 버전도 확인해요.
2. content/query.ts에서 승인본의 목록·상세·섹션·검색을 구현해요. 사람용 문서·GET API·MCP가 같은 조회 계층을 읽어요.
3. 기존 일곱 도구와 섹션 키에 연결해요. 필요한 섹션만 정적으로 표현하고 조회 중 AI로 새 규칙을 만들지 않아요. examples를 가져오지 않은 사용 목적 조회에 코드 예시를 덧붙이지 않아요.
4. 하네스가 같은 MCP를 조회하도록 연결해요. 규칙 JSON을 harness 폴더나 스킬에 다시 복사하지 않아요. 실제 설치·변경은 신뢰하는 CLI와 설치 기록을 사용하는 기존 계약을 따라요.

세부 필터·null/빈 배열·오류 형식·일반 응답에서 제외할 내부 정보는 원격 MCP 규격을 그대로 적용해요. 이 문서는 구현 작업의 인계 목록이며 별도 서버나 새 도구를 요구하지 않아요.

## 예시 import를 소비 프로젝트에 맞춰요

코드 예시는 기본 설치 위치를 사용하는 Example.tsx를 전제로 해요. [예시 위치와 검증 범위](component-guide-review.md#예시의-설치-위치와-검증-범위)를 함께 안내해요. ./components/ui/button 같은 문자열을 사용자 프로젝트의 절대적인 import로 취급하지 않아요.

하네스는 컴포넌트 id를 UI 레지스트리와 연결하고, 소비 프로젝트의 eli.json·설치 기록·실제 파일로 import를 확인해요. 서버는 로컬 설치 경로를 모르므로 예시를 반환하는 것과 사용자 파일에 맞춰 import를 결정하는 일을 구분해요. 설치되지 않았다면 신뢰하는 설치 도구로 추가하는 기존 흐름을 사용해요.

예시에 여러 컴포넌트가 등장하면 실제 import한 항목을 함께 확인해요. 예를 들어 Drawer의 루트만 설치했다고 Category·Menu까지 자동 제공된다고 가정하지 않아요. 레지스트리의 실제 소스 의존성, 가이드의 조합 관계, 관련 컴포넌트 추천은 서로 다른 정보예요. 관련 목록 전체를 설치하지 않아요.

## 연결 완료 시 확인할 항목

- draft는 목록·검색·상세와 검색 색인에서 기본적으로 제외되고, 검토 전용 조회에만 나타나요.
- 승인본이 없는 상태의 목록은 빈 결과를 반환하며, 미승인 상세 조회를 승인본으로 바꿔 반환하지 않아요.
- 같은 컴포넌트·섹션 요청을 GET API와 MCP에서 같은 의미로 반환해요.
- 사용 목적 조회에 전체 JSON·예시·Props 표를 중복 전송하지 않아요. 원문 경로·해시·review는 일반 응답에서 제외해요.
- null과 빈 배열을 구분하며 없는 섹션을 만들거나 빈 템플릿을 컴포넌트로 노출하지 않아요.
- 실제 설치된 UI 버전·로컬 import·사용자 수정 여부를 확인하고, 다른 버전의 prop을 그대로 삽입하지 않아요.
- 하네스에서 조회·선택·설치·사용 흐름을 실제로 실행하고 토큰 수·호출 횟수·작업 결과를 함께 기록해요. 현재는 연결이나 토큰 절감 검증을 완료한 상태가 아니에요.
