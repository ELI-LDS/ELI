# MCP·하네스 컴포넌트 가이드 연동 인계

컴포넌트 가이드의 준비 상태와 담당자가 이어서 확인할 범위를 관리해요. 도구 계약은 [원격 MCP 규격](../Agent/mcp-spec.md), 변환과 승인은 [JSON 검토 절차](component-guide-json.md)를 기준으로 해요. 담당자에게 별도 메시지를 전송한 상태는 아니며 PR에서 이 문서를 연결해요.

## 현재 연결 상태

2026-11-24 기준으로 컴포넌트 가이드 34개를 사용자가 승인해 모두 `stable`이에요. 가이드 JSON·레지스트리에서 데이터를 생성하고 공통 조회 계층과 원격 MCP 도구로 제공해요. 사용자용 문서 웹페이지와 GET API는 아직 구현 전이에요.

일반 조회는 승인된 가이드의 내용만 제공해요. `draft`이거나 가이드가 없는 컴포넌트도 목록에는 상태·설치 정보가 나오고 코드에서 추출한 props는 조회할 수 있지만, 미승인 사용 기준과 예시는 제공하지 않아요. 별도 검토용 초안 본문 조회는 없어요. 필터를 이 문서에 따로 정의하지 않고 [조회 기준](../Agent/docs.md#조회-계층을-하나로-둬요)을 따라요.

이 문서는 가이드 데이터와 MCP 조회의 인계예요. 하네스의 설치·세션 연결 구현과 실제 에이전트 사용 검증은 [하네스 지침](../Agent/harness.md)에서 구분해요. 이번 작업에서 하네스 구현을 수정하지 않았어요.

## 준비된 자료

| 자료 | 위치·용도 |
| --- | --- |
| 디자이너 원문 | apps/docs/content/source/components의 Markdown 24개와 source/templates의 작성 양식 1개를 전달받은 바이트 그대로 보존했어요. |
| 검토한 데이터 | apps/docs/content/components의 공개 심벌별 JSON 34개예요. 사용자 승인과 검증한 개발자 예시를 포함해요. |
| 형식 | [JSON Schema](../apps/docs/content/component-guide.schema.json)와 [빈 템플릿](../apps/docs/content/templates/component-guide.json)이 필드·자료형의 기준이에요. |
| 대조 결과 | [검토 기록](component-guide-review.md)에 원문과 구현의 차이·처리 결과·예시별 검증 범위가 있어요. |
| 조회와 도구 | apps/docs/content/query.ts와 backend/mcp/server.ts가 같은 생성 데이터를 조회해요. 도구 이름·입출력·섹션 매핑은 [원격 MCP 규격](../Agent/mcp-spec.md#컴포넌트-json과-응답을-연결해요)에서 관리해요. |

원문 수와 JSON 수가 다른 이유는 한 문서가 하위 컴포넌트를 함께 설명하기 때문이에요. 가이드 규칙을 하네스 폴더나 스킬에 복제하지 않아요.

## 공개 MCP에서 확인한 범위

2026-11-24에 [가이드 PR #114](https://github.com/ELI-team/ELI/pull/114)를 병합하고 main 커밋 `4964548`의 Cloudflare 빌드가 성공한 뒤 `https://eli-design.dev/mcp`에 실제 요청을 보냈어요.

- list_components 응답의 34개 항목이 모두 stable이며 로컬 목록과 일치했어요.
- Modal·Divider·Tab의 summary·examples·accessibility·variants를 요청해 승인된 로컬 조회 결과와 일치하는지 확인했어요. 예시는 기본 설치 경로의 로컬 import를 사용해요.
- Modal의 open·defaultOpen·onOpenChange props와 도구 응답의 진입 파일·export가 로컬 데이터와 일치했어요.
- get_versions는 ui.latest·ui.docs를 모두 0.3.0으로 반환했어요. 설치 도구·하네스의 독립 버전을 UI 버전으로 대신하지 않았어요.
- 요청한 섹션만 반환하고 일반 상세 응답에 원문 경로·해시·review를 포함하지 않는지 확인했어요.

이는 공개 MCP의 데이터 반영 확인이에요. 실제 Claude Code·Codex 세션에서 조회·선택·설치·사용을 모두 검증했거나 토큰 절감률을 측정했다는 뜻은 아니에요. 예시별 타입·빌드·브라우저 확인 범위는 검토 기록을 함께 확인해요.

## 설명 대상 UI 버전을 확인해요

현재 가이드는 공개 UI 콘텐츠 0.3.0과 대조했어요. 과거 UI PR #103의 Navigation·SnackBar·Ghost 변경은 해당 콘텐츠에 포함되어 있어요. 이후 main의 UI가 바뀌면 다음 공개 콘텐츠 릴리스 전까지 서버 설명과 설치 버전이 다시 달라질 수 있어요.

원격 서버의 ui.docs·ui.latest와 설치 도구 버전은 [버전 기준](../Agent/versioning.md#설치-도구와-콘텐츠-버전을-구분해요)에 따라 구분해요. 현재 서버가 버전을 정하는 방식과 남은 배포 정책은 [원격 MCP의 구현 상태](../Agent/mcp-spec.md#구현-상태)에서 확인해요. 이 문서로 도구 필드의 의미나 하네스 호환 범위를 변경하지 않아요.

## 예시 import를 소비 프로젝트에 맞춰요

코드 예시는 기본 설치 위치를 사용하는 Example.tsx를 전제로 해요. [예시 위치와 검증 범위](component-guide-review.md#예시의-설치-위치와-검증-범위)를 함께 안내해요. ./components/ui/button 같은 문자열을 사용자 프로젝트의 절대적인 import로 취급하지 않아요.

하네스는 컴포넌트 id를 UI 레지스트리와 연결하고, 소비 프로젝트의 eli.json·설치 기록·실제 파일로 import를 확인해요. 서버는 로컬 설치 경로를 모르므로 예시를 반환하는 것과 사용자 파일에 맞춰 import를 결정하는 일을 구분해요. 설치되지 않았다면 신뢰하는 설치 도구로 추가하는 기존 흐름을 사용해요.

예시에 여러 컴포넌트가 등장하면 실제 import한 항목을 함께 확인해요. 예를 들어 Drawer의 루트만 설치했다고 Category·Menu까지 자동 제공된다고 가정하지 않아요. 레지스트리의 실제 소스 의존성, 가이드의 조합 관계, 관련 컴포넌트 추천은 서로 다른 정보예요. 관련 목록 전체를 설치하지 않아요.

## 담당자가 이어서 확인해요

- 데이터 생성기의 기본 검사와 별도로 로컬에서 수행한 전체 스키마·선택값·예시 검증을 구분하고, CI 연결이 필요한 범위를 확인해요. 실제 실행한 자동 검사는 [검증 기준](../Agent/testing.md)을 따라 기록해요.
- 사람용 문서 화면과 GET API를 구현할 때 기존 공통 조회 계층을 사용해요. 같은 요청이 MCP와 같은 의미로 반환되는지 확인해요.
- 하네스의 실제 에이전트 세션에서 조회·선택·설치·사용을 확인해요. 설치된 UI 버전·로컬 import·사용자 수정 여부를 확인하고 다른 버전의 prop을 그대로 삽입하지 않아요.
- 부분 조회의 효과는 토큰 수·호출 횟수·작업 결과를 함께 측정해요. JSON 형식이나 조회 도구가 있다는 이유만으로 토큰 절감 검증을 완료했다고 표현하지 않아요.
