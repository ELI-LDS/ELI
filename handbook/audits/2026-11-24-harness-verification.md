2026-11-24에 main `33db3b1`과 공개 CLI·하네스를 확인했어요. 요청한 PR #117·#118은 이미 병합되어 있었고 열린 PR은 없었어요. 하네스·MCP·UI 구현과 개인 도구 설정은 수정하지 않았어요. 이번 결과는 전체 에이전트 제작 흐름의 완료 판정과 구분해요.

공개 npm에서 받은 CLI를 임시 경로에 설치해 실행했어요. 공개 하네스와 UI는 GitHub Release에서 받았으며 로컬 후보 레지스트리로 대신하지 않았어요. 하네스만 설치한 프로젝트에는 React·UI 초기 설정이나 전체 UI 패키지가 추가되지 않았어요.

소스 경로 검증 프로젝트는 React 메타데이터만 갖춘 설치용 fixture예요. 이 fixture의 검증을 실제 React 앱의 타입·빌드·렌더링 검사로 설명하지 않아요. 이번에는 UI 코드를 바꾸지 않아 전체 UI·브라우저·패키지 매니저 행렬을 반복하지 않았어요.

### 수정한 의존 파일의 보호

Button을 직접 수정한 상태에서 Select를 추가하면 수정한 Button은 유지되고 Select의 MenuItem 의존성만 함께 설치돼요. Modal은 Button을 실제로 참조하므로 이 상태에서 추가하면 FILE_CONFLICT로 중단돼요. 기존 Button과 eli.lock.json은 그대로 유지됐어요.

이는 현재 설치 계약의 충돌 보호 동작이에요. 자동 재사용을 기대해 성공으로 처리하거나 수정한 파일을 원본으로 되돌리지 않았어요. 하네스도 이 상황에서 실패 이유를 설명하고 사용자 변경의 처리 방안을 먼저 확인해야 해요.

## 실제 Codex 세션에서 확인한 것

공개 하네스를 설치한 프로젝트에서 읽기 전용 세션을 실행했어요. 설치된 eli 스킬과 설치 기록을 읽도록 요청하고, 저장 버튼·단일 분류 선택·변경 확인 창의 요구를 전달했어요. 컴포넌트 이름과 prop 정답은 요청에 넣지 않았어요. 스킬을 명시해서 사용했으므로 자동 스킬 선택까지 확인한 것은 아니에요.

- 원격 MCP의 get_versions·list_components·get_component·get_props를 실제로 호출했어요. 총 22회 중 21회는 성공했고 1회는 아래 네이티브 prop 조회에서 invalid_argument를 받았어요.
- 주요 저장 행동에 Button의 brand·solid와 icon=null, onClick·disabled를 제안했어요. 존재하지 않는 loading prop을 만들지 않았어요.
- 단일 선택에 Select와 value·onValueChange·옵션별 disabled를 제안했어요. 승인된 문서와 실제 설치 소스를 대조했어요.
- 확인 창에 Modal의 open·onOpenChange·액션 콜백을 제안하고 Positive 성공 후 닫힘은 소비 앱의 책임으로 구분했어요.
- 설치된 로컬 Button·Select의 실제 경로를 읽고, 설치하지 못한 Modal의 로컬 import는 없다고 정확히 보고했어요. 추천한 SnackBar도 미설치임을 구분했어요.
- UI·하네스·설치 도구 버전을 구분하고 수정된 Button을 감지했어요. 읽기 전용 세션 뒤에도 하네스 파일 46개는 그대로였고 UI의 기존 수정 파일은 Button 한 개뿐이었어요.
- DESIGN.md·UX-WRITING.md가 없어 프로젝트별 토큰·문구 기준은 확인할 수 없다고 밝혔어요. 셋업이나 화면 생성을 실행하지 않았어요.

이 결과는 문서 조회·선택 계획·설치 상태 확인의 통과예요. 실제 기능 코드를 생성하거나 저장·선택·모달을 브라우저에서 실행한 결과는 아니에요. Codex 훅 신뢰와 설치한 현재 세션의 자동 셋업도 별도 확인 대상이에요.

### MCP 담당자와 검토할 안내

실제 세션의 첫 Button props 요청에는 네이티브 type이 포함됐어요.

```json
{"name":"Button","names":["children","icon","onClick","disabled","variant","color","type"]}
```

응답은 `invalid_argument`와 “prop 'type'은(는) 쓸 수 없어요.”였어요. 현재 [get_props 계약](../../Agent/mcp-spec.md#get_props)은 직접 정의한 props만 조회하고 상속은 extends로 알려주므로 구현이 이 계약을 위반한 것은 아니에요. 그러나 Button이 type 자체를 지원하지 않는다는 뜻으로 읽힐 수 있어요.

에이전트는 allowed 목록으로 재조회하고 문서·로컬 코드에서 기본 type=button을 확인해 복구했어요. MCP 담당자에게는 다음을 검토할 항목으로 남겨요. 이번 검증에서 도구나 하네스를 변경하지 않았어요.

- 조회할 수 없는 이름과 HTML에서 실제 사용할 수 없는 prop을 구분해 설명할 수 있는지 확인해요.
- 상속 prop은 extends와 로컬 타입에서 확인하도록 오류 안내를 보완할지 검토해요.
- 직접 정의한 props만 반환하는 현재 범위를 유지할지, 상속 prop까지 확장할지는 담당자가 별도 계약 변경으로 결정해요.

### 호출량 기록

세션이 보고한 누적 사용량은 입력 304,397토큰(캐시 입력 267,520 포함), 출력 2,428토큰이에요. 여러 모델 호출에 걸친 합계이므로 한 번에 받은 문서의 크기나 고유 컨텍스트 길이를 뜻하지 않아요. 같은 과제의 비교 실행이 없어서 절감률·성능 개선 수치로 사용하지 않아요.

## 읽기 전용 검증에서 확인하지 못한 범위

- Claude Code 실제 세션: 로그인되지 않아 미실행이에요. 로그인 정보나 개인 설정을 변경하지 않았어요.
- Codex 자동 스킬 선택·훅 신뢰·설치한 현재 세션의 자동 셋업: 명시적으로 스킬을 읽는 읽기 전용 검증과 구분해요.
- 소스 선택 설치·기능 코드 생성·타입·빌드·브라우저 조작은 당시 미실행이었어요. 이후 아래 임시 앱 실험에서 Codex의 해당 흐름을 확인했으며 Claude와 모든 지원 환경의 완료를 뜻하지는 않아요.
- 네트워크 단절·미승인 가이드·버전 불일치 상황에서 실제 에이전트의 판단: 미실행이에요. 자동 파일 보호 검사를 이 결과로 대신하지 않아요.
- 웹사이트·문서 화면 제작, npm 게시, 토큰 절감 비교: 범위에 포함하지 않았어요.

기존 시스템의 Codex CLI 0.46.0은 모델 서버가 더 새 클라이언트를 요구해 실행 전 실패했어요. ELI 문제와 구분해 기록하고 개인 도구를 업데이트하는 대신 임시 CLI로 위 읽기 전용 검증을 마쳤어요. 후속 확인은 [실행 체크리스트](../harness-guide-acceptance.md)의 남은 시나리오를 사용해요.

## 후속 임시 React 앱 생성·실행

사용자의 요청에 따라 Storybook 외부의 임시 React 앱에서 생성 코드까지 검증했어요. Storybook은 컴포넌트 자체와 제공한 예시를 검수하며, 이 실험은 소비 프로젝트의 설치 경로·기능 연결 코드를 하네스가 작성하는지 확인해요. 실제 웹사이트를 만들거나 배포하지 않았어요.

### 준비와 실행 범위

- 공개 UI 0.3.0의 목록·필요한 의존 JSON 11개를 받아 SHA-256을 대조한 뒤 로컬 스냅샷으로 제공했어요. Codex는 공개 CLI 0.4.0으로 Button·Select·Modal과 의존 MenuItem만 선택 설치했어요. 샌드박스 안의 설치는 이 스냅샷을 사용했고 원격 문서는 실제 공개 MCP에서 읽었어요.
- React 진입점·저장 함수 mock·검증용 프로젝트 문서는 검사자가 준비했어요. Codex가 App.tsx의 상태·이벤트·컴포넌트 조립 코드를 작성했어요. 새 앱의 기술 스택·전체 초기 설정까지 자동 선택한 실험은 아니에요.
- 개발 의존성은 저장소의 고정된 node_modules를 심볼릭 링크로 연결했어요. 독립 npm 설치·패키지 매니저 행렬·폰트 로딩·시각 검수를 다시 수행한 결과로 설명하지 않아요.

### 첫 생성에서 발견한 문제와 피드백

첫 생성은 strict 타입·프로덕션 빌드와 저장·선택 기능을 통과했지만, 저장 처리 중 모든 모달 닫힘 요청을 막는 조건을 소비 앱에 추가했어요. 취소·Dim·Escape로 닫혀야 하는 요구와 달랐어요. 공개 Modal 소스의 문제는 아니에요. 별도 토큰 CSS import도 불필요하게 추가했어요.

검사자가 브라우저 실패 결과와 원하는 동작을 피드백했고, Codex가 App.tsx만 한 차례 수정했어요. 처리 중에도 닫힘을 허용하고 포커스를 복원하도록 열기 버튼을 처리했으며, 중복 저장 방지와 성공 후 닫힘을 유지하고 별도 CSS import를 제거했어요. 검사자가 생성된 App 코드를 직접 고치지는 않았어요.

### 최종 결과

- 공개 UI·하네스 소스의 파일 해시는 그대로이며 관계없는 UI는 설치하지 않았어요.
- strict 타입 검사와 Vite 프로덕션 빌드를 통과했어요. 컴포넌트 import만으로 기본 CSS·토큰이 연결됐어요.
- Chromium에서 저장 함수 호출·처리 중 비활성화·중복 실행 방지·성공 문구를 확인했어요.
- 선택값·placeholder·비활성 옵션 제외·목록 닫힘·방향키/End/Escape·포커스 복귀를 확인했어요.
- Modal의 초기 닫힘·열기·콘텐츠 클릭 유지·취소/Dim/Escape 닫기·재열기·포커스 순환과 복귀를 확인했어요.
- Positive 중복 방지·실패 시 창 유지·성공 후 닫힘과 처리 중 취소/Dim/Escape 닫힘·배경 스크롤 복원을 확인했어요. 브라우저 콘솔·페이지 오류는 없었어요.

생성 세션의 MCP 호출 14회 중 설치 가이드 부재와 상속 prop 조회 제한으로 2회 오류 응답을 받았고 기존 절차로 이어갔어요. 피드백 세션의 MCP 호출 2회는 성공했어요. 원격 가이드가 전부 준비됐다고 해석하지 않아요.

실험 뒤 브라우저·임시 서버를 종료하고 임시 앱·빌드 결과·로컬 소스 캐시를 삭제했으며 경로가 더 이상 존재하지 않는지 확인했어요. 생성 App 코드가 포함된 원시 세션 로그도 제거하고 `.artifacts/harness-ui-run/result.json`에 검사 결과·코드 해시·호출 요약만 남겼어요. Storybook·실제 웹사이트·공개 UI·하네스 구현은 변경하지 않았어요.
