# CLI 0.4.0 릴리스 기록

2026-11-24 깨끗한 main `a9a3ae8c130de440e455638c20f76bfad78ee529`([#113](https://github.com/ELI-team/ELI/pull/113))에서 최종 파일을 고정해 npm `next`로 게시하고 `latest`로 전환했어요. 사용자가 없는 실험 단계라 [릴리스 절차](../releasing.md)의 일부를 생략했어요. 생략한 범위는 아래에 적었어요.

## 대상과 변경 범위

| 대상 | 버전 | 배포 상태 |
| --- | --- | --- |
| 설치 도구 eli-design | 0.4.0 | npm 게시, `latest` |
| 하네스 콘텐츠 | 0.3.0 | [harness-v0.3.0](https://github.com/ELI-team/ELI/releases/tag/harness-v0.3.0) 공개 |
| UI 소스 콘텐츠 | 0.3.0 | 공개 v0.3.0 JSON 재사용 |

`harness --agent claude`가 `.mcp.json`에 문서 서버를 등록하고, 하네스에 조회 스크립트를 더해 설치한 세션에서 셋업까지 이어가요. 디자인 시스템 페이지는 데스크톱 폭 기준으로 만들어요. 둘 다 MINOR예요.

## 실제 검증

- Node.js 24.21.0·pnpm 12.8.1·macOS arm64에서 `test:harness` 17개, `test:cli` 31개, `test:docs` 8개, `typecheck`, `lint`를 통과했어요.
- [#113의 CI](https://github.com/ELI-team/ELI/pull/113/checks)에서 패키지 매니저 설치 행렬과 registry 검사가 통과했어요. 병합 전 커밋의 결과이며 고정 tarball로 다시 실행하지는 않았어요.
- npm의 tarball과 공개 `harness.json`을 인증 없이 받아 로컬 파일과 SHA-256을 대조했어요.
- 공개 명령 `npx eli-design@0.4.0 harness --agent claude`로 UI·React 없는 새 프로젝트에 하네스 0.3.0을 설치했어요. `.mcp.json` 등록, 설치된 조회 스크립트의 `get_versions` 응답, 재실행 재사용, `status`를 확인했어요.

## 생략했거나 확인하지 못한 것

- `pnpm check`(브라우저 검사 포함)와 고정 tarball의 설치 행렬 재실행을 생략했어요.
- `cli-v0.4.0` Release의 tarball·`SHA256SUMS`·`release.json` 전달 단계를 생략했어요. 준비자와 게시자가 같아요.
- `--agent codex`의 공개 명령 확인, 기존 UI 소스가 있는 앱에서의 확인을 하지 않았어요.
- 실제 Claude Code·Codex 세션에서 설치부터 디자인 시스템까지 이어지는 흐름과 만들어지는 페이지의 모양을 확인하지 않았어요.
