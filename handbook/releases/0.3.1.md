# CLI 0.3.1 릴리스 기록

2026-11-23 깨끗한 main `8c2868b0d9ab7fec2574fcd750dbbc7803de72b9`에서 최종 파일을 고정했어요. [cli-v0.3.1 전달 파일](https://github.com/ELI-team/ELI/releases/tag/cli-v0.3.1)에 tarball·SHA256SUMS·release.json을 제공하고 세 파일 모두 인증 없이 다시 받아 로컬 바이트와 대조했어요. 2026-11-24에 npm `next`로 게시했고 npm의 tarball SHA-256이 아래 고정 파일과 같은 것을 확인했어요. 같은 날 `latest`도 0.3.1로 전환했어요. 게시 뒤 공개된 UI 콘텐츠 0.3.0과 하네스 0.2.1을 `npx eli-design@latest`로 받는 것을 확인했어요. 아래 표와 검증 기록은 파일을 고정한 시점의 UI 0.2.0·하네스 0.1.0 기준이에요.

## 대상과 변경 범위

| 대상 | 버전 | 배포 상태 |
| --- | --- | --- |
| 설치 도구 eli-design | 0.3.1 | GitHub 전달 완료, npm 게시 대기 |
| UI 소스 콘텐츠 | 0.2.0 | 공개 v0.2.0 JSON 51개 재사용 |
| 하네스 콘텐츠 | 0.1.0 | 공개 harness-v0.1.0 JSON 재사용 |

[#101](https://github.com/ELI-team/ELI/pull/101)에서 버전을 준비하고 [#99](https://github.com/ELI-team/ELI/pull/99)의 저장소 이전 주소와 [#95](https://github.com/ELI-team/ELI/pull/95)의 status 안내 개선을 묶었어요. 기존 0.3.0 후보·태그·파일은 보존해요. API 보완 [#100](https://github.com/ELI-team/ELI/pull/100)은 별도 검토 대상이며 이 파일에 포함하지 않았어요.

0.3.0 후보 이후 수정은 PATCH예요. 실제 npm 0.2.0에서 갱신할 때는 짧은 소스 경로·기본 설치 위치 변경을 포함하는 MINOR 이전이에요. 새 init은 src 유무에 따라 src/components/ui 또는 components/ui를 사용해요. 이전 위치는 init --dir로 지정하고 기존 eli.json·설치 소스·별칭은 자동 이동하지 않아요.

eli-design.dev는 웹페이지 제작 예정 주소예요. Storybook은 storybook.eli-design.dev이며 이번 후보에는 웹페이지·DNS 구현이 없어요.

## 실제 검증

- Node.js 24.21.0·pnpm 12.8.1·npm 11.19.0·macOS arm64에서 frozen 설치, pnpm check·test:registry·CLI 31개 검사를 통과했어요.
- 같은 tarball의 npm 11.19.0·pnpm 12.8.1·Yarn Classic 1.22.22·Yarn Modern 4.18.1 node-modules/strict PnP·Bun 1.4.4 실행·설치·타입·Vite·CSS·SSR을 통과했어요. 의존성·lockfile 보존, 하네스 설치·재사용과 PnP 프로젝트에서 npm으로 CLI를 실행하는 경로도 확인했어요.
- 고정 파일을 격리 설치한 실행 파일로 공개 UI의 전체 컴포넌트 34개를 추가하고 타입·Vite·CSS와 대표 Next.js SSR·hydration·Modal/TextField 동작을 확인했어요. 전체 UI 패키지를 설치하지 않았어요.
- 공개 하네스 0.1.0을 UI·React 없이 설치하고 에이전트 선택·dry-run·재사용·status와 소스 UI를 인식하는 실제 복사 훅을 확인했어요. 이전 저장소 주소의 UI 목록과 하네스 설치 기록도 버전·해시 검증을 유지하며 재사용했어요.
- [최종 커밋의 브라우저 7종 CI](https://github.com/ELI-team/ELI/actions/runs/45151271595)가 통과했어요. iOS 작업은 WebKit 설치 단계의 장시간 정체로 그 작업만 재실행했고 다른 여섯 성공 결과는 유지했어요. 같은 SHA의 로컬 iOS WebKit 검사도 통과했어요.
- GitHub 전달 파일 3개를 인증 없이 다시 받아 바이트·체크섬을 대조했어요. 실제 게시 이름으로 실행하는 npm 명령 검사는 게시 후 진행해요.

로컬 검증 도구는 격리된 임시 경로를 사용했어요. PnP 교차 실행 검사에서 필요한 Yarn 명령이 PATH에 있도록 로컬 도구 경로를 정리했으며, 개인 설정 문제를 위한 우회 코드는 공유 프로젝트에 추가하지 않았어요.

## 남은 확인과 게시

실제 macOS Safari 앱·Android/iOS 기기·VoiceOver·에이전트 신뢰·스킬 수행·원격 MCP는 별도 검증이에요. Android/iOS 자동 결과는 에뮬레이션이며 기존 axe 색상 대비 기준선 14개는 디자이너 검토 대상이에요.

npm 담당자는 [게시 안내](../npm-publishing.md)에 따라 세 파일을 받은 뒤 체크섬을 확인하고 tarball 그대로 next에 게시해요. 준비자가 명시적 npm 버전의 공개 명령·integrity를 확인한 뒤 latest로 승격해요. GitHub 파일 전달을 npm 게시 완료로 표현하지 않아요.
