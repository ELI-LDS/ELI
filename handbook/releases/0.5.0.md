# CLI 0.5.0 릴리스 기록

2026-11-24 깨끗한 main `56fa0395f18a8791d73c3702dce52add2d2035f3`([#119](https://github.com/ELI-team/ELI/pull/119))에서 최종 파일을 고정해 npm `next`로 게시하고 `latest`로 전환했어요. 사용자가 없는 실험 단계라 [릴리스 절차](../releasing.md)의 일부를 생략했어요. 생략한 범위는 아래에 적었어요.

## 대상과 변경 범위

| 대상 | 버전 | 배포 상태 |
| --- | --- | --- |
| 설치 도구 eli-design | 0.5.0 | npm 게시, `latest` |
| 하네스 콘텐츠 | 0.4.0 | [harness-v0.4.0](https://github.com/ELI-team/ELI/releases/tag/harness-v0.4.0) 공개 |
| UI 소스 콘텐츠 | 0.3.0 | 공개 v0.3.0 JSON 재사용 |

설치 설정과 기록을 `.eli/` 폴더로 옮기고, 셋업의 세 질문(서비스 기획, 디자인 레퍼런스, 브랜드 컬러)을 질문 도구로 반드시 묻게 했어요. 기록 위치 변경은 호환되지 않지만 공식 홍보 전 0.x라 MINOR로 배포해요. 하네스 0.4.0의 훅은 `.eli/`만 읽으므로 설치 도구 0.5.0 이상과 함께 써요.

## 실제 검증

- Node.js 24.21.0·pnpm 12.8.1·macOS arm64에서 `test:harness` 18개, `test:cli` 31개, `test:registry`, `test:cli:consumer`, `typecheck`, `lint`를 통과했어요.
- [#119의 CI](https://github.com/ELI-team/ELI/pull/119/checks)에서 패키지 매니저 설치 행렬과 registry 검사가 통과했어요. 병합 전 커밋의 결과이며 고정 tarball로 다시 실행하지는 않았어요.
- npm의 integrity와 공개 `harness.json`의 SHA-256을 로컬 고정 파일과 대조했어요.
- 공개 명령 `npx eli-design@0.5.0`으로 새 프로젝트에서 확인했어요.
  - `harness --agent all`: 하네스 0.4.0 설치, 루트에는 `.eli/`와 에이전트 폴더·`.mcp.json`만 생성, 조회 스크립트의 `get_versions` 응답, 재실행 재사용, `status`
  - React 19.3.0 프로젝트의 `init`, `add button tab`: `.eli/config.json`·`.eli/lock.json` 생성과 `status`

## 생략했거나 확인하지 못한 것

- `pnpm check`(브라우저 검사 포함)와 고정 tarball의 설치 행렬 재실행을 생략했어요.
- `cli-v0.5.0` Release의 tarball·`SHA256SUMS`·`release.json` 전달 단계를 생략했어요. 준비자와 게시자가 같아요.
- 공개 명령으로 추가한 소스의 타입 검사·빌드·브라우저 동작은 확인하지 않았어요.
- 실제 Claude Code·Codex 세션에서 질문 도구가 뜨는지, 브랜드 컬러가 설치된 컴포넌트에 반영되는지, 설치부터 디자인 시스템까지 이어지는지 확인하지 않았어요.
