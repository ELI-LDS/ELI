# CLI 0.3.0 · UI 콘텐츠 0.2.0 릴리스 준비

아직 npm 게시·GitHub 콘텐츠 공개·최종 파일 전달을 진행하지 않았어요. 이 문서는 준비 상태이며 이전 PR의 성공 검사를 새 버전의 최종 후보 검사로 대신하지 않아요.

## 대상

| 대상 | 버전 | 배포 위치 |
| --- | --- | --- |
| 설치 도구 eli-design | 0.3.0 | npm, 검증된 tarball은 cli-v0.3.0에 전달 예정 |
| UI 소스 콘텐츠 | 0.2.0 | GitHub v0.2.0의 개별 JSON으로 공개 예정 |
| 하네스 콘텐츠 | 0.1.0 | 이미 공개된 harness-v0.1.0을 그대로 재사용 |

2026-11-22 조회한 npm latest·next는 모두 CLI 0.2.0이에요. 기존 @eli-design/ui의 npm 게시·삭제는 이번 대상이 아니에요. 미게시 0.2.1의 과거 후보 파일은 보존하고 이번 릴리스는 0.3.0으로 준비해요.

## 포함할 변경

- #92의 짧은 소스 진입 경로와 components/ui 기본 설치 위치, 기존 모듈 충돌 보호
- #87·#88의 Modal 닫기·포커스 관리
- #89의 TextField 입력 지우기
- 미게시 0.2.1 후보에 준비했던 일반 status 출력 수정과 사용자용 README

기존 소스·설치 기록·경로 별칭을 자동으로 바꾸지 않아요. 새 콘텐츠로 이전할 때 사용자 수정 파일과 import·CSS 선택자를 확인해요. 공개 API·이전 안내는 [CHANGELOG](../../CHANGELOG.md)에 정리했어요.

## 후보 검증 계획

- 준비 PR 병합 후 깨끗한 main SHA를 고정해요.
- 같은 SHA의 기본 검사·레지스트리·CLI·소스 소비 검사 결과를 확인해요.
- CLI tarball·UI JSON을 고정하고 같은 파일로 여섯 패키지 매니저와 대표 Next.js SSR·hydration을 확인해요.
- 하네스는 현재 작업 폴더의 미배포 문서로 만든 JSON을 배포하지 않고 공개 0.1.0의 해시와 원본 바이트를 재사용해요.
- v0.2.0 공개 후 익명 다운로드·무결성과 최종 tarball의 공개 콘텐츠 소비를 확인해요.
- 최종 tarball·SHA256SUMS·release.json을 cli-v0.3.0에 제공한 뒤 npm 담당자에게 전달해요.

최종 원본 SHA·파일명·해시·integrity·크기·검사 링크는 실제 후보 고정과 검사 후에 기록해요. 수행 전 항목을 완료로 표시하지 않아요.

## 준비 브랜치 사전 확인

고정 Node.js 24.21.0·pnpm 12.8.1에서 lockfile 동기화와 frozen 설치, 타입·린트, CLI 테스트 28개와 레지스트리 테스트 8개를 확인했어요. 최종 병합 SHA·tarball의 검사와는 구분해요.

재사용할 공개 하네스 0.1.0을 익명 다운로드하고 내부 파일 해시를 확인했어요. 원본 JSON의 SHA-256은 `f034ddf934b97f59cb7cef0575bd0ef7b22caeb6b94525eb34111740e2144efd`예요. 최종 CLI의 공개 하네스 소비 검증은 후보 고정 후에 진행해요.

## 게시 경계

준비 PR이나 CLI Release만으로 npm에 게시됐다고 표현하지 않아요. npm 담당자는 [게시 안내](../npm-publishing.md)에 따라 고정 파일을 next로 게시하고 공개 명령 검증 통과 후 latest로 전환해요.

실제 Android·iOS 기기, VoiceOver, 에이전트의 스킬 수행·훅 신뢰와 원격 MCP는 자동 브라우저·설치 검사와 별도 검증 범위예요.
