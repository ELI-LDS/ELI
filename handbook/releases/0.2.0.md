# CLI 0.2.0 · 하네스 0.1.0 릴리스 기록

CLI `eli-design@0.2.0`은 2026-11-21 19:04:59 KST에 npm에 게시됐어요. 2026-11-22 조회 기준 `latest`와 `next` 모두 `0.2.0`이며 npm integrity는 아래 고정 전달 파일과 일치해요. UI·하네스 콘텐츠도 GitHub에 공개되어 있어요. 기존 0.1.0 후보와 공개된 태그·파일은 변경하지 않았어요.

| 대상 | 버전 | 제공 방식 |
| --- | --- | --- |
| 설치 도구 | `eli-design@0.2.0` | npm `latest`·`next`, Git `cli-v0.2.0` |
| UI 콘텐츠 | `0.1.0` | 기존 `v0.1.0`·JSON을 해시 대조 후 재사용 |
| 하네스 콘텐츠 | `0.1.0` | 독립 `harness-v0.1.0`·`harness.json` |
| 기존 전체 UI 패키지 | npm latest `0.0.0` | 이번 게시 대상 아님 |

하네스의 비공개 workspace manifest는 버전 원본이에요. 새 npm 하네스 패키지를 별도로 설치하라는 의미는 아니에요. 하나의 CLI에서 UI와 하네스를 각각 선택하고 실행 의존성은 semver 하나를 유지해요.

## 변경 범위

- UI 선택·전체 추가는 유지하고 하네스를 자동 포함하지 않아요.
- 하네스는 Claude Code·Codex 또는 둘을 명시적으로 선택해 전체 스킬·훅을 복사하고 기존 JSON 설정을 보존해 병합해요.
- `eli.harness.json`에 하네스·CLI 버전·배포 주소·해시·선택 에이전트·실제 파일을 기록해요. `status`에서 수정·누락을 확인해요.
- 소스 UI의 실제 import는 `eli.lock.json`의 진입 경로로 확인하고 기존 전체 UI를 자동으로 추가하지 않아요.
- 같은 버전 재실행을 지원하며 사용자 수정·다른 버전·심볼릭 링크·손상 데이터는 실패로 반환해요. UI·하네스 업데이트와 강제 덮어쓰기는 제공하지 않아요.

## 검증과 게시 범위를 구분해요

실제 수행한 검사·크기·파일 해시와 원본 SHA는 작업 PR과 최종 전달 파일에 기록해요. 이전 0.1.0 후보나 다른 해시의 통과 결과로 새 최종 파일의 검증을 대신하지 않아요. 최종 tarball을 다시 빌드하지 않고 같은 파일을 확인하고 전달해요.

필수 자동 범위는 CLI 설치·복구·보호 검사, 훅·스킬 검사, UI 소비·SSR·hydration, 여섯 패키지 매니저 실행과 UI·하네스 선택 다운로드 측정이에요. Codex 훅 사용자 신뢰와 실제 에이전트가 스킬을 따르는지, 원격 MCP의 응답, 실제 모바일 기기·화면 낭독기는 자동 파일 설치 검사에 포함되지 않아요.

### 최종 전달 파일과 검증

Node.js 24.21.0·pnpm 12.8.1·macOS arm64에서 frozen 설치, `pnpm check`, UI·하네스 CLI 검사 23개, 훅·스킬 검사 16개, 레지스트리 계약 검사 6개를 확인했어요. 전체 검사는 main `df619d0`에서 통과했고, 이후 터미널 안내만 보완한 [#82](https://github.com/ELI-team/ELI/pull/82)는 CLI 검사·대상 린트와 [레지스트리 CI](https://github.com/ELI-team/ELI/actions/runs/44873161283), [CLI 행렬 CI](https://github.com/ELI-team/ELI/actions/runs/44873161321)가 통과했어요.

최종 tarball과 같은 SHA-256의 파일로 npm 11.19.0·pnpm 12.8.1·Yarn Classic 1.22.22·Yarn Modern 4.18.1 node-modules/strict PnP·Bun 1.4.4를 확인했어요. 저장소 밖에 설치한 그 파일의 실행 코드로 공개 UI 34개의 타입·Vite·CSS, 대표 Next.js SSR/hydration·Button/Select 상호작용과 콘솔 오류 없음을 확인했어요. 공개 하네스는 익명 다운로드·해시·기본 릴리스 탐색·React 없는 설치·설정 보존·재실행·status·소스 UI 인식·등록된 훅 명령·터미널 신뢰 안내까지 확인했어요.

| 대상 | 크기·구성 | SHA-256 |
| --- | --- | --- |
| CLI 최종 tarball | 압축 19,614 B / 압축 해제 64,109 B / 11개 파일 | `813c49f2aec5d1e302455feb59b11a65941fe30eca0499b87059f7c18a56e049` |
| 하네스 JSON | 153,615 B / 원본 파일 22개 | `f034ddf934b97f59cb7cef0575bd0ef7b22caeb6b94525eb34111740e2144efd` |
| 기존 전체 UI 참고 tarball | 압축 116,808 B / 압축 해제 450,863 B / 311개 파일 | 이번 npm 게시 대상 아님 |

UI 콘텐츠의 원본과 실행 의존성은 바꾸지 않았어요. CLI 실행 의존성은 semver 7.8.6 하나예요. 하네스의 스킬·훅 원본은 CLI tarball에 넣지 않고 선택한 경우에만 받아요.

로컬 HTTP 레지스트리에서 실제 npm exec로 측정한 gzip 응답 본문 합계는 아래와 같아요. 도구·실행 의존성·npm 메타데이터·선택한 JSON을 포함하고 HTTP 헤더·TLS·공개 CDN·이미 설치된 React는 제외해요. UI는 React가 설치된 앱, 하네스 단독은 React 없는 앱이에요.

| 요청 | 빈 npm 캐시의 초기 설정·추가 | 기존 앱에서 추가 재실행 |
| --- | ---: | ---: |
| Button | 113,174 B | 12,714 B |
| 전체 UI | 207,762 B | 107,302 B |
| 하네스만 (두 에이전트) | 143,541 B | 47,476 B |
| Button·하네스 | 160,650 B | 60,190 B |

UI만 요청하면 하네스 전송량은 0이고, 하네스만 요청하면 UI 전송량은 0임을 확인했어요. 하네스 JSON 자체의 gzip 본문은 47,476 B였고 두 에이전트를 골라도 한 번 받아요. 재실행은 새 파일을 만들지 않지만 UI·하네스 JSON을 다시 받아요. 자세한 identity/gzip 조건과 요청 로그는 `.artifacts/cli-download-size/report.json`에 남겼어요.

## npm 게시와 전달 파일

[CLI 전달 Release](https://github.com/ELI-team/ELI/releases/tag/cli-v0.2.0)에 `eli-design-0.2.0.tgz`, `SHA256SUMS`, `release.json`을 공개했어요. 로컬 파일은 `.artifacts/releases/0.2.0/`에 고정했어요. 이 파일과 실제 npm 게시 파일의 integrity가 일치함을 확인했어요. 다음 릴리스는 [npm 담당자 안내](../npm-publishing.md)에 따라 새 버전·파일을 고정해요. 기존 `@eli-design/ui` 게시 명령을 재사용하지 않아요.

| 대상 | 고정 원본 SHA | GitHub Release |
| --- | --- | --- |
| CLI 0.2.0 | `7fb378d685a1044c5b2c43c5f9433cfac19a8d66` | [cli-v0.2.0](https://github.com/ELI-team/ELI/releases/tag/cli-v0.2.0) |
| UI 0.1.0 | `2aff8e85e00f1709135b0b0c4afe4f5f04c4395f` | [v0.1.0](https://github.com/ELI-team/ELI/releases/tag/v0.1.0) 재사용 |
| 하네스 0.1.0 | `df619d03c6c2014008de2f07a063f716310deeac` | [harness-v0.1.0](https://github.com/ELI-team/ELI/releases/tag/harness-v0.1.0) |

UI 목록 SHA-256은 `18b1c022824b54da729553427f31215515791d89b290555bd6659d17ab5276b3`이에요. CLI tarball의 npm integrity는 `sha512-l5TM1tCLkrzc4vkcZArMPcrO5rVIPfXGt3MytsAvw2Ldp3ZwiaNtuD3xot1+ez6qZQi/Szpf5NIK0clRjiKwRQ==`예요. 이 기록을 추가한 후속 문서 커밋으로 배포 태그를 이동하지 않아요.

준비 시점의 npm 조회는 E404였고 이후 위 게시·태그·integrity를 확인했어요. 이번 문서 동기화에서는 실제 npm 실행 명령·패키지 매니저 행렬을 다시 실행하지 않았으며, 앞의 로컬 후보·공개 콘텐츠 검사와 구분해요. 저장소의 기존 Storybook·Vite 등 개발 도구 보안 알림은 별도 정리가 필요하며, 새 CLI의 실행 의존성 semver 7.8.6은 해당 알림 목록에 없었어요.

하네스 원격 MCP는 별도 담당 범위예요. 스킬 설치 완료를 문서 서버·전체 셋업 흐름 완료로 표현하지 않아요.

## 게시 후 확인한 제한과 다음 문서 변경

하네스만 설치한 프로젝트에서 CLI 0.2.0의 일반 `status` 출력이 실패하는 문제는 [PR #84](https://github.com/ELI-team/ELI/pull/84)에서 별도로 수정 중이에요. 현재 버전에서는 `status --json`을 사용해요. 해당 PR의 CLI 코드·회귀 테스트는 이번 문서 동기화에 포함하지 않았어요.

사용자용 README 정리와 하네스 문서의 독립 버전 안내 보완은 미배포 변경이에요. CLI·하네스 각각 다음 패치 릴리스 대상으로 검토하고, 이 기록을 고쳤다고 공개된 CLI tarball·하네스 JSON을 덮어쓰지 않아요. 실제 에이전트 신뢰·스킬 수행·원격 MCP는 여전히 별도 확인 대상이에요.
