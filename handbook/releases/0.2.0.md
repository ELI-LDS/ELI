# CLI 0.2.0 · 하네스 0.1.0 준비 기록

하네스를 함께 선택 설치하기 위한 후보예요. **이 문서만으로 npm 게시·새 Git 태그·하네스 콘텐츠 업로드가 완료된 것은 아니에요.** 기존 UI 전용 CLI 0.1.0 전달 파일은 그대로 남기고 새 후보를 검증해요.

| 대상 | 버전 | 제공 방식 |
| --- | --- | --- |
| 설치 도구 | `eli-design@0.2.0` | 새 최종 tarball, `cli-v0.2.0` |
| UI 콘텐츠 | `0.1.0` | 기존 `v0.1.0`·JSON을 해시 대조 후 재사용 |
| 하네스 콘텐츠 | `0.1.0` | 독립 `harness-v0.1.0`·`harness.json` |
| 기존 전체 UI 패키지 | npm latest `0.0.0` | 이번 게시 대상 아님 |

하네스의 비공개 workspace manifest는 버전 원본이에요. 새 npm 하네스 패키지를 별도로 설치하라는 의미는 아니에요. 하나의 CLI에서 UI와 하네스를 각각 선택하고 실행 의존성은 semver 하나를 유지해요.

## 변경 범위

- UI 선택·전체 추가는 유지하고 하네스를 자동 포함하지 않아요.
- 하네스는 Claude Code·Codex 또는 둘을 명시적으로 선택해 전체 스킬·훅을 복사하고 기존 JSON 설정을 보존해 병합해요.
- `eli.harness.json`에 하네스·CLI 버전·배포 주소·해시·선택 에이전트·실제 파일을 기록해요. `status`에서 수정·누락을 확인해요.
- 소스 UI의 실제 import는 `eli.lock.json`의 진입 경로로 확인하고 기존 전체 UI를 자동으로 추가하지 않아요.
- 같은 버전 재실행을 지원하며 사용자 수정·다른 버전·심볼릭 링크·손상 데이터는 실패로 반환해요. UI·하네스 업데이트와 강제 덮어쓰기는 제공하지 않아요.

## 검증과 게시 범위를 구분해요

실제 수행한 검사·크기·파일 해시와 원본 SHA는 작업 PR과 최종 전달 파일에 기록해요. 이전 0.1.0 후보나 다른 해시의 통과 결과로 새 최종 파일의 검증을 대신하지 않아요. 최종 tarball을 다시 빌드하지 않고 같은 파일을 확인하고 전달해요.

필수 자동 범위는 CLI 설치·복구·보호 검사, 훅·스킬 검사, UI 소비·SSR·hydration, 여섯 패키지 매니저 실행과 UI·하네스 선택 다운로드 측정이에요. Codex 훅 사용자 신뢰와 실제 에이전트가 스킬을 따르는지, 원격 MCP의 응답, 실제 모바일 기기·화면 낭독기는 자동 파일 설치 검사에 포함되지 않아요.

### 작업 브랜치에서 확인한 후보

Node.js 24.21.0·pnpm 12.8.1·macOS arm64에서 frozen 설치, `pnpm check`, UI·하네스 CLI 검사 23개, 훅·스킬 검사 16개, CLI 소스의 타입·Vite·CSS·Next.js SSR/hydration을 확인했어요. 같은 해시의 tarball로 npm 11.19.0·pnpm 12.8.1·Yarn Classic 1.22.22·Yarn Modern 4.18.1 node-modules/strict PnP·Bun 1.4.4를 확인했어요. 원격 CI와 병합 후 최종 SHA의 결과는 별도로 기록해요.

| 대상 | 크기·구성 | SHA-256 |
| --- | --- | --- |
| CLI 준비 tarball | 압축 19,585 B / 압축 해제 63,977 B / 11개 파일 | `1a8f7a534b471cd46e78ccc2abb65d4e2867904e7b69d5bd5e3b8f219bfb25ee` |
| 하네스 JSON | 153,615 B / 원본 파일 22개 | `f034ddf934b97f59cb7cef0575bd0ef7b22caeb6b94525eb34111740e2144efd` |
| 기존 전체 UI 참고 tarball | 압축 116,808 B / 압축 해제 450,863 B / 311개 파일 | 이번 npm 게시 대상 아님 |

UI 콘텐츠의 원본과 실행 의존성은 바꾸지 않았어요. CLI 실행 의존성은 semver 7.8.6 하나예요. 하네스의 스킬·훅 원본은 CLI tarball에 넣지 않고 선택한 경우에만 받아요.

로컬 HTTP 레지스트리에서 실제 npm exec로 측정한 gzip 응답 본문 합계는 아래와 같아요. 도구·실행 의존성·npm 메타데이터·선택한 JSON을 포함하고 HTTP 헤더·TLS·공개 CDN·이미 설치된 React는 제외해요. UI는 React가 설치된 앱, 하네스 단독은 React 없는 앱이에요.

| 요청 | 빈 npm 캐시의 초기 설정·추가 | 기존 앱에서 추가 재실행 |
| --- | ---: | ---: |
| Button | 113,155 B | 12,714 B |
| 전체 UI | 207,743 B | 107,302 B |
| 하네스만 (두 에이전트) | 143,522 B | 47,476 B |
| Button·하네스 | 160,631 B | 60,190 B |

UI만 요청하면 하네스 전송량은 0이고, 하네스만 요청하면 UI 전송량은 0임을 확인했어요. 하네스 JSON 자체의 gzip 본문은 47,476 B였고 두 에이전트를 골라도 한 번 받아요. 재실행은 새 파일을 만들지 않지만 UI·하네스 JSON을 다시 받아요. 자세한 identity/gzip 조건과 요청 로그는 `.artifacts/cli-download-size/report.json`에 남겼어요.

## npm 담당자에게 전달해요

[릴리스 절차](../releasing.md)에 따라 병합 후 main SHA와 tarball·UI/하네스 스냅샷을 고정해요. 필요한 GitHub 콘텐츠와 게시용 파일·체크섬·기록을 준비한 뒤 [npm 담당자 안내](../npm-publishing.md)를 전달해요. 담당자는 새 `eli-design` 파일을 `next`로 게시하고 공개 검증 통과 후 `latest`로 전환해요. 기존 `@eli-design/ui` 게시 명령을 재사용하지 않아요.

하네스 원격 MCP는 별도 담당 범위예요. 스킬 설치 완료를 문서 서버·전체 셋업 흐름 완료로 표현하지 않아요.
