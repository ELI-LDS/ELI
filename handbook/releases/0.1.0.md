# 0.1.0 릴리스 준비 기록

**npm 게시 전 준비 기록이에요. Git 태그·GitHub 업로드와 실제 일반 사용자 다운로드 가능 여부를 구분해요.** 실행 순서는 [릴리스 절차](../releasing.md), 버전·태그의 기준은 [버전 규칙](../../Agent/versioning.md)을 따라요.

**후속 결정:** 하네스 선택 설치를 포함한 [CLI 0.2.0 후보](0.2.0.md)를 준비해요. 아래 UI 전용 CLI 0.1.0 파일은 기존 준비 기록으로 남기며 이번 새 배포 파일로 사용하지 않아요. 저장소 공개 전환 후 기존 UI JSON의 익명 다운로드·타입·CSS·Next.js SSR/hydration은 확인했어요. 아래의 비공개·404 내용은 당시 확인 기록이에요.

## 배포 대상

| 대상 | 후보 버전 | 태그 | 상태 |
| --- | --- | --- | --- |
| npm 설치 도구 `eli-design` | `0.1.0` | npm `next` → 검증 후 `latest`, Git `cli-v0.1.0` | 게시용 파일 전달 완료, npm 미게시 |
| UI 소스 콘텐츠 | `0.1.0`, JSON 규격 v1 | GitHub Release `v0.1.0` | 비공개 저장소에 업로드 완료, 일반 사용자 다운로드 불가 |
| 기존 npm `@eli-design/ui` | 현재 게시 `0.0.0` | npm `latest=0.0.0` | 이번 게시 대상에 포함하지 않아요 |

콘텐츠 버전의 현재 원본은 `packages/ui/package.json`이에요. 이 manifest를 `0.1.0`으로 올리는 것은 소스 콘텐츠 준비이며 기존 npm UI의 배포 태그를 변경한 것이 아니에요. 도구와 콘텐츠의 첫 후보 번호가 같지만 이후 버전을 같이 올려야 한다는 규칙은 아니에요. 공식 홍보 시작을 뜻하는 `1.0.0` 전환도 아니에요.

## 확인한 기존 게시 상태

2026-11-20에 조회했어요. 실제 게시 직전에 다시 확인해요.

- `npm view eli-design versions dist-tags --json`: 공개 npm에서 E404. 이름 사용과 게시 권한은 게시 단계에서 별도로 확인해요.
- `npm view @eli-design/ui versions dist-tags --json`: `0.0.0-stage`, `0.0.0`; `latest=0.0.0`, `next` 없음.
- `gh release list`: 기존 GitHub Release 없음.
- 게시한 `0.0.0`을 소스 Release로 뒤늦게 덮어쓰거나 최신 main을 당시 원본으로 간주하지 않아요.

## 준비 기준과 검증

기능 PR [#78](https://github.com/ELI-LDS/ELI/pull/78)은 `953e1ff66f596bb6bd6ea579e7bdee1002b80341`로 병합됐어요. 다음은 기능 PR 원본 SHA의 검증이며 **릴리스 준비 PR 병합 후 최종 후보의 검증을 대신하지 않아요.**

준비 브랜치의 버전 변경 후 수행한 검사는 릴리스 준비 PR에 기록해요. 실제 Safari·iOS·Android 기기·화면 낭독기 수동 확인은 이 자동 행렬에 포함되지 않아요.

### 준비 브랜치에서 확인했어요

2026-11-20, macOS arm64의 Node.js `24.21.0`·pnpm `12.8.1`에서 확인했어요. 콘텐츠 버전은 `0.1.0`이고 UI 구현 코드는 기능 PR과 같아요.

- lockfile 동기화 후 `pnpm install --frozen-lockfile` 통과. 버전 참조가 없어 lockfile 변경은 없어요.
- `pnpm check`: 타입·린트·Storybook·Chromium 소비·Next.js·UI 패키징과 용량 검사 통과.
- `pnpm test:registry`: 6개 검사와 34개 컴포넌트 소스의 타입·Vite·CSS, 대표 Next.js SSR·hydration 통과.
- `pnpm test:cli`: 13개 검사 통과. 공개 컴포넌트 34개 각각의 신규 프로젝트 설치도 포함해요.
- `pnpm test:cli:consumer`: CLI로 추가한 소스의 타입·Vite·CSS·Next.js SSR·hydration 통과.
- 같은 준비 tarball·콘텐츠 스냅샷으로 npm `11.19.0`·pnpm `12.8.1`·Yarn Classic `1.22.22`·Yarn Modern `4.18.1`의 node-modules/strict PnP·Bun `1.4.4` 실행 통과. `node tests/cli/package-managers.mjs --prepare` 후 `--all`을 실행했고 소스 타입·Vite·CSS·일반 SSR과 앱 설정·lockfile 보존을 확인했어요.
- 변경 문서 6개의 로컬 링크·앵커 44개와 `git diff --check` 확인.

첫 준비 커밋 `86ff9a8`에서 측정한 후보는 `eli-design-0.1.0-90cf5c7d4512.tgz`예요. 압축 `15,380 B`, 압축 해제 `46,174 B`, 9개 파일이며 실행 의존성은 `semver@7.8.6` 하나예요. 이후 게시용 README를 갱신했으므로 이 파일을 최종 게시 파일로 사용하지 않아요. 최종 파일은 병합 후 별도로 고정해요. 기존 전체 UI tarball은 압축 `113,090 B`, 압축 해제 `439,271 B`, 310개 파일로 별도 측정했어요. UI tarball은 이번 게시 대상이 아니에요.

```text
CLI SHA-256: 90cf5c7d45122bb9c15edd8be59915fb653ac63ebb82a5257c56ba0c693e74e5
CLI integrity: sha512-6BPMDzcm53qBwIPPY9RrQVO0SVARIL84d88ucEKJ7yuG24jG/KqjkzPMJeQuMs0ODMpXVTsmindvPe13+bTvog==
registry.json SHA-256: 18b1c022824b54da729553427f31215515791d89b290555bd6659d17ab5276b3
```

콘텐츠는 공개 항목 34개·공유 항목 16개, 목록을 포함해 JSON 51개예요. 최종 게시 후보는 준비 PR 병합 후 고정 SHA에서 다시 확정하며 위 파일을 이미 게시했다고 기록하지 않아요.

같은 CLI의 설치 흐름을 로컬 HTTP 레지스트리에서 측정했어요. React는 이미 설치되어 있고 아래 gzip 값은 도구·실행 의존성·npm 메타데이터·UI JSON의 **응답 본문 합계**예요. 공개 CDN·HTTP 헤더·TLS와 React 다운로드는 포함하지 않아요.

| 요청 | 빈 npm 캐시의 초기 설정·추가 | 기존 앱에서 추가 재실행 | 설치된 소스 |
| --- | ---: | ---: | ---: |
| Button | 108,947 B | 12,714 B | 22,934 B / 11개 파일 |
| Modal | 112,930 B | 16,697 B | 29,503 B / 17개 파일 |
| Button → Modal → Select | 141,868 B | 45,635 B | 51,636 B / 27개 파일 |
| 전체 34개 | 203,535 B | 107,302 B | 231,183 B / 138개 파일 |

재실행은 소스를 추가하지 않지만 현재 CLI는 UI JSON을 다시 받아요. 위 수치는 첫 준비 커밋의 후보를 대상으로 했어요. 최종 tarball 자체의 Next.js 확인과 공개 서버 소비는 아래 게시 단계에서 별도로 수행해요.

## npm 담당자에게 전달해요

릴리스 준비자가 GitHub 콘텐츠·최종 tarball·해시와 검증 결과를 제공해요. npm 담당자는 [게시 안내](../npm-publishing.md)에 따라 최종 파일을 `next`로 게시하고, 준비자의 공개 검증 통과 후 `latest`로 전환해요. UI 빌드·GitHub 업로드·소비 검사를 담당자에게 다시 요구하지 않아요. 최종 파일과 source SHA는 `cli-v0.1.0` Release의 `release.json`에 기록해요. 기존 `@eli-design/ui`와 하네스 경로는 이번에 삭제하지 않아요.

## 게시 전 남은 항목

### main에서 고정한 최종 파일

PR [#79](https://github.com/ELI-LDS/ELI/pull/79)는 `2aff8e85e00f1709135b0b0c4afe4f5f04c4395f`로 병합됐어요. 이 깨끗한 main에서 frozen 설치·`pnpm check`·13개 CLI 검사를 다시 실행해 통과했어요. PR의 모든 필수 CI도 통과했고, 병합 전후의 파일 트리가 같음을 확인했어요.

| 항목 | 값 |
| --- | --- |
| npm 전달 파일 | `eli-design-0.1.0.tgz` |
| 압축 / 압축 해제 / 파일 수 | 15,536 B / 46,734 B / 9개 |
| SHA-256 | `8c9eb8b732778f9a2067631df1004eea733225cf278c9dfc1d20f27a176e14bc` |
| npm integrity | `sha512-og2pG8M+fDi5kE/GsRPxn9cXt2CqjVc1DctfUgj5NvnuexWYVsCrmxQJJdmwe10iQBnIvVnkWFEP/sEmFnMzsA==` |
| 콘텐츠 목록 SHA-256 | `18b1c022824b54da729553427f31215515791d89b290555bd6659d17ab5276b3` |

최종 파일과 SHA-256이 같은 tarball의 여섯 패키지 매니저 검사가 통과했어요. 고정한 최종 파일 자체를 저장소 밖에 설치한 bin으로 전체 소스의 타입·Vite·CSS와 대표 Next.js SSR·hydration도 확인했어요. CLI와 토큰·UI 원본은 이 후속 문서 작업에서 변경하지 않아요.

콘텐츠 태그 `v0.1.0`과 JSON 51개를 같은 원본으로 업로드했어요. 익명 CLI 확인에서는 Release 목록과 파일 URL이 404를 반환했고 저장소가 비공개임을 확인했어요. 저장소 담당자가 직접 공개로 전환하기로 했으므로 공개 범위는 변경하지 않았어요. **공개 전환 후 실제 다운로드 검사가 통과할 때까지 npm 게시를 대기해요.**

[CLI 게시용 파일](https://github.com/ELI-LDS/ELI/releases/tag/cli-v0.1.0)에 tarball·`SHA256SUMS`·`release.json`을 올렸어요. 전달 기록에는 공개 검증 대기 상태를 명시했고 npm에 게시하지 않았어요. [UI 콘텐츠 파일](https://github.com/ELI-LDS/ELI/releases/tag/v0.1.0)과 함께 저장소 공개 전까지 협업자만 접근할 수 있어요. 두 Git 태그는 위의 고정 원본 SHA를 가리켜요.

하네스 지침의 [새 설치 방식 연결 기준](../../Agent/harness.md#새-설치-도구와-연결하는-완료-기준)은 담당자에게 전달하는 규칙이에요. 스킬·훅을 이번에 구현·수정하거나 새 CLI에 포함하지 않았어요.
