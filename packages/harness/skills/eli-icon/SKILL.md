# 커스텀 아이콘 만들기

사용자에게 크게 보이는 아이콘을 SVG 코드로 만들어요. 스타일은 프로젝트 루트의 `ICON.md`에 한 번 정하고, 모든 아이콘이 그 문서를 따라요. 그래서 언제 만들어도 같은 톤이 나와요.

## 1. 커스텀 아이콘이 맞는지 판단해요

커스텀 아이콘은 아껴 써요. 기본은 ELI가 제공하는 선 아이콘이에요. 커스텀 아이콘이 많아지면 화면이 시끄러워지고, 정말 강조할 곳이 묻히고, 관리할 그림이 늘어요.

아이콘이 들어갈 자리를 아래 표의 위에서부터 확인해요. 처음 해당하는 줄에서 멈추고 그 결정을 따라요. 모든 자리는 한 줄에만 해당해요.

| 순서 | 이 자리가 | 결정 | 예 |
| --- | --- | --- | --- |
| 1 | 뜻을 전달하지 않고 빈 곳을 채우기만 해요 | 아이콘을 넣지 않아요 | 허전해 보여서 넣는 그림 |
| 2 | 누르거나 조작하는 요소 안에 있어요 | 선 아이콘 | 버튼, 탭, 메뉴, 입력창, 내비게이션 |
| 3 | 글자 옆에서 그 글자를 돕고 있어요 | 선 아이콘 | 라벨 앞 아이콘, 오류·성공 문구, 설정 항목 |
| 4 | 같은 화면에서 여러 번 반복돼요 | 선 아이콘 | 목록 항목, 카드 그리드, 카테고리 |
| 5 | 작게 보여요 | 선 아이콘 | 배지, 툴팁, 표의 칸 |
| 6 | 사용자가 일하려고 자주 들르는 화면에 있어요 | 선 아이콘 | 폼, 목록, 설정, 대시보드 |
| 7 | 그 화면이 전하려는 단 하나의 메시지를 대표해요 | 커스텀 아이콘 | 빈 화면, 온보딩, 완료·결과 화면, 오류 페이지, 기능 소개 |
| 8 | 위의 어느 것도 아니에요 | 선 아이콘 | |

- 5번의 "작게"는 `icon` 가이드에 기준이 있으면 그 기준을 따라요. 없으면 한 변이 48px보다 작은 경우로 봐요.
- 7번은 1~6번을 모두 지난 자리에만 해당해요. 크고, 한 번만 나오고, 조작하는 요소가 아니고, 사용자가 잠시 멈춰서 보는 자리예요.
- 판단하기 어려우면 선 아이콘으로 정해요.

커스텀 아이콘으로 정했어도 아래를 지켜요.

- 한 화면에 커스텀 아이콘은 하나만 둬요. 이미 있으면 새로 만들지 않아요.
- ELI의 선 아이콘을 크게 써도 뜻이 전달되면 그 아이콘을 써요. `eli-docs`의 `search`로 먼저 찾아요.
- `ICON.md`의 "만든 아이콘"에 같은 뜻의 아이콘이 있으면 그 아이콘을 다시 써요.
- 다른 작업을 하다가 먼저 나서서 커스텀 아이콘을 만들지 않아요. 사용자가 요청했을 때만 만들어요.

선 아이콘이나 넣지 않는 것으로 정했으면 만들지 않아요. 표의 어느 줄에 해당하는지 사용자에게 말하고, 쓸 수 있는 ELI 아이콘을 찾아 제안해요. 사용자가 이유를 듣고도 원하면 만들어요.

사진, 복잡한 일러스트, 로고는 이 명령의 범위가 아니에요. 사용자에게 그렇게 말해요.

## 2. ICON.md를 준비해요

`ICON.md`가 있으면 읽고 3번으로 넘어가요. 없으면 아이콘을 만들기 전에 먼저 만들어요.

1. 스타일의 근거를 모아요.
   - `get_guide`로 `icon` 가이드를 읽어요. ELI의 기본 규칙이 여기에 있어요.
   - `DESIGN.md`가 있으면 톤과 지향하는 제품을 읽어요.
   - 프로젝트에 이미 있는 커스텀 아이콘을 찾아 스타일과 파일 위치를 확인해요.
   - 색은 프로젝트의 토큰 파일에서 골라요. 토큰 파일이 없으면 `/eli-design-system`으로 먼저 만들자고 안내해요.
2. 근거로 정할 수 없는 항목만 사용자에게 물어요. 지어내지 않아요.
3. 이 스킬 폴더의 `template.md`를 바탕으로 `ICON.md`를 써요. 처음부터 새로 쓰지 않아요. 초안을 보여주고, 사용자가 확인한 뒤 프로젝트 루트에 저장해요.

- `{중괄호}`는 사용자의 답, 기존 코드, 다른 문서에서 확인한 내용으로 채워요.
- `<!-- 맞춤: ... -->` 주석의 지시대로 고치고, 주석은 모두 지워요.
- 예시는 이 서비스에 실제로 나올 내용으로 바꿔요. 템플릿의 예시를 그대로 두지 않아요.
- 서비스에 해당하지 않는 항목은 지워요. 서비스에만 필요한 항목은 더해요.
- 답을 받지 못해 채울 수 없는 항목은 지어내지 않고 "정하지 않은 것"으로 옮겨요.
- 저장한 파일에 `{`, `}`, "맞춤" 주석이 남아 있지 않은지 검색해 확인해요.

이 문서에서 지켜요.

- 형태의 값은 이 순서로 정해요: 원격 `icon` 가이드의 값, 프로젝트에 이미 있는 커스텀 아이콘에서 읽은 값, 템플릿의 기본값. 기본값을 썼으면 예시 아이콘을 보여주고 확인받아요.
- 기존 아이콘끼리 스타일이 다르면 어느 쪽을 기준으로 할지 물어요.
- 형태와 색은 "선 굵기 4", "모서리 반경 8"처럼 숫자와 토큰 이름으로 적어요. "부드럽게" 같은 표현만으로는 다음 아이콘이 같은 톤으로 나오지 않아요.
- 색의 토큰 이름은 프로젝트 토큰 파일의 실제 이름으로 적어요.

## 3. 무엇을 만들지 확인해요

- 사용자에게 확인해요: 무엇을 나타내는 아이콘인가요? 어느 화면에 어떤 크기로 들어가나요?
- 비슷한 대상을 그린 기존 아이콘의 SVG를 읽어요. 같은 대상은 같은 모양으로 그려요.

## 4. SVG를 써요

- `ICON.md`의 형태와 색을 그대로 따라요. 이번 아이콘만 다른 값을 쓰지 않아요.
- `viewBox`를 쓰고 고정 `width`·`height`를 넣지 않아요. 크기는 쓰는 쪽에서 정해요.
- 색은 `currentColor`나 프로젝트 토큰의 CSS 변수로 써요. 색상 값과 `--eli-` 변수를 직접 쓰지 않아요.
- 도형은 단순하게 유지해요. 작은 크기에서도 무엇인지 알아볼 수 있어야 해요.
- 래스터 이미지, 외부 파일 참조, 글꼴에 의존하는 글자, 스크립트를 넣지 않아요.
- 장식이면 `aria-hidden="true"`를 넣어요. 뜻을 전달하면 `role="img"`와 이름을 넣어요.

## 5. 프로젝트에 넣어요

- `ICON.md`의 "파일"에 적힌 폴더, 형식, 이름 규칙을 따라요.
- 기존 파일을 확인 없이 덮어쓰지 않아요.
- 요청받은 화면에 연결하는 것까지 해요. 다른 화면은 바꾸지 않아요.
- `ICON.md`의 "만든 아이콘"에 새 아이콘을 추가해요.

## 6. 눈으로 확인해요

- 브라우저 도구가 있으면 실제 화면에서 쓰이는 크기로 렌더링해 확인해요. 밝은 배경과 어두운 배경을 모두 봐요.
- 확인할 도구가 없으면 확인하지 못했다고 말하고, 사용자가 볼 수 있는 위치를 알려줘요.
- 브라우저 도구가 있으면 기존 아이콘과 나란히 놓고 톤이 같은지 봐요.
- 결과를 보여주고 고칠 점을 물어요.

## 스타일을 바꿀 때

사용자가 선 굵기나 색 같은 스타일 자체를 바꾸자고 하면 그 아이콘만 고치지 않아요. `ICON.md`를 먼저 고치고, 이미 만든 아이콘도 새 스타일로 다시 그릴지 물어요. 아이콘 하나만 다르게 두면 톤이 어긋나요.
