# DESIGN.md 만들기

`DESIGN.md`는 이 서비스가 무엇이고 어떤 디자인을 지향하는지 적은 문서예요. `/eli-design-system`, `/eli-verify`, `/eli-icon`이 이 문서를 읽고 판단해요.

## 1. 먼저 확인해요

- `DESIGN.md`가 이미 있으면 읽고, 새로 쓸지 부족한 부분만 채울지 사용자에게 물어요. 확인 없이 덮어쓰지 않아요.
- README, 라우트 구조, 기획 문서에서 이미 알 수 있는 내용은 묻지 않아요. 알아낸 내용을 보여주고 맞는지만 확인해요.
- `eli-docs`가 연결되어 있으면 `get_guide`로 `design-md` 가이드를 읽어 질문 목록과 템플릿을 가져와요. 연결되지 않았으면 아래 질문으로 진행해요.

## 2. 질문해요

한 번에 네 개 이하로 물어요. 질문 도구가 있으면 선택지를 함께 줘요. 사용자가 모른다고 답하면 넘어가요.

| 주제 | 물어볼 것 |
| --- | --- |
| 서비스 기획 | 어떤 문제를 누구에게 풀어주는 서비스인가요? 핵심 기능 세 가지는 무엇인가요? |
| 사용자 예시 | 대표 사용자 한두 명은 어떤 사람인가요? 언제, 어디서, 어떤 기기로 쓰나요? |
| 핵심 흐름 | 사용자가 가장 자주 하는 일은 무엇인가요? 그 일을 어떤 화면 순서로 하나요? |
| 지향하는 제품 | 당근, 토스처럼 닮고 싶은 제품이 있나요? 그 제품의 어떤 점을 닮고 싶나요? 닮고 싶지 않은 제품도 있나요? |
| 톤과 분위기 | 친근함과 신뢰감, 가벼움과 차분함 중 어느 쪽인가요? |
| 제약 | 모바일 웹과 데스크톱 중 무엇이 우선인가요? 프레임워크, 다크 모드, 접근성 요구가 정해져 있나요? |

지향하는 제품은 이름만 받지 않아요. "토스의 어떤 점"인지 구체적으로 물어요. 예: 한 화면에 한 가지 일, 큰 글씨, 여백.

## 3. 문서를 써요

프로젝트 루트에 `DESIGN.md`를 아래 구성으로 써요.

```markdown
# 디자인 방향

## 서비스
## 사용자
## 핵심 흐름
## 지향하는 제품
## 톤과 분위기
## 제약
## 단위
## 토큰
## 정하지 않은 것
```

- 사용자가 답한 내용만 써요. 답하지 않은 항목을 지어내지 않고 "정하지 않은 것"에 적어요.
- 지향하는 제품은 "제품 이름, 닮고 싶은 점, 우리 서비스에 적용하는 방법" 순서로 적어요.
- 색상 값, 간격 값 같은 구체적인 디자인 값은 적지 않아요. 값은 토큰 파일이 가져요.
- `## 토큰`은 `/eli-design-system`이 토큰 파일의 경로와 이름 규칙을 적는 자리예요. 이미 내용이 있으면 지우지 않아요.
- 말투와 용어 같은 문구 규칙은 적지 않아요. `/eli-ux-writing`이 `UX-WRITING.md`에 따로 정해요.
- 짧게 써요. 다른 명령이 매번 읽는 문서예요.

## 4. 단위 기준을 반드시 적어요

`## 단위`는 빼지 않아요. 사용자에게 묻지 않아도 항상 적어요. 화면 코드를 쓰는 모든 작업이 이 표를 보고 단위를 골라요.

아래 표를 기본으로 적어요. 기존 코드가 이미 다른 기준을 일관되게 쓰고 있으면 그 기준을 보여주고 어느 쪽으로 할지 물어요.

| 용도 | 쓰는 단위 | 이유 |
| --- | --- | --- |
| 글자 크기 | 토큰. 토큰 파일에 새로 정할 때는 `rem` | 사용자가 브라우저 글자 크기를 바꾸면 함께 커져요 |
| 줄 높이 | 단위 없는 숫자 (예: `1.5`) | 글자 크기에 비례해요 |
| 글자 간격 | `em` | 글자 크기에 비례해요 |
| 안쪽 여백, 요소 사이 간격, 모서리 반경 | 토큰. 토큰 파일에 새로 정할 때는 `rem` | 글자와 함께 커져서 비율이 유지돼요 |
| 요소의 너비 | `%`, `fr`, `flex`, `grid` | 부모의 크기에 맞춰 늘고 줄어요 |
| 콘텐츠의 최대 너비 | `rem`과 `max-width` | 넓은 화면에서 줄이 너무 길어지지 않아요 |
| 화면 전체 너비 | `100%`. 부모와 상관없이 화면에 맞춰야 할 때만 `vw` | `100vw`는 스크롤바 너비만큼 가로로 넘칠 수 있어요 |
| 화면 전체 높이 | `dvh` | 모바일 브라우저의 주소창이 접히고 펴져도 맞아요 |
| 화면 크기에 따라 변하는 값 | `clamp()`, `minmax()` | 최솟값과 최댓값 사이에서만 변해요 |
| 테두리 두께, 구분선 | `px` | 어느 화면에서나 같은 두께여야 해요 |
| 그림자 | `px` | 정밀하게 고정된 값이에요 |
| 아이콘 크기 | 글자와 함께 커져야 하면 `rem`, 고정이면 `px` | 쓰이는 자리에 따라 달라요 |
| 반응형 기준점 | 토큰의 값 | 프로젝트 전체에서 같은 기준점을 써요 |

표 아래에 다음을 함께 적어요.

- 글자 크기, 간격, 모서리는 값을 직접 쓰지 않고 토큰으로 써요. 이 표의 단위는 토큰 파일에 새 토큰을 정할 때와 토큰이 다루지 않는 레이아웃 크기에 적용해요.
- 글자 크기에 `px`를 쓰지 않아요. 사용자가 정한 글자 크기를 무시하게 돼요.
- 요소의 너비와 높이를 `px`로 고정하지 않아요. 좁은 화면에서 넘쳐요. 꼭 고정해야 하면 `max-width`와 함께 써요.
- 표에 없는 용도가 생기면 추측하지 않고 표에 먼저 추가해요.

## 5. 마무리해요
