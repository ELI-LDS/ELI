## 디자인 원칙

<!-- 맞춤: 아래는 기본 원칙이에요. 서비스의 방향과 어긋나는 원칙은 빼거나 고치고, 서비스만의 원칙이 있으면 더해요. 다섯 개를 넘기지 않아요. -->

판단이 갈릴 때 위에 있는 원칙을 먼저 따라요.

1. **한 화면에는 가장 중요한 일이 하나예요.** 주요 버튼은 화면에 하나만 두고, 나머지는 덜 눈에 띄게 해요.
2. **만들기 전에 있는 것을 써요.** ELI에 맞는 컴포넌트가 있으면 직접 만들지 않아요.
3. **꾸미기보다 덜어내요.** 뜻을 전달하지 않는 선, 색, 그림자, 아이콘은 넣지 않아요.
4. **다음에 할 일을 항상 알려줘요.** 빈 화면, 오류, 완료 화면에도 사용자가 할 수 있는 일을 하나 둬요.
5. **같은 것은 같게 보여요.** 같은 역할의 요소는 어느 화면에서나 같은 모양, 같은 위치, 같은 문구예요.

## 화면 구성

<!-- 맞춤: 우선 기기와 탐색 방식을 사용자의 답과 기존 코드에 맞게 고쳐요. -->

- **우선 기기:** {모바일 웹 우선 / 데스크톱 우선}. 좁은 화면을 먼저 만들고 넓은 화면으로 넓혀요.
- **탐색:** {예: 하단 내비게이션으로 주요 화면 네 개를 오가요}
- **위계:** 한 화면에서 제목, 본문, 보조 설명 세 단계만 써요. 크기와 굵기로 구분하고 색으로 구분하지 않아요.
- **여백:** 관련 있는 요소는 가깝게, 관련 없는 요소는 멀게 둬요. 구분선보다 여백으로 나눠요.
- **주요 버튼:** {예: 내용 끝이나 화면 아래에 일반 버튼으로 둬요. 떠 있는 버튼은 목록 화면에서 새 항목을 만들 때만 써요}
- **강조색:** 브랜드 색으로 채운 요소는 한 화면에 주요 버튼 하나예요. 그 밖에는 선택 상태와 링크에만 써요. 제목, 아이콘, 카드의 배경과 테두리, 보조 버튼에 쓰지 않아요.
- **색 조합:** 눈에 띄는 색상은 브랜드 색 하나, 중립색은 한 계열, 배경의 단계는 두 개까지예요.
- **테두리:** 경계를 알아야 하는 곳에만 써요. 간격이나 옅은 배경으로 드러나는 묶음에는 두르지 않아요.
- **면:** 배경이 있는 면은 한 겹까지예요. 버튼만 감싼 면을 만들지 않고, 채운 버튼은 주요 버튼 하나예요.
- **크기:** {예: 모바일 화면의 제목은 가장 작은 제목 단계를 쓰고, 큰 제목과 넓은 간격은 소개 화면에만 써요}
- **목록과 카드:** 한 항목에서 가장 중요한 정보 하나가 먼저 보이게 해요.

## 상태

데이터를 불러오는 모든 화면은 아래 상태를 모두 갖춰요. 하나라도 빠지면 완성된 화면이 아니에요.

| 상태 | 보여주는 것 |
| --- | --- |
| 불러오는 중 | 화면의 틀을 유지한 채 불러오고 있음을 보여줘요. 화면 전체를 비우지 않아요. |
| 비어 있음 | 왜 비어 있는지와 다음에 할 일을 알려줘요. |
| 오류 | 무슨 일이 생겼는지와 다시 해 볼 방법을 알려줘요. |
| 일부만 있음 | 내용이 한 개일 때, 아주 많을 때, 글자가 아주 길 때도 깨지지 않아요. |
| 완료 | 일이 끝났음을 알리고 다음에 갈 곳을 보여줘요. |

누르는 요소는 기본, 눌림, 포커스, 비활성 상태를 모두 갖춰요. ELI 컴포넌트는 이미 갖추고 있으니 덮어쓰지 않아요.

## 접근성

- 색만으로 뜻을 전달하지 않아요. 글자나 아이콘을 함께 써요.
- 글자와 배경의 대비를 충분히 둬요. 대비는 토큰의 조합으로 맞춰요.
- 누르는 요소는 손가락으로 누르기에 충분히 크고 서로 떨어져 있어요.
- 키보드만으로 모든 기능을 쓸 수 있어요. 포커스 표시를 지우지 않아요.
- 입력창에는 보이는 라벨을 둬요. placeholder를 라벨 대신 쓰지 않아요.
- 뜻이 있는 그림에는 설명을, 장식인 그림에는 `aria-hidden`을 넣어요.
- 움직임 줄이기 설정을 켠 사용자에게는 움직임을 줄여요.

## 단위

<!-- 맞춤: 이 섹션은 빼지 않아요. 기존 코드가 다른 기준을 일관되게 쓰고 있을 때만 사용자에게 확인받고 고쳐요. -->

CSS 값을 쓸 때 이 표에서 용도에 맞는 단위를 골라요.

| 용도 | 쓰는 단위 | 이유 |
| --- | --- | --- |
| 글자 크기 | 토큰. 토큰 파일에 새로 정할 때는 `rem` | 사용자가 브라우저 글자 크기를 바꾸면 함께 커져요 |
| 줄 높이 | 단위 없는 숫자 (예: `1.5`) | 글자 크기에 비례해요 |
| 글자 간격 | `em` | 글자 크기에 비례해요 |
| 안쪽 여백, 요소 사이 간격, 모서리 반경 | 토큰. 토큰 파일에 새로 정할 때는 `rem` | 글자와 함께 커져서 비율이 유지돼요 |
| 요소의 너비 | `%`, `fr`, `flex`, `grid` | 부모의 크기에 맞춰 늘고 줄어요 |
| 콘텐츠의 최대 너비 | `rem`과 `max-width` | 넓은 화면에서 줄이 너무 길어지지 않아요 |
| 화면 전체 너비 | `100%`. 부모와 상관없이 화면에 맞춰야 할 때만 `vw` | `100vw`는 스크롤바 너비만큼 가로로 넘칠 수 있어요 |
| 화면 전체 높이 | 화면이 흔들리면 안 되는 곳은 `svh`, 주소창을 따라 늘고 줄어야 하는 곳만 `dvh` | `vh`는 모바일에서 처음에 화면보다 길어요. `dvh`는 주소창이 움직일 때 함께 움직여요 |
| 화면 크기에 따라 변하는 값 | `clamp()`, `minmax()` | 최솟값과 최댓값 사이에서만 변해요 |
| 테두리 두께, 구분선 | `px` | 어느 화면에서나 같은 두께여야 해요 |
| 그림자 | `px` | 정밀하게 고정된 값이에요 |
| 아이콘 크기 | 글자와 함께 커져야 하면 `rem`, 고정이면 `px` | 쓰이는 자리에 따라 달라요 |
| 반응형 기준점 | 토큰의 값 | 프로젝트 전체에서 같은 기준점을 써요 |

- 글자 크기, 간격, 모서리는 값을 직접 쓰지 않고 토큰으로 써요. 이 표의 단위는 토큰 파일에 새 토큰을 정할 때와 토큰이 다루지 않는 레이아웃 크기에 적용해요.
- 글자 크기에 `px`를 쓰지 않아요. 사용자가 정한 글자 크기를 무시하게 돼요.
- 요소의 너비와 높이를 `px`로 고정하지 않아요. 좁은 화면에서 넘쳐요. 꼭 고정해야 하면 `max-width`와 함께 써요.
- 표에 없는 용도가 생기면 추측하지 않고 표에 먼저 추가해요.
