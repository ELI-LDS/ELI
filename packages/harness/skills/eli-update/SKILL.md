# 버전 확인하고 올리기

## 소스 설치는 먼저 구분해요

`../eli/references/installation.md`를 읽고 설치 방식을 확인해요. 소스 방식은 `eli.lock.json`의 UI 콘텐츠 버전, `eli.harness.json`의 하네스·설치 도구 버전과 실제 파일을 대조해요. `npx eli-design@latest status --json`의 수정·누락 상태를 먼저 보고해요. UI 소스 업데이트와 다른 버전의 하네스로 덮어쓰는 명령은 아직 없으므로 변경 내역·로컬 수정·필요한 이전을 정리하고 멈춰요. npm UI를 설치하거나 스킬을 강제로 복사해 대신하지 않아요. 기존 MCP의 `ui.latest`를 소스 콘텐츠 최신 버전으로 사용하지 않아요. 호환되는 응답이 없으면 최신 여부는 미확인으로 남기고 날짜를 갱신하지 않아요.

아래 절차는 실제로 기존 npm 패키지 방식을 사용하는 프로젝트에만 적용해요. 하네스 버전은 패키지의 `harness/skills/eli/VERSION`을 먼저 읽고, UI 버전과 같아야 한다고 가정하지 않아요.

프로젝트가 쓰는 버전은 `DESIGN.md`의 `## 버전`에 적어요. 이 표가 기준이에요.

```markdown
## 버전

| 항목 | 값 |
| --- | --- |
| `@eli-design/ui` | 0.0.0 |
| 복사한 스킬과 훅 | 0.0.0 |
| 마지막으로 확인한 날짜 | 2026-11-16 |
```

- 기존 npm 패키지의 스킬과 훅을 프로젝트로 복사해서 써요. 복사한 버전은 패키지 안의 `harness/skills/eli/VERSION`과 비교해요. 이 파일이 없는 이전 패키지만 패키지 버전을 참고해요.
- 날짜는 `YYYY-MM-DD`로 적어요. 세션 시작 훅이 이 줄을 읽어요. 줄의 이름을 바꾸지 않아요.
- 마지막으로 확인한 지 14일이 지나면 세션 시작 훅이 확인하라고 알려줘요.

## 1. 지금 쓰는 버전을 읽어요

| 대상 | 읽는 곳 |
| --- | --- |
| 설치된 `@eli-design/ui` | `node_modules/@eli-design/ui/package.json`의 `version`. 없으면 `package.json`에 적힌 범위 |
| 프로젝트에 복사한 스킬과 훅 | 프로젝트의 `eli` 스킬 폴더에 있는 `VERSION` 파일 |
| 기록된 버전과 날짜 | `DESIGN.md`의 `## 버전` |

기록된 버전과 실제로 설치된 버전이 다르면 보고에 적고, 설치된 버전을 기준으로 삼아요.

복사한 스킬의 버전이 패키지의 하네스 버전과 다르면 원격을 확인하기 전에 5번으로 스킬과 훅을 대조해요. 사용자 수정이 있으면 덮어쓰지 않아요. 이 작업은 원격 없이 할 수 있어요.

## 2. 원격에서 최신 버전을 확인해요

`eli-docs` MCP의 `get_versions`를 불러요.

| 응답 | 뜻 |
| --- | --- |
| `ui.latest` | 공개된 UI 콘텐츠의 최신 버전 |
| `ui.docs` | 원격 문서가 설명하는 UI 콘텐츠의 버전 |
| `harness.minimum` | 이 서버와 함께 쓸 수 있는 가장 낮은 하네스 버전 |

- 두 `ui` 값은 소스 설치의 UI 콘텐츠 버전이에요. 소스 방식은 `eli.json`의 콘텐츠 버전과 비교해요. 설치 도구 `eli-design`의 npm 버전과 비교하지 않아요.
- 기존 `@eli-design/ui` 패키지 방식의 프로젝트는 이 값과 패키지 버전이 같은 기준인지 확인할 수 없어요. 최신 여부를 미확인으로 남겨요.

- 원격에 연결할 수 없으면 추측하지 않아요. "확인하지 못했어요"라고 알리고, 날짜를 갱신하지 않고 멈춰요.
- npm이나 다른 곳에서 버전을 대신 알아내 올리지 않아요. 확인의 기준은 원격 MCP예요.

## 3. 비교해서 보고해요

```markdown
| 대상 | 지금 | 최신 | 상태 |
| --- | --- | --- | --- |
| `@eli-design/ui` | | | |
| 복사한 스킬과 훅 | | | |
```

| 상태 | 뜻 | 하는 일 |
| --- | --- | --- |
| 최신이에요 | 지금 버전이 최신과 같아요 | 날짜만 갱신해요 |
| 새 버전이 있어요 | `ui.latest`가 더 높아요 | 4번으로 패키지를 올리고 5번으로 스킬과 훅을 다시 복사해요 |
| 스킬이 달라요 | 복사한 스킬이 설치된 패키지와 버전이 달라요 | 5번으로 다시 복사해요 |
| 반드시 올려야 해요 | 복사한 스킬이 `harness.minimum`보다 낮아요 | 다른 작업보다 먼저 올려요. 스킬이 서버와 맞지 않아 틀린 결과가 나올 수 있어요 |
| 문서와 달라요 | 설치된 `@eli-design/ui`가 `ui.docs`와 달라요 | 원격 문서의 props가 설치된 버전과 다를 수 있다고 알려요 |

올리기 전에 무엇이 어떻게 바뀌는지 사용자에게 보여주고 한 번 확인받아요. 의존성과 훅을 바꾸는 일이라 말없이 올리지 않아요. 사용자가 지금 올리지 않겠다고 하면 그 결정을 따르고, 확인한 날짜만 갱신해요.

## 4. `@eli-design/ui`를 올려요

1. 저장하지 않은 변경이 있으면 먼저 알려요. 올리는 변경이 다른 작업과 섞이지 않게 해요.
2. 프로젝트의 타입 검사, 린트, 테스트, 빌드가 지금 통과하는지 먼저 실행해요. 이미 실패하는 검사는 기록해 둬요.
3. 프로젝트의 패키지 매니저로 `ui.latest` 버전을 정확히 지정해 설치해요.
4. 패키지에 들어 있는 변경 내역과 `get_guide`의 `install` 가이드를 읽어요. 바뀌거나 없어진 props, 토큰, import 경로를 찾아요.
5. 프로젝트에서 그 props, 토큰, 경로를 쓰는 곳을 검색해 고쳐요. `get_props`와 `get_component`로 새 사용법을 확인하고 고쳐요.
6. 타입 검사, 린트, 테스트, 빌드를 다시 실행해요. 브라우저 도구가 있으면 디자인 시스템 페이지와 주요 화면을 열어 확인해요.
7. 새로 실패하는 검사가 있고 고칠 수 없으면, 이전 버전으로 되돌릴지 사용자에게 물어요.

지켜요.

- `0.x` 버전에서는 MINOR가 올라가도 사용법이 바뀔 수 있어요. 작은 변경이라고 가정하지 않아요.
- 변경 내역을 찾을 수 없으면 그렇다고 알리고, 타입 검사와 `/eli-verify`의 "잘못된 사용" 조사로 대신 확인해요.
- 검사를 통과시키려고 테스트를 지우거나 건너뛰지 않아요.
- React 같은 다른 의존성은 함께 올리지 않아요. peer dependency가 맞지 않으면 알리고 어떻게 할지 물어요.

## 5. 스킬과 훅을 다시 복사해요

패키지를 올렸거나 복사한 스킬의 버전이 설치된 패키지와 다를 때 해요.

1. `node_modules/@eli-design/ui/harness/INSTALL.md`를 읽고 그 순서대로 다시 설치해요. 설치 방법이 바뀌었을 수 있어요. 저장소나 다른 곳에서 받지 않아요. 설치된 패키지 안의 파일이 기준이에요.
2. 스킬과 훅 파일을 덮어쓰기 전에 프로젝트의 파일을 새 파일과 비교해요. 사용자가 고친 파일이 있으면 무엇이 사라지는지 보여주고 어떻게 할지 물어요.
3. 훅 파일이나 훅 설정이 바뀌었으면 무엇이 바뀌는지 사용자에게 알려요. 훅은 사용자의 컴퓨터에서 명령을 실행해요.
4. `DESIGN.md`, `UX-WRITING.md`, `ICON.md`와 토큰 파일은 건드리지 않아요. 사용자의 문서예요.
5. 복사한 뒤 프로젝트의 `eli` 스킬 폴더에 있는 `VERSION`이 패키지의 하네스 버전과 같은지 확인해요.
6. 새 스킬이 문서의 구성을 바꿨으면(예: `DESIGN.md`에 새 섹션) 알려주고, 채울지 물어요.

## 6. 기록해요

`DESIGN.md`의 `## 버전`을 고쳐요. 섹션이 없으면 만들어요.

- 버전에는 실제로 설치된 버전을 적어요. 올리려던 버전이 아니에요.
- 마지막으로 확인한 날짜는 원격에서 버전을 실제로 확인한 날에만 오늘 날짜로 바꿔요. 확인하지 못했으면 바꾸지 않아요.
- 올리지 않기로 했으면 표 아래에 한 줄로 이유를 남겨요. 예: "0.3.0이 있지만 출시 전까지 0.2.1을 유지해요."

## 7. 보고해요

확인한 버전, 올린 것과 올리지 않은 것, 고친 코드, 실행한 검사와 결과, 확인하지 못한 것을 알려요.
