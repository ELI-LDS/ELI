# 버전 확인하고 올리기

ELI는 세 가지를 따로 버전 관리해요. 하나가 최신이라고 나머지도 최신이라고 말하지 않아요.

| 대상 | 무엇인가요 | 지금 버전을 읽는 곳 | 최신을 확인하는 방법 | 올리는 방법 |
| --- | --- | --- | --- | --- |
| 하네스 | 스킬과 훅 | `.eli/harness.json`의 `version` | 설치 도구의 `harness --update --dry-run` | 설치 도구의 `harness --update` |
| UI 콘텐츠 | 프로젝트에 들어온 컴포넌트 소스 | `.eli/config.json`의 `version` | `eli-docs`의 `get_versions`의 `ui.latest` | 아직 명령이 없어요. 3번을 따라요 |
| 설치 도구 | `eli-design` 명령 | `npx eli-design@latest --version` | 같은 명령. `@latest`로 실행하면 항상 최신이에요 | 따로 올리지 않아요 |

- **`get_versions`는 하네스의 최신 버전을 알려주지 않아요.** `ui.latest`와 `ui.docs`는 UI 콘텐츠의 버전이고, `harness.minimum`은 서버와 함께 쓸 수 있는 가장 낮은 하네스 버전이에요. 이 응답만 보고 하네스가 최신이라고 말하지 않아요.
- 먼저 `../eli/references/installation.md`로 설치 방식을 확인해요. `.eli/harness.json`이 없으면 이 프로젝트에는 설치 도구로 설치한 하네스가 없어요. 이 문서 끝의 "설치 기록이 없을 때"를 따라요.

## 1. 지금 상태를 읽어요

```bash
npx eli-design@latest status --json
npx eli-design@latest harness --update --dry-run --json
```

- 첫 명령은 UI와 하네스의 설치 버전, 파일별 `unchanged`·`modified`·`missing` 상태를 알려줘요.
- 둘째 명령은 아무것도 바꾸지 않아요. 응답의 `from`이 지금 하네스, `version`이 공개된 최신 하네스예요. `updated`가 `true`이면 새 버전이 있어요. `files`의 `replace`·`add`와 `stale`이 바뀔 파일이에요.
- 둘째 명령이 `FILE_CONFLICT`로 끝나면 직접 수정한 스킬·훅이 있는 거예요. `details.paths`가 그 파일이고 `details.to`가 최신 버전이에요. 2번의 "직접 수정한 파일이 있을 때"를 따라요.
- 이어서 `eli-docs`의 `get_versions`를 불러 `ui.latest`·`ui.docs`·`harness.minimum`을 읽어요. 도구가 세션에 보이지 않으면 `eli` 스킬의 조회 스크립트로 불러요.
- 명령이나 조회가 네트워크 문제로 실패하면 그 항목은 "확인하지 못했어요"로 적어요. 추측하지 않고, 확인하지 못한 항목 때문에 다른 항목까지 멈추지 않아요.

## 2. 비교해서 보고하고 하네스를 올려요

```markdown
| 대상 | 지금 | 최신 | 상태 |
| --- | --- | --- | --- |
| 하네스 | | | |
| UI 콘텐츠 | | | |
| 설치 도구 | | | |
```

| 상태 | 뜻 | 하는 일 |
| --- | --- | --- |
| 최신이에요 | 지금 버전이 최신과 같아요 | 그대로 둬요 |
| 새 버전이 있어요 | 최신이 더 높아요 | 하네스는 아래대로 올려요. UI 콘텐츠는 3번을 따라요 |
| 반드시 올려야 해요 | 하네스가 `harness.minimum`보다 낮아요 | 다른 작업보다 먼저 올려요. 스킬이 서버와 맞지 않아 틀린 결과가 나올 수 있어요 |
| 문서와 달라요 | UI 콘텐츠가 `ui.docs`와 달라요 | 원격 문서의 props가 설치된 소스와 다를 수 있다고 알려요 |
| 확인하지 못했어요 | 명령이나 조회가 실패했어요 | 이유를 적고 날짜를 갱신하지 않아요 |

하네스에 새 버전이 있으면 표를 보여주고 올려요.

1. 바뀔 파일의 수와 직접 수정한 파일이 있는지를 한두 문장으로 알려요. 사용자가 "업데이트해줘", "올려줘"처럼 올려 달라고 했으면 다시 묻지 않고 진행해요. 버전을 확인해 달라고만 했거나 세션 시작 훅의 안내로 시작했으면 올릴지 한 번 물어요.
2. `npx eli-design@latest harness --update`를 실행해요. 설치 당시와 같은 파일만 새 내용으로 바꾸고, 이미 설치한 에이전트를 모두 함께 옮겨요. 중간에 실패하면 바꾼 파일을 되돌려요.
3. 출력의 안내를 따라요. 새 버전에 없는 파일(`stale`)이 있으면 쓰지 않는지 확인하고 지워요.
4. **스킬을 다시 읽어요.** 이번 세션이 이미 읽은 지침은 이전 버전이에요. 이어서 할 작업의 `SKILL.md`를 파일로 다시 읽고, Claude Code는 `/reload-skills`를 안내해요. Codex는 `/hooks`에서 바뀐 훅을 다시 신뢰해야 해요.
5. `npx eli-design@latest status --json`으로 하네스 파일이 모두 `unchanged`이고 버전이 최신인지 확인해요.
6. 새 스킬이 문서의 구성을 바꿨으면(예: `DESIGN.md`에 새 섹션) 알려주고 채울지 물어요. `DESIGN.md`, `UX-WRITING.md`, `ICON.md`와 토큰 파일은 업데이트가 건드리지 않아요.

### 직접 수정한 파일이 있을 때

설치 도구는 직접 수정한 스킬·훅이 하나라도 있으면 아무것도 바꾸지 않아요.

1. 수정한 파일마다 무엇이 달라졌는지 보여줘요. Git이 있으면 `git diff`로, 없으면 파일을 읽어서 요약해요.
2. 파일마다 사용자에게 물어요. 수정을 버리고 새 버전을 받을지, 수정을 유지할지예요.
3. 버리기로 한 파일은 지우고 `harness --update`를 다시 실행해요. 없는 파일은 새 버전으로 채워져요. 강제로 덮어쓰는 옵션은 없어요.
4. 유지하기로 한 파일이 남아 있으면 업데이트할 수 없어요. 그 내용을 다른 곳에 옮겨 두고 파일을 지운 뒤 업데이트하고, 새 파일에 다시 적용하는 방법을 제안해요. 사용자가 원하지 않으면 올리지 않고 이유를 `DESIGN.md`에 남겨요.

## 3. UI 콘텐츠에 새 버전이 있을 때

설치한 UI 소스를 다른 버전으로 옮기는 명령은 아직 없어요. 올린 것처럼 말하지 않아요.

- 지금 버전과 `ui.latest`를 알리고, 새 버전의 변경 내역을 찾을 수 있으면 요약해요.
- `status`의 `modified` 파일과 `DESIGN.md`의 `## 컴포넌트`에 적힌 변형·다듬은 원본을 정리해요. 버전을 옮길 때 다시 적용할 목록이에요.
- 전체 npm UI 패키지를 설치하거나 파일을 강제로 덮어써서 대신하지 않아요.
- 지금 필요한 컴포넌트가 새 버전에만 있으면 그 사실을 알리고 어떻게 할지 물어요.

## 4. 기록해요

`DESIGN.md`의 `## 버전`을 실제 설치된 값으로 고쳐요. 섹션이 없으면 `eli-design-md` 스킬의 `template.md`에 있는 표를 가져와 만들어요.

- 버전에는 실제로 설치된 버전을 적어요. 올리려던 버전이 아니에요.
- "마지막으로 확인한 날짜"는 하네스의 최신 버전과 `get_versions`를 둘 다 실제로 확인한 날에만 오늘 날짜(`YYYY-MM-DD`)로 바꿔요. 세션 시작 훅이 이 줄을 읽으니 줄의 이름을 바꾸지 않아요.
- 올리지 않기로 했으면 표 아래에 한 줄로 이유를 남겨요.

## 5. 보고해요

대상별로 지금 버전과 최신 버전, 올린 것과 올리지 않은 것, 직접 수정해서 남긴 파일, 확인하지 못한 것을 알려요. 하네스만 올렸으면 UI 콘텐츠는 그대로라고 분명히 적어요.

## 설치 기록이 없을 때

- **스킬은 있는데 `.eli/harness.json`이 없어요.** 설치 도구 0.4.0 이하로 설치했거나 손으로 복사한 프로젝트예요. 루트에 `eli.harness.json`이 있으면 `.eli/harness.json`으로 옮긴 뒤 1번부터 진행해요(`eli.json`은 `.eli/config.json`, `eli.lock.json`은 `.eli/lock.json`). 기록이 아예 없으면 복사된 스킬·훅 폴더를 사용자가 고쳤는지 확인하고, 고친 것이 없으면 지운 뒤 `npx eli-design@latest harness --agent <에이전트>`로 다시 설치해요.
- **기존 `@eli-design/ui` 패키지 방식이에요.** 이 패키지는 종료 예정이에요. 패키지를 올리지 않고 `../eli/references/installation.md`의 안내대로 소스 방식으로 옮길지 물어요. 기존 의존성을 임의로 지우지 않아요.
