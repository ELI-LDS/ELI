# CSS를 쓰는 기준

화면의 CSS를 쓰거나 고칠 때 읽어요. 값은 프로젝트 토큰으로, 단위는 `DESIGN.md`의 `## 단위` 표로 정해요. 이 문서는 그 밖의 구조, 레이아웃, 글자, 상태를 다뤄요. ELI 컴포넌트의 내부 스타일에는 적용하지 않아요. 프로젝트가 직접 쓰는 스타일에 적용해요.

## 구조

- **클래스 하나로 스타일해요.** 선택자는 클래스 하나를 기본으로 해요. ID 선택자, 태그를 길게 이은 선택자, 깊은 중첩을 쓰지 않아요. ID 하나는 클래스 몇 개를 써도 이길 수 없어서 나중에 덮어쓸 방법이 없어져요.
- **`!important`를 쓰지 않아요.** 우선순위가 안 맞으면 선택자를 단순하게 고치거나 선언 순서를 바꿔요. 꼭 써야 하면 이유를 주석으로 남겨요.
- **덮어쓰라고 만든 기본 스타일은 `:where()`로 감싸요.** `:where()`의 우선순위는 항상 0이에요.
- **중첩은 얕게 써요.** `.a { .b {} }`는 자손 선택자이고 `&.b`는 같은 요소예요. `&__child`처럼 이름을 이어 붙이는 방식은 동작하지 않아요.
- **바깥 여백은 부모가 정해요.** 컴포넌트는 자기 바깥 `margin`을 갖지 않아요. 부모가 `gap`으로 사이를 띄워요. 여백은 두 요소 사이의 관계라서, 컴포넌트가 가지면 다른 자리에서 다시 쓸 수 없어요.
- **토큰 이름을 틀리면 조용히 깨져요.** `var(--없는-토큰)`은 이전 선언으로 돌아가지 않고 상속값이나 초깃값이 돼요. 글자가 검정이 되거나 배경이 투명해져요. 토큰 이름은 토큰 파일에서 확인하고 써요.
- **`var()`는 미디어 쿼리 조건에 쓸 수 없어요.** 반응형 기준점은 토큰의 값을 숫자로 적고, 프로젝트 전체에서 같은 숫자를 써요.
- **동적인 값만 인라인 스타일로 넘겨요.** 정적인 스타일은 CSS 파일에 써요. 진행률처럼 실행 중에 정해지는 값은 `style={{ '--progress': value }}`처럼 변수로 넘기고 CSS에서 받아요.

## 레이아웃

- **한 방향은 flex, 두 방향은 grid를 써요.**
- **좁은 화면을 먼저 만들어요.** 기본 스타일이 가장 좁은 화면이고, `@media (width >= …)`로 넓혀 가요. `max-width`와 `min-width` 방식을 섞지 않아요.
- **너비 320px에서 가로 스크롤이 생기면 안 돼요.** 접근성 기준(WCAG 1.4.10)이에요. 375px에만 맞추지 않아요.
- **flex와 grid의 자식에 `min-width: 0`을 줘요.** flex 항목은 내용의 최소 너비보다 줄어들지 않아서, 긴 낱말이나 URL 하나가 화면을 가로로 밀어요. grid에서는 `1fr` 대신 `minmax(0, 1fr)`을 써요.
- **위치를 잡으려고 `position: absolute`를 쓰지 않아요.** 흐름에서 빠져서 글자가 커지거나 내용이 길어지면 겹쳐요. 배지나 닫기 버튼처럼 다른 요소 위에 올리는 경우에만 써요.
- **높이를 고정하지 않아요.** 글자가 든 상자에는 `height` 대신 `min-height`와 안쪽 여백을 써요. 사용자가 글자 크기나 줄 간격을 키우면 넘쳐요.
- **이미지와 영상의 자리를 미리 잡아요.** `width`와 `height` 속성이나 `aspect-ratio`를 주고, `max-width: 100%`와 `height: auto`를 함께 써요. 자리를 잡지 않으면 불러올 때 화면이 밀려요.
- **재사용하는 컴포넌트는 컨테이너 쿼리, 페이지 배치는 미디어 쿼리를 써요.** 컴포넌트는 화면이 아니라 자기가 놓인 자리의 너비에 맞춰야 해요.
- **화면 전체 높이는 용도에 맞게 골라요.** 화면이 흔들리면 안 되는 곳은 `min-height: 100svh`, 주소창을 따라 늘고 줄어야 하는 곳만 `100dvh`를 써요. `100vh`는 모바일에서 처음에 화면보다 길어요.
- **아래에 고정한 요소에는 안전 영역을 더해요.** `padding-bottom: calc(여백 + env(safe-area-inset-bottom))`처럼 써요. 뷰포트 메타에 `viewport-fit=cover`가 있어야 해요.
- **확대를 막지 않아요.** 뷰포트 메타에 `user-scalable=no`나 `maximum-scale=1`을 넣지 않아요.

### 겹침

- **`z-index: 9999`를 쓰지 않아요.** `z-index`는 자기가 속한 쌓임 맥락 안에서만 겨뤄서, 숫자를 키워도 밖으로 나가지 못해요.
- **컴포넌트의 뿌리에 `isolation: isolate`를 줘요.** 안쪽의 `z-index`가 밖으로 새지 않아요.
- **모달과 팝오버는 ELI 컴포넌트를 써요.** 직접 만들어야 하면 `<dialog>`의 `showModal()`을 써요. 브라우저의 최상위 층에 올라가서 `z-index`와 `overflow`의 영향을 받지 않아요.
- **`position: sticky`가 안 되면 조상을 봐요.** `top` 같은 위치 값이 있어야 하고, 조상 중에 `overflow`가 `hidden`·`auto`·`scroll`인 요소가 있으면 그 요소에 붙어요.
- **`position: fixed`가 화면에 붙지 않으면 조상을 봐요.** 조상에 `transform`, `filter`, `will-change: transform`이 있으면 화면이 아니라 그 조상을 기준으로 잡혀요.

## 글자

- **글자 크기, 굵기, 줄 높이, 자간은 타이포그래피 토큰을 한 묶음으로 써요.** ELI의 값은 Pretendard에 맞춰져 있어요. 자간만 따로 바꾸거나 글꼴을 바꾸면 어긋나요.
- **줄 높이는 단위 없는 숫자로 써요.** 본문은 `1.5` 안팎, 제목은 더 좁게 써요.
- **한 줄이 너무 길지 않게 해요.** 본문은 `max-inline-size`로 한 줄의 글자 수를 제한해요.
- **한국어 줄바꿈은 `word-break: keep-all`과 `overflow-wrap: anywhere`를 함께 써요.** `keep-all`은 낱말 중간에서 끊지 않고 띄어쓰기에서만 줄을 바꿔요. `overflow-wrap`이 없으면 띄어쓰기 없는 긴 문자열이 넘쳐요.
- **한 줄 말줄임은 세 속성을 함께 써요.** `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`이고, flex 안에서는 `min-width: 0`도 필요해요.
- **여러 줄 말줄임은 `-webkit-` 방식으로 써요.** `display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: N; overflow: hidden`이에요. 접두사 없는 `line-clamp`는 아직 일부 브라우저만 지원해요.
- **제목에는 `text-wrap: balance`를 써요.** 줄 길이를 고르게 맞춰요. 본문에는 쓰지 않아요.
- **바뀌는 숫자에는 `font-variant-numeric: tabular-nums`를 써요.** 숫자가 바뀔 때 폭이 흔들리지 않아요.
- **입력창의 글자는 16px(`1rem`)보다 작게 하지 않아요.** iOS Safari는 그보다 작은 입력창에 포커스가 가면 화면을 확대해요. 확대를 막아서 해결하지 않아요.
- **입력창과 버튼에 `font: inherit`를 줘요.** 브라우저 기본 글꼴은 작고 본문과 달라요. ELI 컴포넌트에는 이미 적용되어 있어요.

## 상태와 움직임

- **포커스 표시를 지우지 않아요.** `outline: none`만 쓰지 않아요. 바꾸려면 `:focus-visible`에 눈에 띄는 대체 표시를 줘요.
- **hover 스타일은 `@media (hover: hover)` 안에 써요.** 터치 기기에서는 누른 뒤에 hover가 남아요.
- **hover에서만 보이는 기능을 만들지 않아요.** 터치 기기에서는 쓸 수 없어요.
- **누르는 요소에 `touch-action: manipulation`을 줘요.** 두 번 눌러 확대하는 동작과 눌림 지연이 없어져요. `touch-action: none`은 확대를 막으니 넓게 쓰지 않아요.
- **`transform`과 `opacity`만 움직여요.** `width`, `height`, `top`, `left`, `margin`을 움직이면 매 프레임마다 배치를 다시 계산해서 끊겨요.
- **`transition: all`을 쓰지 않아요.** 바뀌는 속성을 적어요.
- **`will-change`를 미리 넣지 않아요.** 실제로 끊기는 문제를 확인한 곳에만 써요. 메모리를 쓰고 쌓임 맥락을 새로 만들어요.
- **움직임 줄이기 설정을 따라요.** `@media (prefers-reduced-motion: reduce)`에서는 크게 움직이는 효과를 옅어지는 효과로 바꿔요.
- **안쪽 스크롤 영역에 `overscroll-behavior: contain`을 줘요.** 모달이나 서랍을 끝까지 스크롤했을 때 뒤의 페이지가 따라 움직이지 않아요.
- **고정된 머리글 아래로 이동하는 대상에 `scroll-margin-top`을 줘요.** 포커스나 앵커로 이동한 요소가 머리글에 가려지지 않아요.

## 써도 되는 기능

2026년 11월 기준이에요. "널리"는 주요 브라우저가 지원한 지 오래된 기능이고, "최근"은 모든 주요 브라우저가 지원하지만 오래되지 않은 기능이에요.

| 지원 | 기능 | 쓰는 법 |
| --- | --- | --- |
| 널리 | flex `gap`, `aspect-ratio`, 논리 속성(`margin-inline` 등), `:focus-visible`, `:where()`, `:has()`, 중첩, 컨테이너 쿼리, `svh`·`dvh`, `clamp()`, 서브그리드, `color-mix()`, `<dialog>`, `inert` | 그대로 써요 |
| 최근 | `text-wrap: balance`, `light-dark()`, `@starting-style`, 팝오버, `content-visibility`, 같은 문서 안의 뷰 전환, `field-sizing` | 지원하지 않아도 화면이 깨지지 않는 곳에 써요 |
| 일부 | `text-wrap: pretty`, 접두사 없는 `line-clamp`, `interpolate-size`, 앵커 위치 잡기, 문서 사이의 뷰 전환 | 없어도 되는 꾸밈에만 써요 |

프로젝트가 지원하는 브라우저는 `DESIGN.md`의 `## 제약`을 따라요.

## 쓰기 전에 확인해요

- 색, 간격, 글자, 모서리 값을 직접 쓰지 않았나요?
- 너비와 높이를 `px`로 고정하지 않았나요?
- 너비 320px에서 가로로 넘치지 않나요?
- 글자가 두 배로 길어져도 깨지지 않나요?
- 포커스 표시가 보이나요?
- hover 없이도 모든 기능을 쓸 수 있나요?
