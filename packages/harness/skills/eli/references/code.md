# 화면 코드를 쓰는 기준

React 컴포넌트와 마크업을 쓰거나 고칠 때 읽어요. ELI에 맞는 컴포넌트가 있으면 그 컴포넌트를 먼저 써요. ELI 컴포넌트는 아래 기준의 많은 부분을 이미 갖추고 있어요. 이 문서는 프로젝트가 직접 쓰는 코드에 적용해요.

## 마크업

- **하는 일은 `<button>`, 이동은 `<a href>`를 써요.** `div`나 `span`에 `onClick`을 달지 않아요. 키보드로 누를 수 없고 스크린 리더가 버튼으로 읽지 않아요. `role`을 붙여도 키보드 동작은 생기지 않아요.
- **제목은 순서대로 써요.** `h1` 다음에 `h3`으로 건너뛰지 않아요. 크기를 바꾸려고 제목 단계를 고르지 않아요.
- **영역에 맞는 요소를 써요.** `header`, `nav`, `main`, `footer`, `section`, `ul`을 써요.
- **아이콘만 있는 버튼에는 `aria-label`을 써요.** 장식인 아이콘에는 `aria-hidden="true"`를 써요.
- **이미지에는 `alt`를 써요.** 장식이면 `alt=""`로 비워요.

## 입력

- **모든 입력창에 라벨을 둬요.** `<label>`로 감싸거나 `htmlFor`와 `useId`로 만든 `id`로 연결해요. placeholder는 라벨이 아니에요.
- **`type`, `inputmode`, `autocomplete`를 맞게 써요.** 모바일에서 맞는 키보드가 뜨고 자동 완성이 돼요.

| 입력 | 쓰는 속성 |
| --- | --- |
| 이메일 | `type="email"` `autocomplete="email"` |
| 전화번호 | `type="tel"` `autocomplete="tel"` |
| 새 비밀번호 | `type="password"` `autocomplete="new-password"` |
| 기존 비밀번호 | `type="password"` `autocomplete="current-password"` |
| 인증 번호 | `inputmode="numeric"` `autocomplete="one-time-code"` |
| 숫자 | `inputmode="numeric"` 또는 `inputmode="decimal"` |
| 검색 | `type="search"` `enterkeyhint="search"` |

- **없는 `autocomplete` 값을 지어내지 않아요.** 로그인 입력창의 `autocomplete="off"`는 브라우저가 무시할 수 있어요.
- **오류는 색만으로 알리지 않아요.** 오류 문구를 `aria-describedby`로 입력창에 연결하고, 제출했을 때 첫 오류로 포커스를 옮겨요.
- **붙여넣기를 막지 않아요.**
- **제출 버튼은 요청을 보낼 때까지 켜 둬요.** 요청을 시작하면 끄고 진행 중임을 보여줘요. 미리 꺼 두면 왜 못 누르는지 알 수 없어요.

## 누르는 영역과 대비

| 기준 | 값 | 출처 |
| --- | --- | --- |
| 누르는 영역의 최소 크기 | 24 × 24px | WCAG 2.2 2.5.8 (AA) |
| 터치 화면에서 권장하는 크기 | 44 × 44px 이상 | WCAG 2.2 2.5.5 (AAA), Apple |
| 누르는 요소 사이의 간격 | 8px 안팎 | Android, web.dev |
| 글자와 배경의 대비 | 4.5:1 이상 | WCAG 2.2 1.4.3 (AA) |
| 큰 글자(약 24px, 굵으면 약 18.5px 이상)의 대비 | 3:1 이상 | WCAG 2.2 1.4.3 (AA) |
| 입력창 테두리, 뜻이 있는 아이콘, 포커스 표시의 대비 | 3:1 이상 | WCAG 2.2 1.4.11 (AA) |

- 보이는 모양이 작으면 안쪽 여백이나 가상 요소로 누르는 영역만 넓혀요.
- 대비는 토큰의 조합으로 맞춰요. 대비를 맞추려고 색상 값을 직접 쓰지 않아요.
- placeholder의 글자도 대비 기준을 지켜야 해요. 꺼진 요소는 예외예요.

## 바뀌는 내용

- **결과를 스크린 리더에도 알려요.** `role="status"`나 `aria-live="polite"`를 가진 빈 요소를 처음부터 그려 두고, 나중에 안의 글자만 바꿔요. 요소와 글자를 함께 그리면 읽어 주지 않아요.
- **급한 오류에만 `role="alert"`를 써요.**
- **모달은 ELI 컴포넌트를 써요.** 직접 만들어야 하면 `<dialog>`의 `showModal()`을 쓰고, 보이는 닫기 버튼을 둬요.

## 이미지와 성능

- **이미지에 `width`와 `height`를 반드시 써요.** 불러올 때 화면이 밀리지 않아요.
- **화면 아래의 이미지에만 `loading="lazy"`를 써요.** 처음 화면에서 가장 큰 이미지에는 쓰지 않고 `fetchpriority="high"`를 써요.
- **가장 큰 이미지는 `<img>`로 넣어요.** CSS 배경으로 넣거나 스크립트로 나중에 넣으면 늦게 떠요.
- **내용을 불러오는 자리의 크기를 미리 잡아요.** 뼈대 화면은 실제 내용과 같은 크기로 만들어요.
- **이미 있는 내용 위에 새 내용을 끼워 넣지 않아요.** 보던 내용이 밀려요.
- **긴 목록은 필요한 만큼만 그려요.**

| 지표 | 좋은 기준 |
| --- | --- |
| 가장 큰 내용이 뜨는 시간(LCP) | 2.5초 이하 |
| 눌렀을 때 반응하는 시간(INP) | 200ms 이하 |
| 화면이 밀리는 정도(CLS) | 0.1 이하 |

## React

- **계산할 수 있으면 상태로 두지 않아요.** 다른 상태나 props에서 구할 수 있는 값은 렌더링 중에 계산해요. `useEffect`로 상태를 맞추지 않아요.
- **사용자가 한 일은 이벤트 핸들러에서 처리해요.** `useEffect`는 화면에 보이는 동안 외부 시스템과 맞춰야 할 때만 써요.
- **상태를 초기화하려면 `key`를 바꿔요.** `useEffect`로 초기화하지 않아요.
- **서로 어긋날 수 있는 상태를 만들지 않아요.** `isLoading`, `isError`를 따로 두지 않고 `status` 하나로 둬요.
- **props를 상태에 복사하지 않아요.** 처음 값으로만 쓸 때는 이름을 `initialX`나 `defaultX`로 지어요.
- **`key`는 데이터의 고유한 값으로 써요.** 순서가 바뀌거나 지워지는 목록에 배열의 순번을 쓰지 않아요. `Math.random()`을 쓰지 않아요.
- **렌더링 중에 props, 상태, 바깥 변수를 바꾸지 않아요.**
- **컴포넌트 안에서 컴포넌트를 정의하지 않아요.** 렌더링할 때마다 새로 만들어져서 상태가 사라져요.
- **입력창은 제어하거나 제어하지 않거나 하나로 정해요.** 제어하면 `value`와 `onChange`를 함께 쓰고, `value`에 `null`이나 `undefined`를 넣지 않아요.
- **React 19에서는 `ref`를 props로 받아요.** `forwardRef`를 새로 쓰지 않아요.

### 컴포넌트를 만들 때

- **`className`을 받아 뿌리 요소에 합쳐요.** 받은 `className`을 마지막에 붙여요. 나머지 props도 뿌리 요소에 넘겨요.
- **참·거짓 props를 늘리지 않아요.** 모양이 여러 가지면 `variant` 하나로, 안의 내용이 여러 가지면 `children`으로 받아요.
- **상태에 따른 스타일은 클래스나 `data-` 속성으로 바꿔요.** 정적인 스타일을 인라인 `style`로 쓰지 않아요.
- **스타일 파일은 컴포넌트 옆에 둬요.** 프로젝트의 기존 구조가 다르면 그 구조를 따라요.
- **핸들러 이름은 `handleX`, 넘겨받는 props는 `onX`로 지어요.**
- **데이터를 불러오는 화면은 네 가지 상태를 모두 만들어요.** 불러오는 중, 비어 있음, 오류, 성공이에요.

### Next.js App Router

- **기본은 Server Component예요.** 상태, 이벤트, 브라우저 API가 필요한 가장 작은 컴포넌트에만 `'use client'`를 붙여요. 페이지나 레이아웃 전체에 붙이지 않아요.
- **Server Component는 `children`으로 넘겨요.** Client Component 안에서 직접 불러오지 않아요.
- **경계를 넘는 props는 직렬화할 수 있어야 해요.** 함수를 넘기지 않아요.
- **날짜와 숫자는 `Intl`로 표시해요.** 서버와 브라우저의 결과가 달라지지 않게 해요.
- **필터, 탭, 페이지 번호는 주소에 담아요.** 새로 고치거나 공유해도 같은 화면이 나와요.

## 쓰기 전에 확인해요

- ELI에 맞는 컴포넌트가 있는데 직접 만들지 않았나요?
- `div`에 `onClick`을 달지 않았나요?
- 모든 입력창에 라벨이 있나요?
- 키보드만으로 끝까지 쓸 수 있나요?
- 불러오는 중, 비어 있음, 오류 상태가 있나요?
- `useEffect` 없이 쓸 수 있는데 쓰지 않았나요?
