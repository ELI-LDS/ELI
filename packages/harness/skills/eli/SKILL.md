# ELI

ELI는 React 디자인 컴포넌트 라이브러리예요. 컴포넌트 사용법, props, 토큰 값은 원격 MCP `eli-docs`에서 읽어요. 이 스킬은 작업 절차와, 어느 서비스에나 적용되는 화면 코드의 기준을 담아요.

## 작업 전에 문서를 읽어요

먼저 `references/installation.md`로 소스 설치와 기존 npm 패키지 설치를 구분해요. 실제 import 경로는 소스 설치 기록에서 읽어요. UI가 이미 소스로 설치되어 있으면 전체 npm UI 패키지를 추가하지 않아요.

UI나 디자인을 만들거나 고치는 요청을 받으면 코드를 쓰기 전에 아래 순서로 확인해요.

1. 프로젝트 루트에 `DESIGN.md`가 없으면 아직 셋업하지 않은 프로젝트예요. 작업하기 전에 `/eli-setup`을 제안해요. 있으면 읽어요. 서비스의 방향과 톤, 토큰 파일의 경로가 여기에 있어요. 토큰 파일도 읽어요.
2. `list_components`로 요청에 맞는 컴포넌트를 찾아요. 이름이 떠오르지 않으면 `search`를 써요.
3. `get_component`로 필요한 섹션만 읽어요. 어떤 컴포넌트를 쓸지 고를 때는 `when-to-use`, 코드를 쓸 때는 `examples`를 읽어요.
4. props가 필요하면 `get_props`, 색상·간격·글자 값이 필요하면 `get_tokens`로 확인해요.
5. 설치가 필요하면 `references/installation.md`를 따르고 `get_guide`의 `install` 가이드가 있으면 함께 읽어요. 글꼴은 Pretendard로 고정이에요.

## 필요한 만큼만 읽어요

원격 문서는 요청한 부분만 돌려줘요. 넓게 읽으면 컨텍스트만 차지해요. 아래처럼 좁혀서 불러요.

| 필요한 것 | 부르는 방법 |
| --- | --- |
| 컴포넌트 고르기 | `get_component`를 `sections` 없이 불러요. `summary`와 `when-to-use`만 와요 |
| 코드 쓰기 | `sections: ["examples"]`. 변형이 필요할 때만 `variants`, 외부 스타일을 바꿀 때만 `styling`을 더해요 |
| 문구·아이콘·피해야 할 사용 확인 | `sections: ["do-dont"]`. `styling`의 내용이 여기에 들어 있으니 둘을 함께 요청하지 않아요 |
| 키보드·스크린 리더 확인 | `sections: ["accessibility"]` |
| 쓸 prop을 알 때 | `get_props`에 `names`로 그 prop만 요청해요 |
| 어떤 prop이 있는지 훑을 때 | `get_props`에 `fields: ["type"]`. 설명은 쓸 prop을 정한 뒤에 `names`로 읽어요 |
| 토큰 값 | `get_tokens`를 `category` 없이 불러 구역 이름을 본 뒤, `category`와 `group`으로 그 구역만 읽어요. 이름을 알면 `q`로 찾아요 |

- 응답의 `available`에 없는 섹션은 다시 요청하지 않아요. 그 내용은 문서에 없는 거예요.
- 오류 응답의 `allowed`에서 골라 바로 다시 불러요. 이름을 추측해서 여러 번 부르지 않아요.
- `get_component`의 `id`는 설치 도구의 `add`에 쓰는 이름이에요. `entry`는 설치 폴더를 기준으로 한 파일과 export 이름이에요. 서버는 프로젝트의 폴더 위치를 모르므로, 실제 import 경로는 `eli.lock.json`의 같은 `id` 항목에서 읽어요.
- 예시 코드의 import는 기본 설치 위치(`./components/ui/...`)를 전제로 한 것이에요. 그대로 복사하지 않고 위에서 확인한 실제 경로로 바꿔 써요. 예시에 나오는 다른 컴포넌트도 설치되어 있는지 확인해요.
- 응답의 `status`가 `draft`면 아직 검토 전인 가이드예요. 참고해서 작업하되 `DESIGN.md`나 사용자의 지시와 다르면 그쪽을 따르고, 검토 전 가이드를 근거로 썼다고 알려요. `null`이면 가이드가 없는 컴포넌트라 `get_props`와 설치된 소스만 근거로 써요.
- 가이드나 섹션이 `not_found`이거나 빠져 있으면 아직 제공되지 않는 내용이에요. 지어내지 않고, 이 스킬과 프로젝트 문서의 기준으로만 작업했다고 사용자에게 알려요.

## 지켜요

- props, 토큰 값, 컴포넌트 이름, import 경로를 기억으로 쓰지 않아요. 매번 `eli-docs`에서 확인해요.
- ELI에 맞는 컴포넌트가 있으면 직접 만들지 않고 그 컴포넌트를 써요.
- 문서에 없는 사용법은 지어내지 않아요. 없다고 사용자에게 말하고 대안을 물어요.
- 한 요청에서 같은 문서를 두 번 조회하지 않아요.

## 스타일은 프로젝트 토큰으로만 써요

예외 없이 지켜요. 작은 수정, 급한 수정, 임시 화면에도 적용해요.

- 색, 간격, 글자 크기·굵기·줄 높이, 모서리 반경, 그림자는 프로젝트의 토큰으로만 써요. `#3182f6`, `16px` 같은 값을 화면 코드에 직접 쓰지 않아요.
- 화면 코드에서 `--eli-` 변수를 직접 쓰지 않아요. 프로젝트 토큰을 거쳐서 써요. `--eli-` 변수와 값을 직접 쓸 수 있는 곳은 토큰 파일 하나뿐이에요.
- 필요한 토큰이 없으면 값을 직접 쓰지 않고, 토큰 파일에 역할 이름으로 먼저 추가한 뒤 그 토큰을 써요. 추가한 토큰은 사용자에게 알려요.
- 프로젝트에 토큰 파일이 없으면 스타일 작업을 시작하기 전에 `/eli-design-system`으로 토큰부터 만들자고 안내해요.
- 사용자가 값을 직접 쓰라고 요청하면 이 규칙을 알리고, 토큰으로 추가하는 방법을 먼저 제안해요.

## 화면 코드를 잘 써요

ELI를 쓰는 것만으로 좋은 화면이 되지 않아요. 프로젝트가 직접 쓰는 CSS, 마크업, React 코드는 아래 기준을 따라요. 작업에 맞는 문서를 이 스킬 폴더의 `references/`에서 읽어요.

| 작업 | 읽는 문서 |
| --- | --- |
| CSS를 쓰거나 고칠 때 | `references/css.md` |
| 컴포넌트, 마크업, 입력 폼을 쓸 때 | `references/code.md` |
| 새 화면을 만들거나 구성을 바꿀 때 | `references/design.md` |

문서를 읽기 전에도 아래는 항상 지켜요.

- **레이아웃:** 좁은 화면을 먼저 만들어요. 너비 320px에서 가로로 넘치지 않아야 해요. 너비와 높이를 `px`로 고정하지 않아요.
- **넘침:** flex와 grid의 자식에 `min-width: 0`을 줘요. 글자가 든 상자에 `height`를 고정하지 않고 `min-height`를 써요.
- **간격:** 컴포넌트는 바깥 `margin`을 갖지 않아요. 부모가 `gap`으로 띄워요.
- **우선순위:** 클래스 하나로 스타일해요. `!important`, ID 선택자, `z-index: 9999`를 쓰지 않아요.
- **마크업:** 하는 일은 `<button>`, 이동은 `<a href>`를 써요. `div`에 `onClick`을 달지 않아요. 모든 입력창에 라벨을 둬요.
- **상태:** 포커스 표시를 지우지 않아요. hover 스타일은 `@media (hover: hover)` 안에 써요. 데이터를 불러오는 화면에는 불러오는 중, 비어 있음, 오류 상태를 모두 만들어요.
- **누르는 영역:** 터치 화면에서 44px 이상으로 해요. 24px보다 작게 하지 않아요.
- **움직임:** `transform`과 `opacity`만 움직여요. 움직임 줄이기 설정을 따라요.
- **React:** 계산할 수 있는 값을 상태로 두지 않아요. `useEffect`로 상태를 맞추지 않아요. `key`는 데이터의 고유한 값으로 써요.
- **디자인:** 한 화면에 주요 버튼은 하나예요. 관련 있는 것은 가깝게, 없는 것은 멀게 둬요. 선보다 여백으로 나눠요.

이 기준과 `DESIGN.md`가 다르면 `DESIGN.md`를 따라요. 기존 코드의 방식이 이 기준과 다르면 혼자 바꾸지 않고 사용자에게 알려요.

## 글꼴은 Pretendard로 고정이에요

예외 없이 지켜요.

- 전역 글꼴은 Pretendard예요. 다른 글꼴을 추가하거나 제안하지 않아요. `--eli-font-family-sans`를 다시 정하지 않아요.
- ELI의 글자 크기, 굵기, 줄 높이, 자간은 Pretendard에 맞춰져 있어요. 글꼴을 바꾸면 자간과 정렬이 깨져요.
- 전역 스타일의 `body`에만 `font-family: var(--eli-font-family-sans)`를 두고, 그 밖의 화면 코드에서는 `font-family`를 직접 쓰지 않아요. 자간(`letter-spacing`)만 따로 바꾸지 않아요. 타이포그래피 토큰을 한 묶음으로 써요.
- 사용자가 다른 글꼴을 원하면 고정인 이유를 알리고, 굵기, 크기, 색, 여백으로 조절하자고 제안해요.
- Pretendard를 불러오고 있지 않으면 화면을 만들기 전에 `/eli-design-system`으로 연결하자고 안내해요.

## 단위는 DESIGN.md의 기준대로 써요

- CSS 값을 쓸 때 `DESIGN.md`의 `## 단위` 표에서 용도에 맞는 단위를 골라요. 습관대로 `px`를 쓰지 않아요.
- 표에 없는 용도면 추측하지 않고, 사용자에게 확인받아 표에 먼저 추가해요.
- `DESIGN.md`에 `## 단위`가 없으면 `/eli-design-md`로 추가하자고 안내해요.

## 문구는 UX-WRITING.md대로 써요

예외 없이 지켜요. 버튼 하나, 오류 메시지 하나를 쓸 때도 적용해요.

- 화면에 보이는 문구를 쓰거나 고치기 전에 프로젝트 루트의 `UX-WRITING.md`를 읽어요. 스크린 리더가 읽는 `aria-label`과 `alt`도 포함해요.
- 말투, 호칭, 문구 형식, 용어, 표기를 그 문서대로 써요. 기억이나 취향으로 쓰지 않아요.
- 문서에 없는 상황이면 가장 가까운 규칙과 예시를 따르고, 새로 정한 내용을 사용자에게 알려요.
- `UX-WRITING.md`가 없으면 문구를 쓰기 전에 `/eli-ux-writing`으로 규칙부터 만들자고 안내해요.
- 사용자가 준 문구가 규칙과 다르면 그대로 쓰기 전에 다른 점을 알려요.

## 버전을 확인해요

- 소스 방식의 UI·하네스·설치 도구 버전은 `references/installation.md`대로 각각 확인해요. 복사한 하네스 버전은 이 폴더의 `VERSION`에 있어요. 기존 npm 방식에서는 패키지에 포함된 하네스와 비교해요.
- 프로젝트가 쓰는 버전과 마지막으로 확인한 날짜는 `DESIGN.md`의 `## 버전`에 있어요.
- 설치 기록과 복사한 스킬의 버전이 다르다는 안내를 받으면 `/eli-doctor`로 실제 파일부터 확인해요. 사용자 수정 파일을 자동으로 덮어쓰지 않아요.
- 확인한 지 14일이 지났다는 안내를 받으면 사용자에게 알리고 `/eli-update`로 확인해요. 사용자가 하던 일을 먼저 끝내길 원하면 그 뒤에 해요.
- 원격 문서는 최신 버전을 설명해요. 설치된 버전이 낮으면 문서의 props가 없을 수 있어요. 타입 오류가 나면 버전이 다른지 먼저 확인해요.
- 사용자가 요청하지 않았는데 의존성이나 스킬, 훅을 말없이 올리지 않아요.

## 원격 MCP에 연결해요

`eli-docs`의 도구가 보이지 않으면 추측해서 작업하지 않아요. 아래 방법을 사용자에게 안내하고 연결한 뒤 이어서 작업해요.

- 주소: `https://eli-design.dev/mcp`
- Claude Code: `claude mcp add --transport http eli-docs https://eli-design.dev/mcp`
- Codex: `codex mcp add eli-docs --url https://eli-design.dev/mcp`
- 그 밖의 에이전트: MCP 설정에 이름 `eli-docs`, 전송 방식 HTTP(Streamable HTTP), 위 주소로 서버를 추가해요.

인증은 필요 없어요. 모든 도구는 읽기 전용이에요.

- 서버 이름은 반드시 `eli-docs`로 등록해요. 다른 스킬이 이 이름으로 도구를 찾아요.
- 추가한 뒤 `list_components`를 불러 응답이 오는지 확인해요. 에이전트를 다시 시작해야 도구가 보일 수 있어요.
- 주소가 응답하지 않으면 서버 문제로 보고 추측해서 작업하지 않아요. 연결하지 못했다고 알리고 원격 문서가 필요한 단계를 미완료로 남겨요. 다른 주소나 검색 결과의 문서로 대신하지 않아요.
- ELI 저장소에서 문서 서버를 직접 개발할 때만 `pnpm dev:docs`의 `http://localhost:3000/mcp`를 써요.

## 명령

| 명령 | 언제 써요 |
| --- | --- |
| `/eli-setup` | ELI를 처음 셋업할 때. 문서 세 개와 디자인 시스템을 한 번에 만들고 피드백으로 다듬어요 |
| `/eli-doctor` | 설치와 설정을 점검하거나 무엇부터 할지 모를 때 |
| `/eli-design-md` | 서비스 기획과 디자인 방향을 `DESIGN.md`로 정리할 때 |
| `/eli-design-system` | ELI로 디자인 시스템을 구축하고 페이지로 확인할 때 |
| `/eli-verify` | 디자인 시스템을 따르지 않는 코드를 찾아 고칠 때 |
| `/eli-icon` | 화면에 크게 보이는 커스텀 아이콘이 필요할 때 |
| `/eli-update` | 쓰는 버전을 확인하고 새 버전이 있으면 올릴 때 |
| `/eli-ux-writing` | 문구 규칙을 `UX-WRITING.md`로 정하고 화면의 문구를 다듬을 때 |
