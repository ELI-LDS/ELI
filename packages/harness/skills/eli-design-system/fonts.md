# 글꼴 고르기

프로젝트의 글꼴을 고르고 연결할 때 읽어요. 글꼴은 화면의 인상을 가장 크게 바꿔요. 어디서나 보는 글꼴을 쓰면 다른 것을 잘 만들어도 흔한 화면으로 보여요.

## 원칙

- **글꼴은 반드시 골라요.** 브라우저 기본 글꼴이나 시스템 글꼴을 주 글꼴로 두지 않아요. 글꼴을 정하지 않은 채로 화면을 만들지 않아요.
- **너무 흔한 글꼴을 주 글꼴로 쓰지 않아요.** 아래 "쓰지 않는 글꼴"을 제안하지 않고 기본값으로 고르지 않아요.
- **사용자가 골라요.** 서비스의 톤에 맞는 후보를 두세 개 추려서 실제 화면으로 보여주고 고르게 해요. 이름만 나열하지 않아요.
- **라이선스를 확인한 글꼴만 써요.** 아래 목록은 상업적 사용, 웹 글꼴로 직접 올리기, 필요한 글자만 추려 쓰기가 모두 허용된 글꼴이에요.
- **한 서비스에 글꼴은 두 가지까지 써요.** 본문용 하나, 필요하면 제목용 하나예요.

## 쓰지 않는 글꼴

주 글꼴로 쓰지 않아요. 라이선스에 문제가 있어서가 아니라 너무 많이 쓰여서예요.

| 구분 | 글꼴 |
| --- | --- |
| 한글 | Pretendard, Noto Sans KR, 나눔고딕, Spoqa Han Sans, Apple SD Gothic Neo, 맑은 고딕 |
| 영문 | Inter, Roboto, Open Sans, Lato, Poppins, Montserrat, DM Sans, Space Grotesk, Geist |
| 그 밖 | `system-ui`, `sans-serif`만 지정한 상태 |

- 이 글꼴들을 **대체 글꼴 목록에는 써도 돼요.** 고른 글꼴을 불러오기 전이나 없는 글자를 보여줄 때 쓰여요.
- 사용자가 이 중 하나를 쓰자고 하면 흔한 글꼴이라는 점을 알리고, 느낌이 가까운 대안을 화면으로 보여줘요. 그래도 분명히 원하면 따르고, `DESIGN.md`에 사용자가 정했다고 적어요.

## 본문용 한글 글꼴

모두 SIL OFL 1.1이에요. 상업적 사용, 수정, 직접 올리기, 다시 배포하기가 허용돼요. 글꼴 파일 자체를 파는 것만 안 돼요.

| 글꼴 | 만든 곳 | 느낌 | 굵기 | 불러오는 방법 | 주의할 점 |
| --- | --- | --- | --- | --- | --- |
| Asta Sans (아스타 산스) | 42dot | 깔끔하고 약간 각진 느낌. 중립적이면서 친근해요 | 가변 300~800 | Google Fonts, `next/font/google`, `@fontsource-variable/asta-sans` | 2024년에 나온 새 글꼴이에요. 아주 얇거나 아주 굵은 굵기가 없어요 |
| Wanted Sans (원티드 산스) | 원티드랩 | 영문과 숫자가 기하학적이에요. 현대적이에요 | 가변, 7단계 (얇은 굵기 없음) | npm `wanted-sans`의 분할 CSS | 한글 모양은 Pretendard와 같아요. 차이는 영문, 숫자, 굵은 굵기에서 나요 |
| SUIT (수트) | SUNN | 약간 좁고 단정해요 | 가변 100~900 | npm `@sun-typeface/suit` | 한글 2,668자만 있어요. 사용자가 쓴 글에 드문 글자가 나오면 다른 글꼴로 보여요 |
| IBM Plex Sans KR | IBM | 기술적이고 또렷해요. 개발 도구, 금융, 업무용에 어울려요 | 고정 7단계 (100~700), 가변 없음 | Google Fonts, `next/font/google`, `@fontsource/ibm-plex-sans-kr` | 700보다 굵은 굵기가 없어요 |
| LINE Seed Sans KR (라인 시드) | LY Corp. | 둥글고 친근해요. 인상이 강해요 | 3단계 | 공식 사이트에서 내려받아 직접 올려요 | 굵기가 적고, 웹용으로 바꾸고 추리는 작업을 직접 해야 해요. LINE이 떠오를 수 있어요 |

### 톤에 맞춰 후보를 추려요

| `DESIGN.md`의 톤 | 먼저 보여줄 후보 |
| --- | --- |
| 담백해요, 중립적이에요, 깔끔해요 | Asta Sans, SUIT |
| 현대적이에요, 세련됐어요 | Wanted Sans, Asta Sans |
| 믿을 수 있어요, 전문적이에요, 기술적이에요 | IBM Plex Sans KR, Asta Sans |
| 친근해요, 귀여워요, 발랄해요 | LINE Seed Sans KR, Asta Sans |

- 사용자가 글을 쓰는 서비스(게시판, 채팅, 댓글)면 SUIT를 고르기 전에 글자 수 제한을 알려요.
- 판단하기 어려우면 Asta Sans를 첫 후보로 둬요. 불러오기 쉽고 아직 흔하지 않아요.

## 제목용 글꼴

본문과 다른 인상을 주고 싶을 때만 써요. 본문에는 쓰지 않아요.

| 글꼴 | 만든 곳 | 느낌 | 굵기 | 불러오는 방법 | 주의할 점 |
| --- | --- | --- | --- | --- | --- |
| Hahmlet (함렛) | Hypertype | 날카롭고 현대적인 명조 | 가변 100~900 | Google Fonts, `next/font/google`, `@fontsource-variable/hahmlet` | SIL OFL 1.1 |
| 마루 부리 (MaruBuri) | NAVER | 화면에서 읽기 편한 부드러운 명조 | 5단계 | 공식 사이트에서 내려받아 직접 올려요 | 네이버 글꼴 라이선스. 상업적 사용, 수정, 다시 배포가 허용돼요 |
| Paperlogy (페이퍼로지) | 이주임 | 넓고 단단한 고딕. 큰 제목에 어울려요 | 고정 9단계 | 저장소의 CSS나 직접 올리기 | SIL OFL 1.1. 한글 2,780자만 있어요 |

## 영문 글꼴을 따로 짝지을 때

위의 한글 글꼴은 영문을 함께 갖고 있어서 따로 짝짓지 않아도 돼요. 영문과 숫자의 인상을 바꾸고 싶을 때만 써요. 영문 글꼴을 목록의 앞에 둬요.

| 한글 글꼴 | 어울리는 영문 글꼴 |
| --- | --- |
| Asta Sans | Onest, Hanken Grotesk |
| Wanted Sans | 짝짓지 않아요. 영문이 이 글꼴의 특징이에요 |
| SUIT | Instrument Sans, Hanken Grotesk |
| IBM Plex Sans KR | IBM Plex Sans (같은 가족) |
| LINE Seed Sans KR | Outfit, Urbanist |

영문 글꼴은 모두 SIL OFL 1.1이고 Google Fonts와 Fontsource에 있어요. 짝이 어울리는지는 실제 본문 크기로 화면에서 확인해요.

## 고르는 순서

1. `DESIGN.md`의 톤과 레퍼런스를 읽고 후보를 두세 개 추려요.
2. 후보마다 같은 내용(제목, 본문, 버튼, 숫자)을 그 글꼴로 보여주는 비교 화면을 만들어 로컬에서 띄워요. 이 서비스의 실제 문구로 보여줘요.
3. 사용자가 고르면 그 글꼴만 남기고 나머지 후보는 프로젝트에서 지워요.
4. 설치하기 전에 공식 출처에서 라이선스와 패키지가 지금도 맞는지 확인해요. 이 목록은 2026년 11월에 확인한 내용이에요.

`/eli-setup`에서는 2단계에서 톤에 가장 맞는 후보를 하나 골라 `(초안)`으로 적용하고, 디자인 시스템 페이지에 다른 후보와의 비교를 함께 보여줘요. 3단계에서 사용자가 골라요.

목록에 없는 글꼴을 사용자가 원하면 공식 출처에서 라이선스를 확인해요. 상업적 사용과 웹 글꼴로 올리기가 허용되는지, 수정이 금지되어 있지 않은지 봐요. 확인할 수 없으면 쓰지 않고 그렇게 말해요.

## 연결하는 방법

| 환경 | 방법 |
| --- | --- |
| Next.js, Google Fonts에 있는 글꼴 | `next/font/google`로 불러와요. `subsets`에는 `['latin']`을 써요. 한글은 필요한 조각만 자동으로 나눠 불러와요. 빌드할 때 내려받아서 사용자의 브라우저가 Google에 요청하지 않아요 |
| Next.js, 파일 하나짜리 가변 글꼴 | `next/font/local`로 불러와요 |
| Next.js, 조각으로 나뉜 CSS를 주는 글꼴 | 패키지의 분할 CSS를 루트 레이아웃에서 한 번 import해요 |
| Vite, Fontsource에 있는 글꼴 | Fontsource 패키지를 진입점에서 한 번 import해요 |
| Vite, 그 밖의 글꼴 | 패키지의 CSS를 진입점에서 한 번 import해요 |
| 프레임워크가 정해지지 않은 HTML | Google Fonts의 `<link>`나 공식 CSS 주소를 써요 |
| 직접 내려받는 글꼴 | `woff2`로 바꾸고 `@font-face`를 직접 써요. 한글 글꼴은 파일이 커서 쓰는 글자만 추리는 것을 검토해요 |

- 글꼴은 전역 진입점에서 한 번만 불러와요. 이미 불러오고 있으면 다시 추가하지 않아요.
- 프로젝트의 패키지 매니저로 설치해요.
- `font-display`는 `swap`으로 해요. 글꼴을 불러오는 동안에도 글자가 보여요.
- 쓰는 굵기만 불러와요. 고정 굵기 글꼴은 본문, 중간, 굵게 세 가지면 충분해요.
- 사용자의 화면에서 실제로 그 글꼴로 보이는지 브라우저 도구로 확인해요. 불러오기에 실패하면 조용히 대체 글꼴로 보여요.

## 토큰에 연결해요

글꼴도 토큰이에요. 토큰 파일 한 곳에서만 정해요.

```css
:root {
  --font-family-body: "Asta Sans", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo",
    "Noto Sans KR", "Malgun Gothic", system-ui, sans-serif;
}

body {
  font-family: var(--font-family-body);
  /* ELI 컴포넌트도 같은 글꼴을 쓰게 해요 */
  --eli-font-family-sans: var(--font-family-body);
}
```

- 토큰의 이름은 프로젝트의 이름 규칙을 따라요. 위 코드는 예시예요.
- 고른 글꼴 뒤에 대체 글꼴 목록을 반드시 둬요. 글꼴을 불러오기 전이나 없는 글자에 쓰여요.
- `--eli-font-family-sans`를 `body`에서 다시 정해요. ELI 컴포넌트는 이 변수로 글꼴을 읽어요. 원격 `font` 가이드에 다른 방법이 있으면 그 방법을 따라요.
- 화면 코드에서 `font-family`를 직접 쓰지 않아요. 토큰을 써요.
- 제목용 글꼴을 따로 쓰면 `--font-family-heading`처럼 역할 이름으로 토큰을 하나 더 둬요.

## DESIGN.md에 적어요

`DESIGN.md`의 `## 글꼴`에 아래를 적어요.

| 항목 | 적는 것 |
| --- | --- |
| 본문 글꼴 | 이름, 고른 이유 |
| 제목 글꼴 | 이름, 쓰는 자리. 없으면 "본문과 같아요" |
| 라이선스 | 라이선스 이름과 확인한 주소 |
| 불러오는 방법 | 패키지 이름이나 파일의 위치, 불러오는 파일 |
| 쓰는 굵기 | 굵기와 각 굵기의 용도 |
| 주의할 점 | 글자 수 제한 같은 이 글꼴의 한계 |

## 출처와 확인하지 못한 것

라이선스는 각 글꼴의 공식 저장소, 공식 사이트, Google Fonts의 라이선스 파일에서 확인했어요. Next.js의 동작은 Next.js 문서에서 확인했어요.

- 느낌, 흔한 정도, 영문 글꼴과의 어울림은 측정한 값이 아니라 판단이에요.
- 글꼴을 실제로 내려받아 그려 보거나 빌드해 보지 않았어요. 불러오는 방법은 처음 쓸 때 실제로 확인해요.
- Asta Sans, Wanted Sans, IBM Plex Sans KR, LINE Seed Sans KR의 한글 글자 수는 확인하지 못했어요.
- LINE Seed Sans KR의 굵기 목록과 마루 부리의 라이선스 전문은 공식 원문으로 확인하지 못했어요.
