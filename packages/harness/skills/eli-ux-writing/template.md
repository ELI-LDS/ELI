# 문구 규칙

<!-- 맞춤: 이 파일은 초안이에요. {중괄호}는 사용자의 답과 기존 문구로 채우고, "맞춤" 주석의 지시대로 고친 뒤 주석을 모두 지워요. 예시 문구는 이 서비스의 실제 화면에 나올 문구로 바꿔요. -->

이 문서는 {서비스 이름}의 화면에 보이는 모든 문구가 같은 말투로 나오게 하는 기준이에요. 버튼 하나를 쓸 때도 읽어요.

## 원칙

<!-- 맞춤: 서비스의 톤과 어긋나는 원칙은 고치거나 빼요. 다섯 개를 넘기지 않아요. -->

판단이 갈릴 때 위에 있는 원칙을 먼저 따라요.

1. **쉬운 말로 써요.** 사용자가 평소에 쓰는 낱말로 써요. 개발 용어와 내부 용어를 화면에 쓰지 않아요.
2. **짧게 써요.** 한 문장에는 한 가지 내용만 담아요. 없어도 뜻이 통하는 낱말은 빼요.
3. **할 일을 먼저 말해요.** 사용자가 무엇을 하면 되는지 먼저 쓰고, 이유는 필요할 때만 이어서 써요.
4. **사용자를 탓하지 않아요.** 문제가 생기면 사용자의 잘못이 아니라 해결 방법을 말해요.
5. **같은 것은 같은 말로 써요.** 한 가지를 가리키는 낱말은 어느 화면에서나 하나예요.

## 말투

<!-- 맞춤: 사용자가 고른 말투로 바꾸고, 아래 예시도 그 말투로 다시 써요. 기존 문구에 이미 일관된 말투가 있으면 그 말투를 따라요. -->

- **기본 말투:** {해요체 / 합쇼체}
- 한 화면에서 말투를 섞지 않아요.

| 좋은 예 | 나쁜 예 | 이유 |
| --- | --- | --- |
| 저장했어요 | 저장되었습니다 | 능동으로, 정한 말투로 써요 |
| 다시 시도해 주세요 | 재시도 바랍니다 | 평소에 쓰는 말로 써요 |
| 이름을 입력해 주세요 | 이름 입력 필수 | 완전한 문장으로 써요 |

- 수동 표현을 피해요. "~되었어요"보다 "~했어요"를 써요.
- "~하시겠어요?"처럼 과하게 높이지 않아요. "~할까요?"로 써요.
- 명사로 끝나는 문장은 버튼, 제목, 라벨에만 써요.

## 호칭

<!-- 맞춤: 사용자의 답으로 채워요. 답하지 않았으면 "정하지 않은 것"으로 옮겨요. -->

- **사용자를 부를 때:** {예: 이름이 있으면 "{이름}님", 없으면 부르지 않아요}
- **서비스가 자신을 부를 때:** {예: "{서비스 이름}". "저희", "당사"를 쓰지 않아요}
- "고객님", "회원님" 같은 호칭은 {쓰지 않아요 / 이럴 때만 써요}.
- 주어 없이 뜻이 통하면 주어를 빼요.

## 톤

<!-- 맞춤: DESIGN.md의 톤과 레퍼런스에 맞게 고쳐요. 느낌표와 이모지 규칙은 사용자의 답을 따라요. -->

말투는 같아도 상황에 따라 톤을 조절해요.

| 상황 | 톤 | 예 |
| --- | --- | --- |
| 평소 안내 | 담백하게 | {예: 모임 일정을 확인해요} |
| 일이 잘 끝났을 때 | 가볍게 반겨요 | {예: 신청을 마쳤어요} |
| 문제가 생겼을 때 | 차분하게, 해결 방법 중심으로 | {예: 연결이 끊겼어요. 다시 시도해 주세요} |
| 되돌릴 수 없는 일 | 분명하게, 결과를 숨기지 않고 | {예: 삭제하면 되돌릴 수 없어요} |
| 기다려야 할 때 | 무엇을 하는 중인지 알려요 | {예: 사진을 올리고 있어요} |

- **느낌표:** {쓰지 않아요 / 축하할 때 한 번만 써요}
- **이모지:** {쓰지 않아요 / 이런 자리에만 써요}
- **농담과 유행어:** 쓰지 않아요. 문제가 생긴 화면에서는 특히 쓰지 않아요.
- "죄송합니다"를 습관처럼 쓰지 않아요. 실제로 서비스의 잘못일 때만 써요.

## 문구 형식

<!-- 맞춤: 버튼 형식("저장" 또는 "저장하기")과 제목 형식은 사용자의 답을 따라 하나로 정해요. 예시는 이 서비스의 화면에 맞게 바꿔요. -->

### 버튼

- 누르면 일어나는 일을 써요. {동사형 "저장하기" / 명사형 "저장"}으로 통일해요.
- "확인", "예", "아니오"보다 실제로 하는 일을 써요.
- 두 낱말 안팎으로 짧게 써요.

| 좋은 예 | 나쁜 예 |
| --- | --- |
| {삭제하기} | 확인 |
| {모임 만들기} | 제출 |
| {다음} | 다음 단계로 이동하기 |

### 제목

- 화면에서 할 일이나 화면의 내용을 써요. {명사형 / 문장형}으로 통일해요.
- 마침표를 붙이지 않아요.

| 좋은 예 | 나쁜 예 |
| --- | --- |
| {이름을 알려 주세요} | 회원 정보 입력 페이지 |

### 입력창

| 부분 | 쓰는 법 | 예 |
| --- | --- | --- |
| 라벨 | 무엇을 넣는지 명사로 써요 | {이메일} |
| placeholder | 형식의 예시만 써요. 라벨을 대신하지 않아요 | {name@example.com} |
| 도움말 | 조건을 미리 알려요 | {8자 이상으로 정해 주세요} |
| 검증 메시지 | 무엇이 틀렸는지보다 어떻게 고치는지 써요 | {8자 이상으로 입력해 주세요} |

### 확인 창

- 제목에 무슨 일이 일어나는지 질문으로 써요.
- 본문에 결과를 써요. 되돌릴 수 없으면 그렇다고 써요.
- 버튼에는 그 일을 그대로 써요.

| 부분 | 좋은 예 | 나쁜 예 |
| --- | --- | --- |
| 제목 | {모임을 삭제할까요?} | 알림 |
| 본문 | {삭제하면 되돌릴 수 없어요} | 정말 삭제하시겠습니까? |
| 버튼 | {삭제하기}, {취소} | 예, 아니오 |

### 알림

- 일어난 일을 한 문장으로 써요. 마침표를 붙이지 않아요.
- 되돌릴 수 있으면 되돌리는 버튼을 함께 둬요.

| 좋은 예 | 나쁜 예 |
| --- | --- |
| {링크를 복사했어요} | 클립보드 복사가 완료되었습니다 |

### 빈 화면

- 왜 비어 있는지 한 문장, 다음에 할 일 한 문장으로 써요.
- 할 수 있는 일이 있으면 버튼을 하나 둬요.

| 좋은 예 | 나쁜 예 |
| --- | --- |
| {아직 참여한 모임이 없어요. 관심 있는 모임을 찾아보세요} | 데이터가 없습니다 |

### 불러오는 중

- 오래 걸리면 무엇을 하는 중인지 써요. 금방 끝나면 문구를 넣지 않아요.

## 어려운 상황

### 오류

"무슨 일이 생겼는지"와 "어떻게 하면 되는지"를 함께 써요.

| 좋은 예 | 나쁜 예 | 이유 |
| --- | --- | --- |
| {연결이 끊겼어요. 인터넷 연결을 확인하고 다시 시도해 주세요} | 네트워크 오류 (500) | 오류 코드가 아니라 해결 방법을 써요 |
| {이미 가입한 이메일이에요. 로그인해 주세요} | 잘못된 입력입니다 | 사용자를 탓하지 않고 다음 할 일을 알려요 |

- 오류 코드, 영어 오류 메시지, 개발 용어를 그대로 보여주지 않아요.
- 원인을 알 수 없으면 아는 것처럼 쓰지 않아요. "잠시 후 다시 시도해 주세요"라고 써요.

### 되돌릴 수 없는 일

- 무엇이 사라지는지 구체적으로 써요.
- 겁을 주지 않아요. 사실만 써요.

### 기다림과 실패

- 얼마나 걸리는지 알면 알려줘요.
- 실패했으면 사용자가 한 일이 저장되었는지 알려줘요.

### 권한과 개인정보

- 왜 필요한지 먼저 쓰고 요청해요.
- 허용하지 않아도 쓸 수 있으면 그렇다고 써요.

## 용어

<!-- 맞춤: 기존 문구에서 같은 뜻으로 섞여 쓰인 낱말을 찾아 채워요. 사용자가 고른 쪽을 "쓰는 낱말"에 적어요. 예시 행은 지워요. -->

같은 것은 한 가지 낱말로만 써요.

| 쓰는 낱말 | 쓰지 않는 낱말 | 뜻 |
| --- | --- | --- |
| {예: 로그인} | {예: 접속, 사인인} | {계정으로 들어오는 일} |
| {예: 모임} | {예: 그룹, 스터디, 방} | {이 서비스의 기본 단위} |
| {예: 삭제} | {예: 제거, 지우기} | {되돌릴 수 없이 없애는 일} |

- 새 낱말이 필요하면 이 표에 먼저 추가해요.
- 서비스 안에서 만든 고유한 이름은 처음 나올 때 뜻을 함께 알려줘요.

## 표기

<!-- 맞춤: 기존 문구의 표기를 확인해 채워요. 섞여 있으면 사용자에게 물어요. -->

| 대상 | 쓰는 법 | 예 |
| --- | --- | --- |
| 숫자 | 아라비아 숫자, 세 자리마다 쉼표 | {1,200명} |
| 날짜 | {예: `M월 D일`. 올해가 아니면 연도를 붙여요} | {3월 5일} |
| 요일 | {예: 괄호 안에 한 글자} | {3월 5일 (수)} |
| 시간 | {예: 오전·오후와 12시간} | {오후 2시 30분} |
| 기간 | 물결표 없이 "부터", "까지" | {3월 5일부터 7일까지} |
| 상대 시간 | {예: 하루 안은 "3시간 전", 그 뒤는 날짜} | {방금, 3시간 전} |
| 금액 | 숫자와 "원" | {12,000원} |
| 단위 | 숫자와 붙여 써요 | {3개, 5분} |
| 영어 낱말 | 널리 쓰는 한국어가 있으면 한국어로 | {설정, 알림} |
| 영어 약어 | 풀어 쓰거나 처음에 뜻을 함께 써요 | |
| 말줄임표 | 문구에 쓰지 않아요 | |
| 물음표 | 실제로 묻는 문장에만 써요 | |

## 화면에 보이지 않는 문구

스크린 리더가 읽는 문구도 같은 규칙을 따라요.

- 아이콘만 있는 버튼에는 하는 일을 `aria-label`로 써요. 모양을 설명하지 않아요. 예: "닫기" (좋음), "엑스 아이콘" (나쁨)
- 뜻이 있는 그림의 `alt`에는 그림이 전하는 내용을 써요. "이미지", "사진"이라는 낱말을 넣지 않아요.
- 페이지 제목은 "{화면 이름} | {서비스 이름}" 형식으로 써요.

## 점검 목록

문구를 쓴 뒤 확인해요.

- 정한 말투로 썼나요?
- 한 문장에 한 가지 내용만 있나요?
- 사용자가 다음에 할 일을 알 수 있나요?
- 용어 표의 낱말을 썼나요?
- 소리 내어 읽었을 때 사람이 하는 말처럼 들리나요?
- 문구가 길어져도 화면이 깨지지 않나요?
