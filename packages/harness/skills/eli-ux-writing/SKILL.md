# UX 문구 다듬기

문구 규칙은 프로젝트 루트의 `UX-WRITING.md`에 한 번 정하고, 화면의 모든 문구가 그 문서를 따라요. 그래서 누가 언제 써도 같은 말투가 나와요.

## 1. UX-WRITING.md를 준비해요

`UX-WRITING.md`가 있으면 읽고 2번으로 넘어가요. 없으면 문구를 다듬기 전에 먼저 만들어요.

1. 근거를 모아요.
   - `DESIGN.md`가 있으면 사용자, 톤, 지향하는 제품을 읽어요.
   - 프로젝트에 이미 있는 문구를 훑어봐요. 가장 많이 쓰인 말투, 버튼 문구의 형식, 같은 뜻으로 섞여 쓰인 낱말을 찾아요.
   - `eli-docs`가 연결되어 있으면 `get_guide`로 `ux-writing` 가이드를 읽어 질문 목록과 템플릿을 가져와요. 연결되지 않았으면 아래 질문으로 진행해요.
2. 사용자에게 물어요. 한 번에 네 개 이하로 묻고, 기존 문구에서 찾은 내용은 보여주고 맞는지만 확인해요.

| 주제 | 물어볼 것 |
| --- | --- |
| 말투 | 해요체, 합쇼체, 반말 중 무엇으로 쓰나요? 화면 종류에 따라 다르게 쓰는 곳이 있나요? |
| 호칭 | 사용자를 무엇이라고 부르나요? 서비스는 자신을 무엇이라고 부르나요? |
| 톤 | 친근한 쪽인가요, 담백한 쪽인가요? 느낌표, 이모지, 농담을 쓰나요? |
| 문구 형식 | 버튼은 "저장"과 "저장하기" 중 무엇으로 쓰나요? 제목은 명사형과 문장형 중 무엇으로 쓰나요? |
| 어려운 상황 | 오류, 실패, 빈 화면, 되돌릴 수 없는 일을 알릴 때 어떻게 말하나요? |
| 용어 | 같은 뜻으로 섞여 쓰이는 낱말 중 무엇으로 통일하나요? 쓰지 않는 낱말이 있나요? |
| 표기 | 숫자, 날짜, 시간, 금액, 영어 낱말을 어떻게 적나요? |

3. 아래 구성으로 초안을 보여주고, 사용자가 확인한 뒤 프로젝트 루트에 `UX-WRITING.md`로 저장해요.

```markdown
# 문구 규칙

## 말투
## 호칭
## 톤
## 문구 형식
## 어려운 상황
## 용어
## 표기
## 정하지 않은 것
```

- 규칙마다 좋은 예와 나쁜 예를 한 쌍씩 적어요. "친근하게" 같은 표현만으로는 다음 문구가 같은 말투로 나오지 않아요.
- "문구 형식"에는 버튼, 제목, 입력창 안내, 확인 창, 알림, 빈 화면을 각각 적어요.
- "용어"는 "쓰는 낱말, 쓰지 않는 낱말" 표로 적어요.
- 사용자가 답한 내용과 기존 문구에서 확인한 내용만 써요. 답하지 않은 항목을 지어내지 않고 "정하지 않은 것"에 적어요.
- 짧게 써요. 문구를 쓸 때마다 읽는 문서예요.

## 2. 범위를 정하고 문구를 모아요

사용자가 화면이나 파일을 말했으면 그 범위만, 말하지 않았으면 프론트엔드 소스 전체를 봐요.

| 다듬어요 | 다듬지 않아요 |
| --- | --- |
| 화면에 보이는 글자, 버튼, 제목, 안내 문구 | 로그, 주석, 변수와 함수 이름 |
| 입력창의 라벨·placeholder·도움말·검증 메시지 | 테스트 코드의 문자열 |
| 오류, 알림, 확인 창, 빈 화면의 문구 | 서버나 사용자가 넣은 데이터 |
| 스크린 리더가 읽는 `aria-label`, `alt` | 약관, 개인정보 처리방침 같은 법적 문서 |
| 페이지 제목과 설명 | 고유 명사, 상표 |

문구가 번역 파일에 모여 있으면 그 파일에서 고쳐요. 키는 바꾸지 않고 값만 바꿔요.

## 3. 보고해요

코드를 바꾸기 전에 보고해요.

```markdown
## 요약
고칠 문구 N건, 확인 필요 N건 (살펴본 문구 N건)

## 고칠 문구
| 위치 | 현재 | 제안 | 근거 |

## 확인 필요
| 위치 | 이유 |
```

- 근거에는 `UX-WRITING.md`의 어느 규칙인지 적어요.
- 같은 문구가 여러 곳에 있으면 묶어서 건수와 함께 적어요.
- 뜻이 바뀔 수 있는 문구, 규칙이 없어서 판단할 수 없는 문구는 고치지 않고 "확인 필요"에 적어요.
- 규칙에 맞는 문구는 고치지 않아요. 취향으로 바꾸지 않아요.

## 4. 고쳐요

- 승인받은 문구만 고쳐요.
- 뜻, 숫자, 조건을 바꾸지 않아요. 말투와 표현만 바꿔요.
- 문구가 길어져 화면이 깨지지 않는지 확인해요. 브라우저 도구가 있으면 바뀐 화면을 봐요.
- 스냅샷이나 문구를 검사하는 테스트가 있으면 함께 고치고 실행해요.
- 새로 정한 낱말이나 규칙이 생기면 `UX-WRITING.md`에 추가해요.

## 규칙을 바꿀 때

사용자가 말투나 용어 자체를 바꾸자고 하면 그 문구만 고치지 않아요. `UX-WRITING.md`를 먼저 고치고, 이미 쓴 문구도 새 규칙으로 고칠지 물어요.
