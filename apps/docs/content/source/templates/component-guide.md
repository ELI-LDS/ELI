# Component Documentation

## 문서 작성 원칙

- 문서의 기준은 실제 구현 코드, CSS, Storybook으로 한다.
- 실제 구현된 기능과 속성만 문서화한다.
- 반드시 실제 구현과 문서의 내용이 일치해야 한다.
- 구현 사실(Implementation)과 사용 권장 사항(Guidelines)을 구분하여 작성한다.
- 구현 여부를 확인할 수 없는 내용은 임의로 추측하거나 추가하지 않는다.
- 구현 코드와 문서의 내용이 다를 경우 실제 구현을 우선한다.

## 구현 기준

각 항목을 문서화할 때 다음 자료를 기준으로 확인한다.

| 확인 항목 | 기준 자료 | 확인 내용 |
| --- | --- | --- |
| Props 및 타입 | 구현 코드, Props Type | 속성명, 타입, 기본값, 필수 여부, 상속 속성 |
| 컴포넌트 구조 | 구현 코드 | 내부 구성 요소, 요소 간 계층 관계, 필수 및 선택 요소 |
| 인터랙션 및 동작 | 구현 코드 | 이벤트 처리, 상태 변화 조건, 입력 및 선택 규칙 |
| 시각적 스타일 | CSS | 크기, 간격, 색상, 테두리, 상태별 스타일 |
| 사용 예시 | Storybook | 실제 사용 방식, Props 조합, 상태별 표현 |
| 사용 가이드 | 디자인 시스템 문서 | 권장 사용 방식, 대체 컴포넌트, 조합 기준 |

### 자료 확인 시 유의 사항

- Props의 타입과 기본값은 실제 구현 코드에 정의된 내용을 기준으로 작성한다.
- 컴포넌트의 동작과 이벤트는 구현된 로직을 확인하여 작성한다.
- 상태별 시각적 표현은 CSS와 Storybook을 함께 확인한다.
- Storybook의 예시만으로 실제 구현되지 않은 기능이나 속성을 지원한다고 판단하지 않는다.
- 디자인 시스템의 사용 가이드는 구현 사실과 구분하여 작성한다.
- 구현 코드, CSS, Storybook 간에 내용이 일치하지 않는 경우 해당 차이를 확인하고 임의로 해석하지 않는다.

## 컴포넌트 문서 구성

### 01. 컴포넌트 용도 (Purpose)

- 컴포넌트의 목적
- 해결하는 UI 문제
- 적합한 사용 상황

### 02. 컴포넌트 구조 (Structure)

- 내부 구성 요소
- 요소 간 계층 관계
- 필수 / 선택 요소

### 03. 프로퍼티 (Properties)

- Variant
- Size
- State
- 각 프로퍼티의 정의 및 사용 조건
- 프로퍼티 간 조합 가능 여부

### 04. 인터랙션 규칙 (Interaction)

- 사용자 행동에 따른 반응
- 상태 변화 조건
- 입력 및 선택 규칙
- 예외 상황 및 제한 사항

### 05. 사용 가이드 (Usage Guidelines)

- Do: 권장 사용 방식
- Don't: 잘못된 사용 방식
- Alternative: 대체 컴포넌트
- Reason: 사용 기준 및 근거

### 06. 추천 조합 (Composition)

- 함께 사용하는 컴포넌트
- 조합이 필요한 상황
- 각 컴포넌트의 역할
- 조합 시 동작 규칙

### 07. 구현 파일 (Implementation Files)

- Component
- Props Type
- CSS
- Storybook
