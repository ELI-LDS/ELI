# 알러트

상태: 진행 중

## 01. 컴포넌트 용도 (Purpose)

Alert는 사용자에게 상태, 결과 또는 중요한 안내 내용을 전달하는 알림 컴포넌트예요.

- 작업의 성공이나 실패 결과를 전달할 때 사용해요.
- 사용자에게 주의가 필요한 상황이나 참고 정보를 안내할 때 사용해요.
- 사용자가 현재 상황을 이해하거나 다음 행동을 판단하는 데 필요한 정보를 제공할 때 적합해요.
- 오류, 성공, 주의, 정보의 네 가지 상태를 제공해요.

## 02. 컴포넌트 구조 (Structure)

Alert는 아이콘 영역과 텍스트 영역으로 구성돼요.

- **Icon**: `status`에 해당하는 아이콘을 표시해요.
- **Content**: 제목과 선택적인 본문을 표시해요.
    - **Title**: 알림의 핵심 내용을 전달해요.
    - **Message**: 제목을 보충하는 설명을 전달해요.

구성 규칙은 다음과 같아요.

- 아이콘은 `status`에 따라 자동으로 결정돼요.
- 제목은 필수이며, 본문은 선택 사항이에요.
- 본문을 생략하면 제목만 표시해요.
- 별도의 버튼이나 사용자 입력 요소는 포함하지 않아요.

## 03. 프로퍼티 (Properties)

### Variant

별도의 Variant Props는 제공하지 않아요. 알림의 종류는 `status`로 지정해요.

### Size

별도의 Size Props는 제공하지 않아요.

### State

`status` Props로 네 가지 알림 상태를 지정해요.

| 값 | 아이콘 | 용도 |
| --- | --- | --- |
| `success` | CheckIcon | 작업이 성공적으로 완료됐음을 알려요. |
| `error` | ErrorIcon | 작업에 실패했거나 오류가 발생했음을 알려요. |
| `caution` | CautionIcon | 사용자가 주의해야 할 내용을 알려요. |
| `info` | InfoIcon | 참고하거나 알아두어야 할 정보를 알려요. |

기본값은 `info`예요.

### 기타 Props

| Prop | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `title` | `ReactNode` | 필수 | 알림의 제목을 표시해요. |
| `message` | `ReactNode` | - | 제목 아래에 표시할 설명이에요. |
| `status` | `AlertStatus` | `info` | 알림의 상태를 지정해요. |
| `className` | `string` | - | 루트 요소에 추가할 CSS 클래스예요. |

`AlertStatus`는 `error`, `success`, `caution`, `info` 중 하나를 사용해요.

그 외에 `role`, `aria-label`, `style` 등 HTML `div` 요소의 속성을 전달할 수 있어요. 단, `children`과 HTML의 `title` 속성은 Props에서 제외돼요.

### 프로퍼티 조합

- `title`은 반드시 제공해야 해요.
- `message`는 생략할 수 있어요.
- `status`는 네 가지 값 중 하나만 지정할 수 있어요.
- `className`과 HTML `div` 속성을 함께 사용할 수 있어요.

## 04. 인터랙션 규칙 (Interaction)

### 상태 변경

- `status` 값에 따라 아이콘이 변경돼요.
- `status`를 생략하면 `info` 상태가 적용돼요.
- 알림 상태는 사용하는 쪽에서 전달한 Props에 따라 결정돼요.

### 콘텐츠 표시

- `title`은 항상 표시돼요.
- `message`는 `undefined` 또는 `null`이 아닐 때 표시돼요.
- 제목과 본문은 각각 전달된 ReactNode를 표시해요.

### 예외 상황 및 제한 사항

- 닫기 버튼이나 알림 제거 기능은 제공하지 않아요.
- 일정 시간이 지나면 자동으로 사라지는 기능은 제공하지 않아요.
- 별도의 Hover, Pressed, Disabled, Loading 상태는 제공하지 않아요.
- 컴포넌트 자체에서 알림 상태를 판단하거나 변경하지 않아요. 알림의 내용과 상태는 사용하는 쪽에서 전달해야 해요.
- 기본적으로 `role="alert"` 또는 `aria-live`를 지정하지 않아요. 동적으로 표시되는 알림을 화면 낭독기에 전달해야 한다면 사용하는 쪽에서 적절한 ARIA 속성을 지정해야 해요.

## 05. 사용 가이드 (Usage Guidelines)

### Do

- 작업 결과에 따라 적절한 `status`를 지정해요.
- `title`에는 알림의 핵심 내용을 간결하게 작성해요.
- `message`에는 제목만으로 전달하기 어려운 원인, 조건, 추가 설명을 작성해요.
- 사용자가 상황을 이해하고 다음 행동을 판단할 수 있도록 구체적인 정보를 제공해요.
- 성공, 오류, 주의, 정보의 의미에 맞게 상태를 구분해요.

### Don't

- 하나의 알림에 서로 다른 상태를 혼합하지 않아요.
- 제목에 긴 설명을 모두 담지 않아요.
- 단순한 장식이나 일반적인 텍스트 강조 목적으로 사용하지 않아요.
- 사용자가 직접 조작해야 하는 버튼이나 입력 요소를 Alert 내부에 넣으려고 하지 않아요.
- 자동으로 사라지는 토스트가 필요한 상황에 Alert를 사용하지 않아요.

### Alternative

- 일정 시간 후 자동으로 사라지는 메시지가 필요하다면 SnackBar를 사용해요.
- 입력 필드에 대한 개별적인 오류 안내가 필요하다면 TextField의 `error` 상태를 사용해요.
- 사용자가 선택하거나 실행해야 하는 행동이 중심이라면 Button을 함께 배치해요.

### Reason

Alert는 사용자가 내용을 확인할 수 있도록 상태나 중요한 정보를 화면에 표시하는 안내 컴포넌트예요. 일시적인 피드백이나 개별 입력 요소의 검증 결과처럼 표시 목적이 다른 경우에는 해당 목적에 맞는 컴포넌트를 사용하는 것이 적절해요.

## 06. 추천 조합 (Composition)

### Alert + Button

알림과 관련된 후속 행동을 사용자에게 제공할 때 함께 사용해요.

| 상황 | Alert | Button |
| --- | --- | --- |
| 파일 삭제 실패 | 파일을 삭제할 수 없다는 원인 안내 | 다시 시도 |
| 체험판 만료 예정 | 체험판 종료일까지 남은 기간 안내 | 요금제 선택 |
| 저장 완료 | 변경 사항이 저장됐다는 결과 안내 | 저장된 항목 확인 |

**조합 규칙**

- Alert에는 현재 상태와 상황을 전달해요.
- Button에는 사용자가 수행할 수 있는 구체적인 행동을 표시해요.
- Button은 Alert 내부가 아닌 별도의 요소로 배치해요.
- 알림 내용과 버튼의 행동이 직접적으로 연결되도록 구성해요.

### Alert + TextField

폼 전체에 영향을 주는 오류와 개별 입력 항목의 오류를 구분해서 안내할 때 함께 사용해요.

| 상황 | Alert | TextField |
| --- | --- | --- |
| 서버 오류로 제출 실패 | 요청을 처리하지 못했다는 전체 오류 안내 | 사용자가 입력한 값은 유지 |
| 특정 입력값 오류 | 폼 전체에 영향을 주는 안내가 필요한 경우에만 표시 | 해당 입력 항목의 오류 상태 표시 |

**조합 규칙**

- 폼 전체에 영향을 주는 오류는 Alert로 안내해요.
- 특정 입력 항목에만 해당하는 오류는 TextField의 `error` 상태로 표시해요.
- 동일한 오류 내용을 Alert와 TextField에 불필요하게 반복하지 않아요.
